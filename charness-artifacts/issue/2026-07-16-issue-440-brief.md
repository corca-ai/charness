# Resolution Brief — corca-ai/charness#440

**Classification**: deferred-work

**Reporter JTBD**: Disposition the two remaining round-5 retro improvements
(release-adapter host-proof surface; durable independent-observer probe
artifact) so they stop being silent debt rediscovered by re-reading old retros.

**Proposed boundary**:

- in scope, item (a): evaluate `real_host_required_path_globs` in
  `.agents/release-adapter.yaml` against the v1.0.4 counterexample (commit
  `588488bd` changed the root `charness` CLI's Claude host mutations while the
  planner reported `real_host_required=false`), then either add a narrow
  root-CLI trigger or record why not.
- in scope, item (b): a durable convention for independent-observer release
  evidence (REST readbacks, installed doctor/cache checks) so it survives the
  chat session — or an explicit recorded decision that the release artifact's
  existing distinct-channel record is sufficient.
- out of scope: restructuring the real-host checklist mechanism, the release
  helper, or the probe-artifact validator; any change to how the retro
  Next-Improvements pipeline itself routes items (that structural pattern is
  the issue's framing, not its fix-unit).

**Evaluation, item (a)**: the root `charness` CLI (single 5.5k-line file) is
the only path carrying the Claude host-mutation seam, so no narrower glob than
`charness` exists. Data: `charness` changed in 6 of the last 13 releases, so
the trigger would fire roughly every other release. The retro's own condition —
"add a trigger only if it can request a safe, scoped host proof instead of
forcing destructive real-host work" — is met by the existing
`real_host_checklist`: its items are `charness update` + doctor readback and
dry-run/doctor probes, and the post-publish flow already runs `charness update`
on the maintainer machine, so the marginal ceremony is small. Recommendation:
add the `charness` glob. Counter-position: ~50% trigger rate makes the
checklist feel like per-release ceremony, and the maintainer may prefer keeping
the v1.0.4-style explicit non-claim pattern instead.

**Evaluation, item (b)**: `charness-artifacts/probe/` already exists with
`.json` host-log probes (the repo's persisted probe convention, per
recent-lessons). Recommendation: add a short convention line to the release
skill's `references/publication-boundary.md` — when an independent observer
produces substantive evidence at the publication boundary, persist it as a
JSON probe artifact in the repo's probe directory rather than chat-only. This
is portable (adapter-neutral phrasing) and needs no new validator.

**Non-goals**:

- No new blocking floor (Floor-Addition Restraint: both changes are
  adapter/doc-level briefing surfaces, not gates).

**Acceptance checks**:

- Item (b): the convention line exists in the release reference (plus plugin

- Both retro items have a disposition traceable from this issue.

**Open decisions**:

is bundled into the same glob addition as cheap in-scope prevention of the
identical escape class.
