# Resolution Brief — corca-ai/charness#640

**Classification**: feature

**Reporter JTBD**: let a consuming repo raise (or lower) the debug artifact's
line ceiling when its investigations are legitimately larger, instead of
spending rounds on content-free re-wrapping to satisfy a fixed 180.

## Measured class

The issue names one ceiling. The same shape was measured in four shipped
validators, none of which a consuming repo can override:

| validator (all shipped via `plugins/charness/scripts/`) | constant | override |
| --- | --- | --- |
| `scripts/validate_debug_artifact.py:82` | `MAX_ARTIFACT_LINES = 180` | none |
| `scripts/validate_quality_artifact.py:45` | `MAX_ARTIFACT_LINES = 140` | none |
| `skills/public/handoff/scripts/handoff_content_budget.py:27` | `DEFAULT_MAX_CONTENT_LINES = 78` | none |
| `scripts/validate_cautilus_proof.py:14` | `MAX_ARTIFACT_LINES = 120` | none |

Root primitive: `scripts/adapter_lib.py` exports `optional_string`,
`optional_string_list`, `optional_bool` — and **no `optional_int`**. The shared
adapter vocabulary has no numeric field type at all, which is why every numeric
policy in this family is a module constant rather than an adapter field. The
one numeric adapter field that does exist (`timeout_seconds`,
`skills/public/quality/scripts/adapter_validators.py:165`) hand-rolls its own
`isinstance` check outside that vocabulary.

Wiring is otherwise natural: `validate_debug_artifact.py` already loads the
debug adapter (`owned_prefix` resolves `output_dir` from it), and
`scaffold_debug_artifact.py:30` already single-sources the ceiling from the
validator, so a resolved value propagates to `size_budget.max_lines` for free.

**Proposed boundary**:
- in scope: an `optional_int` primitive in `adapter_lib`, an optional numeric
  ceiling field on the debug adapter schema, validator + scaffold consuming it,
  default unchanged at 180 when unset.
- out of scope: changing any default ceiling; making required-section lists
  configurable; per-artifact-class ceilings.

**Non-goals**:
- Removing the concision pressure. Unset adapter must behave exactly as today.
- Retrofitting every numeric constant in the repo (timeouts, ratchet deltas,
  probe counts) — those are a different sub-class with different risk.

**Acceptance checks**:
- `debug-adapter.yaml` with the field set to N makes the validator refuse at
  N+1 lines and accept at N, measured on a real artifact.
- Same run's `scaffold_debug_artifact.py --repo-root .` reports
  `size_budget.max_lines: N` (not 180), so the author writes-to-fit up front.
- No adapter field set → validator and scaffold both still report 180.
- A malformed value (string, bool, negative, zero) is an adapter *error*, not a
  silent fallback to the default.

**Open decisions**:
1. **Scope**: fix debug only (#640 literal), or land `optional_int` once and
   wire debug + quality + handoff together? The primitive is the same work
   either way; the extra cost is three adapter schemas and three test sets.
   My recommendation: land the primitive + debug in this fix-unit, and file the
   quality/handoff extension as a sibling issue rather than bundling it.
2. **Bounded or unbounded**: an unbounded field lets a repo set `100000` and
   turn the gate decorative. Options: (a) unbounded, trust the repo; (b) clamp
   to a multiple of the default; (c) unbounded but require an adjacent reason
   string in the adapter so the raise is auditable. My recommendation: (a) —
   the repo already owns `output_dir` and `artifact_class`; a ceiling it sets
   for itself is not an external boundary, and (b)/(c) reintroduce a
   charness-chosen number by the back door, which is the defect being fixed.
3. **Field naming across skills**: handoff's budget counts *content* lines
   (blank lines, canonical headings, and the whole `## References` block are
   excluded); debug/quality count raw file lines. One shared `max_lines` name
   would mean two different things. Rename per semantics, or accept the
   collision?
4. **Cautilus in or out**: eval-only and ask-before-run per `CLAUDE.md`, and it
   uses a separate `cautilus_adapter_lib`. My recommendation: out of scope.

**Autonomous vs pause**: pausing for user discussion — open decisions are
non-empty (scope breadth and the bound question both change what ships).
