# Claim Boundary Frame Capability Brief

Date: 2026-09-22. Scope: improve the existing public `impl` and `prove` skills plus the isolated implementation-lane carrier; no new gate, receipt, schema, planner, or mandatory artifact.

## Capability

Before an agent edits a requested mechanism or reports success, it should align four facts: the user concept and premise, a named consumer with a distinct observable state, the canonical behavior owner rather than a substitute, and the claimed evidence level with an observer and falsifier capable of seeing that level. A false premise or out-of-scope owner stops before editing through the existing typed premise/scope escalation. An unavailable higher observer may instead narrow the claim within user intent while retaining the higher non-claim. Honest unit, fixture, and simulated evidence remains valid at its stated lower level.

## Audience and Trigger

The audience is an implementation or proof agent in any consuming repository. The frame applies when accepting a requested option, field, verifier, fixture, simulation, or success claim. It is especially relevant when the requested shape may be redundant, the scoped test is not the product owner, or a lower-level result could be promoted into installed/live/release evidence.

## Capability Failure

The current task-run carrier covers premise, consumer, product-state distinction, owner, and lower-level simulation honesty only for `require-change` isolated lanes. Native subagents and direct `impl` or `prove` use do not consume that carrier. The carrier also leaves evidence level and a boundary-capable observer/falsifier implicit. This allowed a redundant output-mode flag, an orphan synthetic activation marker, and fixture-shaped evidence to look locally complete until the operator challenged the premise.

## Contract and Topology

This is an `improve` change. `skills/shared/references/claim-boundary-frame.md` is the canonical shared judgment owner. `impl` carries the before-edit route, `prove` carries the before-claim route, and `build_lane_prompt` transports the same four axes into isolated lanes that may not explicitly invoke either skill. Host-specific mechanics, adapters, dependencies, accumulated state, and public command vocabulary do not change. Generated plugin placements continue to mirror the canonical source.

## Proof Boundary

Focused deterministic proof covers task-run prompt transport, public skill/package contracts, reference resolution, and generated mirror parity. A bounded independent integration-lead review confirmed that the frame rejects the redundant-flag and orphan-synthetic-release-proof cases, preserves honestly labelled lower-level evidence, and uses the existing typed owner/scope escalation. That review found one over-blocking carrier sentence: a missing higher observer must still permit a claim narrowed within user intent with the higher non-claim retained. The carrier and focused regression now encode that counterweight. This does not prove that every future model will reason correctly or that a native host always routes an unlabelled task to `impl`; consuming-repo `AGENTS.md` remains the host-agnostic standing contract for that route.

## Failure Cases and Recovery

- False premise: do not edit merely because a write scope was granted; return the existing typed premise/scope blocker.
- Owner outside scope: escalate the owner mismatch instead of building a fixture-owned substitute.
- Lower-level evidence only: retain it as unit/simulated evidence and state the higher non-claim.
- Missing observer at the claimed boundary: narrow the claim within user intent and name the higher non-claim, or stop when it cannot be narrowed honestly.

## Portable Candidate

The frame is portable across repositories and belongs in Charness shared skill guidance. It adds no external tool dependency and no repo-specific policy.
