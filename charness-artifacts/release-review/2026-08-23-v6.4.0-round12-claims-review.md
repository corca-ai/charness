# v6.4.0 claims review — round 12

- Prepared commit: `d1d8538843ac`
- Target version: 6.4.0
- Verdict: **pass**, with the coverage limits stated below.
- Reviewer context: bounded `bounded-reviewer` subagent, read-only envelope
  (Read/Grep/Glob), no Bash/Edit/Write/Agent tool present. Two independent
  reviewers ran this round: one claims lens, one adversarial code lens.

## What was reviewed, and by which observer

The claims lens read `charness-artifacts/release/latest.md` and
`charness-artifacts/release/v6.4.0-notes.md` and checked every claim on them
against the shipped tree. It returned **pass**: no claim on either document is
false. Those two files are byte-identical between the commit the reviewer read
(`092603912`) and this prepared commit — verified with `git diff` over both paths
— so the verdict still applies to the exact bytes being tagged.

The adversarial code lens read the rest of the blocking partition and returned
**BLOCK** on two defects. Both were repaired before this record was written, and
each repair carries a negative control that reproduces the defect when reverted:

1. `dup_ratchet_scope.scope_coverage` published a WRONG NUMBER for an absolute
   scope path, `~/…`, a backslash separator, and `//`. Each survived `normpath`,
   was then `lstrip("/")`-ed into a relative path matching nothing, and produced
   `uncovered_file_count == tracked_file_count` plus "this scan never forms a
   CODE family from them" over files the scanner had read. Reverting the guard
   reproduces `/abs/repo/src -> uncovered 3/3`. The repair replaces the list of
   shapes to reject with `_is_literal_relative_prefix`, which states what the
   literal comparison requires, so an unlisted shape is refused by default.
2. The same function's `None` had grown a second cause while its only renderer
   still asserted the first. A consumer scoped with a glob — a shape the adapter
   validator's own docstring calls legal — was told "git could not be asked this
   run" on a run where git answered. Both reviewers found this independently.
   The repair asks for each cause separately and names every true one.

A third finding, that the three-bucket partition assertion in
`tests/test_consumer_validator_catalog.py` was an algebraic identity that could
not fail, was confirmed by substitution: it passes on the negative count that
motivated writing it. `uncovered_module_count` is now a set difference out of one
walked population rather than `total - admitted - excluded`, and the assertion
now fails when the exclusion term is dropped.

## Residual non-claims

This verdict does not establish any of the following.

1. **Completeness of the two documents.** The claims lens checks whether stated
   claims are true, never whether an unstated change should have been stated. A
   shipped behavior change absent from both documents is invisible to it.
2. **That the tagged snapshot is true of the published release.** `latest.md`
   states this itself: the tagged copy carries "claims review: not yet performed"
   and the pre-bump verification figure verbatim. That is a disclosed, deliberate
   falsity in the tagged artifact, corrected only by the post-publish artifact
   commit. It is not a defect this review clears.
3. **That the release gate's figure covers the whole tree.** The gate ran green
   at 99 passed / 0 failed / 0 unproven on this prepared commit, with nothing
   concurrent. `latest.md` scopes its own recorded figure to the evaluated
   changed-path window, which is narrower than the release delta.
4. **That a green derived-claims block means the claims are true.** The publish
   narrative gate compares the notes against registered claim surfaces only; a
   surface nobody registered is invisible to it. Four registered surfaces were
   re-derived by hand this round and all four agreed.
5. **Any particular value of `uncovered_module_count`, `scanned_files`,
   `uncovered.total`, `scope_coverage`, or `link_only_lines_slack`.** Each is
   computed per run by design. The mechanism was verified; no value is frozen.
6. **That `scope_coverage`'s numerator means "files nose parsed".** It is
   tracked-files-by-path, over-counting on the uncovered side and flattering on
   the admitted side. Both the code and the reference say so.
7. **That the absence of the two in-scope `did_not_judge` entries means the
   in-scope files were judged.** Three inputs leave the backstop unable to fire:
   an injected inventory, an empty gate baseline, and a missing or unreadable
   one. One-direction discrimination only.
8. **That the notes' four-gate list is the full set of gates whose output
   changed.** Neither the notes nor this review claims that.
9. **Round-12 SHOULD-FIX findings, left unrepaired and filed rather than fixed.**
   (a) `summarize()`'s `new_doc_family_count` is pinned only on the arm that
   returns zero, so a mistyped key there would report zero new doc families on a
   run that hard-blocks on doc drift. The code is correct; the proof is missing.
   (b) `dup_ratchet_edit_advisory.in_ratchet_scope` reads the same adapter field
   with no normalization at all, so a consumer scoped `["."]` gets permanent
   silence from the edit-time advisory. Advisory-only, never blocks: it ships
   silence, not a falsehood. (c) The `admits X/Y` numerator is published and no
   test asserts its value.
10. **The second bounded review round over the repaired proof surfaces.** This
    slice changed verdict logic on gates (`check_dup_ratchet`,
    `check_consumer_validator_catalog`), which the operating contract says owes a
    second round reading the REPAIRS. Twelve rounds ran; the round that reads
    this specific set of repairs — including the `dup_ratchet_scope` module
    split, which moved code the earlier rounds reviewed in place — did not run.
    This is the largest single gap in this record and it is recorded, not closed.
11. **External facts.** CI's `11197 passed` figure, the scheduled mutation
    workflow's state since the repair, the second uncharacterized mutation
    failure mode from 2026-08-19/20, and the content or state of issues #703,
    #704, #705, #706, #707, #546, #612, #358.
12. **Executed-observable receipts in `latest.md`** — the runtime table, the
    fresh-checkout probe status, the retro trigger outputs, and the
    requested-review gate status. The surfaces they name were verified to exist
    and to be consistent; none was re-run by the reviewer.
13. **Scope deliberately not opened by the claims lens:** the unprinted paths of
    the evaluated-path window, the ten advisory-partition files, plugin-mirror
    byte parity across all changed files (spot-checked only), `mutants/**`, and
    whether `dup_ratchet_scan` actually passes `"."` to nose as `--root .` —
    asserted in code comments and load-bearing for why the un-normalized
    behavior was a defect, but not independently read.
14. **Test outcomes, from the reviewer's own envelope.** Both reviewers were
    read-only and ran nothing. Every gate figure in this record is the
    publisher's receipt, not theirs.
