# Charness 6.0.0 Prepared Claims Review

Date: 2026-08-16

## Verdict

UNPROVEN — the 6.0.0 publication is STOPPED. Three independent claims-review
rounds were run against three successive prepared records, and all three returned
`unproven` after finding real false statements in the artifacts that would be
posted as ten irreversible GitHub close comments. The defects each round named are
repaired; nothing has reviewed the third round's repairs, and the release is not
published.

## Why This Is `unproven` And Not A Fourth Round

Each round found NEW real defects rather than converging, and each round's defects
were of one class: a count or an attribution corrected in one place and left stale
in another, inside prose that had been partially updated.

- Round 1 found the notes' known-weak list still saying
  `skills/public/setup/references/default-surfaces.md` points consumers at a gate
  that refuses inside their repo — contradicting the tree, the ledger's #618 entry,
  and the same document's own added-capability section.
- Round 2 found that the fix for round 1 corrected the ledger's headline narrowing
  count to four while a sentence three paragraphs later still totalled five through
  `F10, F11 and F13`, where `F13` IS the #618 residual the same ledger says was
  repaired.
- Round 3 found that the fix for round 2 introduced a false attribution — it claims
  #626's post-graduation compaction section was first recorded in the 2026-08-14
  review's cohort-B failure angle, and the string `compaction` appears nowhere in
  that review; that angle records #626's resurrection slot, which this slice
  DELIVERED. Round 3 separately found a pre-existing error: the residual paragraph
  credits "#621's seeder" with two residuals that F27d assigns to #625, while F27b
  records "No repair owed" for #621. So the #621 close comment would assert
  residuals #621 does not have and the #625 comment would disclose none.

Three rounds is past this repo's two-round critique cap. The cap exists because a
surface that keeps producing findings is telling you something about the surface,
not about the reviewers. Publishing on a fourth round would be reviewing until it
passes, which is the shape the round-1 finding was made of.

## What The Rounds CONFIRMED

Recorded so the stop is not read as a verdict on the whole release. Round 3
independently re-derived and passed: version parity at 6.0.0 across all four
packaging manifests; all four derived claim blocks (`--json` declarations 0,
subcommands 13, public skills 20, repo shell gates 6), each recomputed by scanning
the declared globs rather than trusting the block; the parity gate's six-site
population; `SCHEMA_VERSION = 6`; the docs-graph bars and ratchet-discard
behaviour; the `CHARNESS_REPO_ROOT` hatch flags on exactly the five gates the notes
name and on none of the three that set it to `0`; both probe scripts' exit-3 and
key-absence contracts; and that #634 and #546 read unambiguously as STAYS OPEN in
every document. The release record claims no hosted fact that has not happened.

## Reviewed Evidence

Three bounded read-only reviewer contexts, each reading the prepared record, the
release notes, the closeout ledger and the tree, and none relying on the preparer's
verdict. None made a worktree, index, ref, tag, release or issue write. The third
round was additionally instructed to enumerate every quantity and status word it
checked, including the passing ones, so that "checked and clean" is separable from
"not looked at".

## Residual The Parent Could Not Close By Review

Round 3 asked whether the round-2 and round-3 artifact repairs are inside the
prepared commit rather than only in the worktree. That question is moot here: the
prepared commit was rolled back and no tag exists, so nothing was published from an
unverified tree. Any future publish must re-prepare and re-answer it.

## Non-Claims

This review does not assert that the repaired artifacts are now correct. It asserts
that three rounds each found real defects, that those defects are repaired, and
that no observer has read the third round's repairs. No tag, GitHub release, issue
closure, install refresh or hosted readback happened.
