# Issue #714 Node TAP Run-Window Debug
Date: 2026-08-24

## Problem

`NodeTestReporter` selected the final TAP duration but counted `exitCode:`
diagnostics from a region that began after the previous duration. Wrapper
chatter and incomplete earlier runs could therefore change the selected
mutation result; a trailing duration-shaped wrapper could also hide a valid
summary.

## Correct Behavior

Given a transcript containing multiple or partial TAP runs, when the reporter
selects the latest complete TAP run, counts and process/module-load diagnostics
must come from that same run. A candidate is complete only when its required
summary keys, final plan, top-level result records, and verdict-critical counts
agree. A selected run containing `exitCode:` remains an error/refusal.
Capability restored: a real assertion failure is counted even when earlier or
wrapper output contains process diagnostics.

## Observed Facts

- Round-1 fresh-eye falsifier: first complete run, wrapper `exitCode: 1`, then a
  final assertion-failure run with `# fail 1` and no `exitCode:` returned
  `(0, 0, 1)`; expected `(0, 1, 0)`.
- The earlier repair scoped from the prior duration, not from the selected TAP
  run start. It did not cover wrapper chatter, an incomplete earlier run, or a
  misleading trailing duration.
- The selected-run module-load refusal is represented by `_NODE_BROKEN` and
  must remain `errors == 1`.

## Reproduction

The focused parameterized regression keeps one final assertion-failure TAP run
identical while varying: a complete run plus inter-run wrapper `exitCode: 1`,
an incomplete earlier run plus wrapper diagnostics, and a trailing wrapper line
`# duration_ms 99`. Before the repair the first axis reproduced `(0, 0, 1)`;
the trailing axis could select a duration-only block.

## Candidate Causes

- Summary counts and process diagnostics had different observation owners.
- Duration was treated as a sufficient run boundary even when wrapper output
  appeared between TAP runs.
- The regression matrix varied an earlier complete run but not incomplete,
  inter-run, or trailing-wrapper structure.

## Hypothesis

The defect is fixed if `_selected_run()` first identifies a complete TAP
candidate by structural start/plan and owned duration, then `read()` derives
both counts and process diagnostics from that returned string. `disconfirmer:`
the focused axis-varying suite plus the selected `_NODE_BROKEN` control; any
wrapper diagnostic changing the final assertion result or any selected broken
run losing `errors` disproves the repair.

## Root Cause

`summary()` and `read()` shared a duration endpoint but not a TAP-run owner, and
the old owner treated a matching marker as sufficient evidence of completeness.
The diagnostic scan therefore crossed wrapper and earlier-run boundaries, while
missing or inconsistent keys were zero-filled into a verdict. The structural
cause was a missing invariant: one reporter verdict must be derived from one
complete, internally consistent observation window.

## Invariant Proof

- Invariant: when the Node TAP producer emits a selected run, the reporter must
  pass that run's counts and process-failure diagnostics together to mutation
  accounting before it can claim a kill or refusal.
- Producer Proof: the parameterized synthetic transcripts emit complete,
  incomplete, wrapper-noisy, and trailing-duration TAP shapes.
- Final-Consumer Proof: `NodeTestReporter.read()` returns `RunCounts`; the
  mutate-and-restore suite consumes its `errors` and count fields. The focused
  producer/reader proof is local, not a host replay.
- Interface-Shape Sibling Scan: `PytestReporter` already keeps one selected
  summary line; `scripts/mutate_and_restore.py` is the downstream consumer.
- Non-Claims: no installed-plugin behavior, host-specific Node variant, live
  provider, GitHub state, push/release, Cautilus run, or lesson-session state.
