## Waste

**~30 minutes to a single command choice.** I ran `python3 -m pytest tests`
instead of `scripts/run_standing_pytest.py`, which owns xdist worker selection,
chunk sizing, and an external basetemp. 8,400 tests took over half an hour
single-process; the same suite runs in ~110s through the runner on this 36-core
host. Nothing in pytest's output says the fast path was skipped, so the cost was
invisible until the operator asked.

**Two full battery cycles spent on my own uncommitted state.** The first 17
failures were the export mirror being stale (I edited source *after* running the
exporter) and `charness update` refusing a checkout with tracked local changes.
The second cycle repeated because I fixed only the part my first hypothesis
covered. Committing before running the battery would have collapsed both.

**Three bounded-reviewer spawns produced nothing**, one of them with the explicit
`opus` override `.agents/claude-host.md` requires. I waited on the first two
before doing the verification myself; the correct read was available after the
first idle notification.

**Not waste, and worth separating**: the deep investigations into the coverage
gate and the reference mapper each cost real time and each ended in a
one-line root cause with a measured before/after. Broad exploration under a
disconfirming probe is the phase intent, not overrun.

## Critical Decisions

- **Suspect the verifier first.** The plan's own opening lesson. Applied to the
  coverage gate, it turned "21 files need coverage" into "the instrument
  measured nothing", which was a one-line fix instead of 21 files of work.
- **Prove the property fires before trusting it.** After `raise pytest.UsageError`
  turned out to be absorbed by pytest's hook caller — the guard "refused" while
  5,935 tests still collected — every subsequent check I wrote got a negative
  control that reinjects its own defect.
- **Refuse to raise the cap.** The test-production ratio broke at 1.0002. I
  executed a documented deletion row from the #753 JTBD audit instead, whose
  subject test disclaims itself in its own docstring.
- **Keep `charness uninstall`'s state cleanup** even though its writer is gone,
  because deleting it leaves residue nothing will ever mention again. Same
  transparency rule the operator set for the auto-build.

## North Star Alignment

Read against `docs/design-north-star.md`.

**P3 (principle over rulebook) is the facet this session was about, and the repo
was already on the wrong side of it in several places.** The doc's own reason —
*"an enumerated 'do not X' list rots and still misses the case it never listed"*
— names exactly what I found: `test_empty_scope_refusals.py` and its two sweep
siblings pin the rows a 2026-08-01 snapshot contained, and every defect I hit
(`package_managers` deriving a crates.io install, `detect_binary_name` reading a
PATH assignment, the absorbed `raise`, the ambient marker) is a new instance of
that already-swept class. The repair — a property over every manifest with
negative controls — is P3 applied where a list stood.

**P4 (different evidence channel, different observer) held, and was the only
thing that worked.** Every finding this session came from RUNNING, never from
reading: the doctor payload, `coverage report`, the instrumented hook, `cargo
--version` in two directories. The named failure signature in the diagnosis —
*terminal trust on a single evidence channel* — is precisely what the coverage
gate was doing: it read its own coverage.json and never asked whether that file
contained any test-suite execution.

**P5 (a gate may force a question; it may not declare completion) was violated
by three mechanisms at once, and I nearly added a fourth.** The coverage gate
declared `blocked` from an instrument that measured nothing. The manifest
declared a safe install and derived an unsafe one. The lessons digest declared a
learned lesson to no reader. My first guard declared a refusal that pytest
absorbed. Each was a terminal green (or a terminal red) with nothing behind it.

**Mis-applied:** I spent the first half of the session treating each failure as
its own incident, which is P3 inverted — building a list of my own. The operator
had to say so before I looked for the property.

## Expert Counterfactuals

**Douglas Engelbart — `(H + LAM + T)` as one unit; design T alongside LAM.**
This is the briefed lens for `work_class: system-improving`, and it converges on
the sharpest miss of the session. The repo has an excellent T for lessons —
eight modules produce, validate, gate, rank, dedup, and score
`recent-lessons.md` — and no wiring from T back to H. The artifact was
referenced by no operating document. Engelbart's unit says a tool that improves
the system must close on the human at the moment of action, so the missing line
in `AGENTS.md` was not an oversight in documentation, it was an unfinished T.
Applied earlier, the counterfactual is concrete: before writing a fifth spelling
of a lesson, ask *what reads this*. I would have found "prefer a structural
property over an enumerated refusal" already in the digest with three sources,
and skipped the day I spent rediscovering it.

**Charity Majors — instrument the thing you are about to trust.** A divergent
second lens, and it fires earlier than the Engelbart one. Majors' habit is to
ask what a green signal is actually derived from before acting on it. Applied at
the first battery, the question "what is in the coverage.json this gate just
read?" is a 30-second `json.load` and it was the whole finding. Instead I
theorized about xdist, subprocess coverage, and file-to-test mapping across
several exchanges before opening the artifact. The changed action: when a gate
reports a number, read the number's source file before reasoning about the
number.
