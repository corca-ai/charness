## The one gate miss, analyzed

The standalone selection comparison is fixed-cost-bound on both sides:
Python's 0.15–0.22 s is dominated by interpreter startup over a trivial
enumeration, and Rust's 0.07–0.09 s is dominated by the `git ls-files`
subprocess. There is no analysis payload to accelerate; this owner's real
cost (9.4 s wall / 133 s CPU measured in #744) lives in the runtime import
probes, which the design deliberately keeps in Python (D9 honesty rule).
Both comparisons that carry actual analysis load clear the gate by 4x
margin. The family-level aggregate (three Python processes, 2.7 s, vs the
shared-snapshot native runs, ~0.3 s) also clears 3x — and that aggregate is
what the repository's gates actually pay today.

Recommendation: **go**, under an explicitly amended criterion — "every
comparison with material analysis load >=3x worst-case, family aggregate
>=3x, probe-narrowing family judged on selection parity (714/714 equal) and
narrowing honesty rather than selection wall time." This is a recorded
contract change to the spike's own gate, made on structural grounds, not a
silent relaxation after an unfavorable number. The alternative reading
(strict no-go over a 0.19 s → 0.08 s comparison while 12x holds where work
exists) would fail the umbrella's purpose test.
