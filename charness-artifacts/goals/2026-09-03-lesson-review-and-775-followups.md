## Boundaries

- **Graduation is three questions in order, per lesson, settled by a person** (`lesson-graduation.md`, lesson `graduation-is-proposal`). The agent drafts the disposition, the owner page, the duplicate removals, and the mechanism; the operator settles; the reason is written before the event; docs, mechanism, and event land in one commit. A docs-only graduation goes only into a page read at the decision moment; otherwise the lesson stays active.
- **The review runs one lesson at a time, in Korean, in conversation** (operator, 2026-09-03). No batch table is applied as a batch decision; a table may only order the conversation.
- **Mechanisms precede the lessons they graduate.** `changed-line-proof-before-broad-quality` and `green-test-is-not-covered-line` are not graduated before slice 1 lands; `detector-blind-class-unstated` not before slice 2. A graduation whose mechanism is "planned" is a keep. This binds per lesson, not the whole review: the other thirty lessons may be settled before slices 1 and 2 land.
- **A focused green is not a covered line** (lesson `green-test-is-not-covered-line`). Every brief written in this goal that touches `scripts/` or `skills/` names `release_changed_line_coverage.py --base-sha <base>` as a verification step and pastes its `blocking_detail`, starting with the briefs for slice 1 itself.
- **A test's verdict never depends on wall-clock time** (operator rule 2026-09-03, `docs/development.md`). Slice 2 rewrites or deletes; it never retries, widens, or deselects. A test whose claim is the timeout itself drives the module's clock from a forced observation.
- **Deletion under the runtime root is measured, reported, then done.** The first sweep across keys runs in report mode, the operator reads the report, and only then does the deleting sweep run; the rule it applies is the one `docs/development.md` already states for `pytest-tmp` keys (recorded repo root gone, or idle past `LEGACY_KEY_MAX_AGE_DAYS`). The deleting sweep is a mechanism, not a sentence: it refuses to run unless a report-mode output younger than a stated window exists at the path it writes its own log to, and it deletes only keys that report named. A sweep never reaches outside `charness/runtime/`.
- **The root cause of the nesting is fixed, not only swept.** A child bootstrapped for a different repo root computes its runtime root from the same base the parent used, not from the parent's `XDG_CACHE_HOME`; a regression test seeds the mismatch and asserts the two roots are siblings.
