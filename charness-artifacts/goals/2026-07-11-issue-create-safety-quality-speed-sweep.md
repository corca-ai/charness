## Goal

Find and repair plausible sibling defects exposed by issue #435: mutating
helpers whose verification, generated carrier, or downstream gate contract can
diverge. Improve the surrounding production-code structure, regression tests,
and standing test speed without weakening proof, laundering baselines, or
adding speculative floors. Finish with a measurable before/after quality and
runtime comparison and a durable disposition for every surfaced finding.

## Non-Goals

- Not an exhaustive promise to eliminate every latent defect in the repo; work
  is limited to evidence-ranked, reproducible findings with a clear owner.
- No blanket increase of budgets, duplicate baselines, coverage exclusions, or
  test skips to manufacture green results.
- No broad minimum-title policy or generic validation framework derived from
  one incident when a narrower owner-level contract suffices.
- No live GitHub release, push, remote-CI dispatch, issue close, package publish,
  or Cautilus evaluation during local slices without a later explicit operator
  instruction for that external boundary.
- No claim that one machine's speedup generalizes across host/provider/profile
  axes; timing claims bind to the measured runtime profile and matched command.

## Boundaries

- Scope the sibling audit by interface shape: producer mutation -> emitted
  command/carrier/status -> final consumer validator/gate/operator. Keyword-only
  matches are diagnostic, not fix candidates.
- Classify every sibling as `confirmed mismatch`, `producer precondition`,
  `consumer contract`, `overreach`, or `defer`; implement only a reproduced
  `confirmed mismatch`, while preconditions/contracts route to their existing
  owner rather than duplicating validation logic.
- Prefer code/interface reduction and validation-before-expensive-work over new
  prose or a new blocking floor. Any proposed floor must pass the north-star and
  floor-addition-restraint contract.
- Keep behavior assertions visible in test files; extract only mechanical
  setup/runners/builders when addressing test pressure.
- Run bug-class causal review before implementing #433 or another confirmed bug.
- Local commits are authorized by the request; external writes remain in the
  Operator Decision Queue unless separately approved.
- External side-effect scope: name which phase or bundle any approved
  publish / push / remote-CI / apply applies to. That approval is phase-scoped
  and does not carry forward — after an approved publish/CI/apply lane
  completes, done-early test-only quality continuation is local by default
  (batch remote proof, run CI once over the final bundled state). Per-slice
  remote publication is assumed only when the operator explicitly asks or a
  runtime-affecting slice requires earlier publication.

## Agent Verification Plan

### Low-Cost Checks

- Focused unit/in-process tests per changed module; CLI parsing and carrier
  draft validation against seeded fixtures.
- `ruff`, `py_compile`, relevant artifact/skill validators, mirror-drift checks,
  and cheap commit hooks at commit boundaries.
- Static interface-shape searches across mutation producers and their final
  consumers, with concrete file:line and decision/proof labels.

### High-Confidence Checks

- `run_slice_closeout.py --skip-broad-pytest` at pre-lock slice boundaries and
  `--verification-lock --produce-mutation-coverage` for the final bundle.
- Full standing pytest and `./scripts/run-quality.sh --read-only` at bundle
  closeout; release-only tests when release helper behavior changes.
- Matched before/after runtime samples: baseline `pytest` latest 30.9s, recent
  median 32.5s on `local-linux-x86_64-36cpu`; report targeted and full-suite
  results separately, including noise and cache non-claims.
- For any speed claim, use the same command/profile/cache declaration with at
  least three paired before/after samples and report min/max/median. A targeted
  improvement cannot be promoted to a full-suite claim, and a median change
  inside observed jitter is reported as inconclusive.
- Limit new test surface to one failing fixture plus one regression per repaired
  sibling unless production simplification or a shared mechanical helper
  removes/centralizes more setup than the tests add.
- Fresh-eye critique for the plan, each substantial risk boundary, and final
  recurrence/quality disposition.

### External Or Live Proof

- Default: not run. GitHub/provider behavior is represented by seeded backends,
  isolated repos, and exact hook/carrier roundtrips.
- If the operator later authorizes push/release/issue-close, batch it once over
  the final bundle and verify via a distinct public/readback channel.
- Cautilus remains ask-before-run; use it only if deterministic proof cannot
  exercise a prompt/agent behavior claim and the planner recommends a scenario.
