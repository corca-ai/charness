# Repeated bootstrap and fixed-form reasoning can obscure a long task's next action

## Problem and capability

The same unchanged contract may be rediscovered at every skill transition or resume. Debug prescribes three hypotheses even when evidence narrows the cause; spec/retro begin with broad bootstrap. Reduce redundant work while preserving the investigation that catches stale assumptions, missing context or recurrence.

## Fixed decisions and scope

- Feature; dependency: comparison-contract. Reuse principles belong in existing public skills/references, not a separate lite mode or progress system.
- Scope: `skills/public/spec/`, `skills/public/debug/`, `skills/public/retro/` and direct shared bootstrap consumers; `impl` supplies the existing reuse example. Remove prose-pinning checks in `tools/check_skill_contracts.py` only when they enforce wording rather than a required parsed contract.
- Preserve live provider/delta reads on resume, causal falsifiability, minimal reproductions, recurrence routing, acceptance and independent proof-boundary judgment. A previous conclusion is not current evidence when its inputs changed.

## First action and probes

Use frozen scenario inputs to distinguish unchanged contract, changed contract, missing context, obvious local cause, uncertain cause and recurring seam. Identify each unconditional operation and its actual owner. Decide from these observations whether a command can disappear or becomes conditional; do not simply move boilerplate into another reference.

## Success criteria and checks

- The unchanged-context scenario reaches its next correct action with a concrete redundant read/planner/scaffold operation removed. Changed/missing inputs still trigger the appropriate lookup and contract repair.
- Debug preserves falsifiable cause and recurrence handling without requiring a fabricated hypothesis quota; visible uncertainty still receives alternative-cause testing.
- Chat-only retro need not pay durable scaffold cost unless persistence is requested or needed for the claim; durable lessons and follow-up obligations stay with their existing owner.
- Local readiness for consumer-comparison requires integrated changes, behavior-oriented scenario proof, focused contract checks and independent review. The downstream candidate pilot assesses preserve/improve for final acceptance and closure; it does not block the pilot from starting. Exact prose substring success is not evidence of semantic behavior.
- Record removed overhead and replacement instruction/selection/fallback cost. Preserve schema/frontmatter/parser checks; negative controls still detect a genuinely missing required boundary.

## Boundary and non-goals

No bypass of user approval, independent boundary observers or durable provider truth. No broad skill rewrite or source-history migration. Public instruction changes receive first-reader review; parent integrates, exports and verifies the shipped consumer path.

## Implementation decisions

Warm selection stays in each skill's core. The existing debug planner remains
the discovery/fallback owner, not a new warm-eligibility engine. Its runtime
summary cannot certify historical adapter/validator equivalence by comparing
two fields produced from the same current scaffold. The parent excluded that
candidate addition and its changed legacy continuation expectations.

The debug validator changes only its numeric candidate floor from three to
one. Its existing hypothesis disconfirmer and current/historical artifact roles
remain unchanged. Whether competing causes were actually distinguished remains
the existing diagnosis/reviewer and first-reader scenario obligation, not a new
magic text marker. Tests exercise one/two causes, no candidate, and one cause
without a falsifier. Retro's catalog moves to optional reads; its parsed artifact,
trigger state, and persistence owners remain. No new mode or state record exists.
