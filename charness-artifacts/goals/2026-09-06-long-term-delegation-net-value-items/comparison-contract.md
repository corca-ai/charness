# A long-delegation net-value claim lacks a fair no-plugin comparison

## Problem and capability

Prior skill-journey comparisons do not establish whether Charness helps versus no plugin, or whether model tiers differ. Existing fixture instructions and task execution inject Charness, so copying them to a baseline would contaminate the comparison. Produce a frozen, runnable pilot protocol without executing an arm before its authority and inputs are settled.

## Fixed decisions

- Feature; no dependencies. Canonical planning provenance: `charness-artifacts/goals/2026-09-06-long-term-delegation-net-value.md`.
- One four-arm pilot: high/low tiers crossed with candidate/no-plugin, two fresh contexts per arm. Reuse alias fixture semantics under `evals/fixtures/consumer-journeys/spec-impl-alias/`; do not reuse its plugin-specific shared instructions.
- Shared semantic task, initial files, scheduled cooperative checkpoint, durable contract delta, acceptance and permissions. Only treatment supplies Charness. Baseline may use ordinary tests, notes, git and the same underlying issue capability.
- Neutral host runner isolates roots and collects observations only. It must not recover intent, repair code, supply a contract, or donate Charness task-run behavior. No new maintained product runner or evaluation platform.

## Probe questions and first action

Before any arm, write the protocol and hidden observer using the existing `charness-artifacts/probe/` class. Resolve exact models/common supported effort, clean host/plugin visibility, provider channel, time/token ceiling, context reset and checkpoint stimulus. A real provider is preferred only within explicit repository authority; if using an isolated adapter fixture, declare that this cannot prove live provider recovery. This choice is fixed in the protocol, not changed across arms.

## Success criteria and checks

- Freeze seed, semantic prompts, treatment wrappers, delta, oracle, settings, model IDs, intervention and retry rubric, arm order, budget and price source if dollars are reported. Hash exact bytes before any run. No agent can read oracle or another arm's outputs.
- Preflight demonstrates actual fresh-context launch and absence of Charness discovery in no-plugin; a contaminated arm is invalid, not a poor baseline result.
- Observer reaches final behavior, preserved prior behavior, delta behavior and disallowed mutations. Resume assessment checks selection of durable truth and the delta before implementation, without user restatement.
- Validation includes a deliberately wrong output rejected by the hidden observer and a correct control accepted. These checks prove the experiment boundary, not product benefit.

## Deferred and non-goals

General crash recovery, broad reliability and significance claims wait for replication driven by a concrete pilot gap. Freeze candidate revision when implementation is ready; preserve the initial pilot if candidate fixes lead to separately labelled reruns. Parent owns provider binding and publication; this child does not create external repositories or grant evaluator authority.
