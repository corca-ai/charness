# charness v3.0.1

A few commits since `v3.0.0`. No new skills, no renames, no changed commands or
flags. Four gates that used to exit **0** on absent, empty, or unrecognized input
now refuse it — and three of them ship inside the plugin, so **a consuming repo's
gates can start failing on inputs that did not change**. Read Migration before
upgrading.

## Why patch

The version policy puts validation and packaging repairs, and runtime corrections
that preserve the same public shape, under `patch`. Nothing here renames a skill,
removes a surface, changes a command or a flag, or forces an edit before you can
upgrade. The bump is nonetheless debatable — a previously-green run can go red —
so the consequences are enumerated below rather than left to discovery. One
caller-contract change (a JSON key rename) is called out explicitly.

## Migration — stricter gates

- **SKILL.md core density.** Lines under `## References`,
  `## Load-Bearing Anchors`, and `## Closeout Vocabulary` are exempt from the
  core-density count only up to a per-heading budget (28 / 12 / 12 non-empty
  lines); the overflow is charged back to the count, and fenced lines inside
  those sections always count. Separately, the anti-abuse audit now reads *every*
  block of *every* exempt heading rather than only the first
  `## Closeout Vocabulary`: a multi-sentence prose line under any of them is a
  blocking finding. Two consequences worth knowing before you hit them:
  - a pre-existing prose line under an exempt heading blocks the **first** edit
    to that package, on a line you did not write. The fix is to rewrite it as a
    single clause or move the explanation into `references/`. The gate now prints
    that remedy.
  - a skill that sat comfortably under the ceiling can now sit closer to the
    headroom buffer, so a later small edit can block. Run
    `python3 scripts/check_skill_surface_preflight.py --path <SKILL.md>` once
    after upgrading to see the new numbers before you need them.
- **`check_skill_surface_preflight.py` payload rename.** The findings key
  `closeout_vocab` is now `exempt_findings`, and the human line
  `BLOCK closeout-vocab:` is now `BLOCK exempt-section:`. If you parse either,
  update it: a reader of the old key sees no findings and reports green.
- **Two `core_nonempty` numbers now exist and they disagree.** The preflight
  counts with budgets, fence charging, and `## Closeout Vocabulary` exempt; the
  `quality` skill's inventory keeps the older unbounded count. Take the number
  you paste into a quality artifact from the **inventory**, not the preflight —
  the artifact validator recomputes it and refuses a mismatch.
- **`hitl` `check_chunk_contract.py`.** Empty or whitespace-only chunk text now
  returns `blocked` / exit 1 instead of `pass` / exit 0, so a wrapper that pipes
  empty stdin as a smoke test will fail. Decision detection also fires now on
  request phrasings without a question mark. A chunk that already carries
  **Agent Assessment** and **Recommended Disposition** is unaffected. An
  unreadable `--chunk-file` path now returns `{"status": "error"}` with exit 2
  instead of a traceback at exit 1.
- **`validate_cautilus_diagnostics.py`.** A directory carrying bundle-shaped
  evidence (`cautilus-report.json`, `justification.md`, `outcome-grade.md`,
  `trace-digest.jsonl`, `transcript.txt`, `observation.stderr`) but no
  `finding.md` and no `observed.v1.json` / `summary.v1.json` / `report.json` is
  now reported under both `--paths` and `--all`. The non-diagnostic exclusion
  list is a hardcoded set of directory prefixes (`held-out/`, `full-gate/`,
  `chatbot-benchmark/`, `chatbot-proposals/`, `skill-experiment-`) with no
  adapter seam: if your cautilus adapter writes evaluator output to a differently
  named directory, that directory will redden your lane.
- **`issue` `audit_brief.py`.** A mutation event with no recognized
  classification recorded before it is now a violation, for every class — absent,
  recorded after the mutation, or misspelled all count. An empty transcript is
  now a transcript error (exit 2) instead of `audit ok`.

## What this does not claim

- **No consuming repo was exercised.** Every repair is proven against this repo's
  fixtures, tests, and live corpus (34 cautilus bundles, 22 `SKILL.md` files).
  That is not a claim about your repo's shapes.
- **The `hitl` decision detection is a floor, not a detector.** A decision request
  phrased outside the known phrases and positions still passes silently; a green
  is not evidence that the chunk asked nothing.
- **`audit_brief.py` still has no caller in the `issue` workflow.** This fixes the
  checker's verdict for direct callers. If you never call it, this release changes
  nothing for you.
- **The `quality` inventory keeps the old exemption rules.** The density repair
  landed at the author-time preflight only; the portable copy is unchanged by
  design (it cannot import repo-internal modules).
- **The checked-in quality review predates these surfaces.**
  `charness-artifacts/quality/latest.md` is dated 2026-07-25 and covers none of
  the code this release changes.
- No live cautilus evaluation, no mutation-score lane, and no consuming-repo
  install were run for this release.
