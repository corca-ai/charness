# charness 6.3.0

Proof got cheaper, the mutation harness works on a Node repository, and the goal
contract can tell a written section from an empty one and represent a goal that
ended without completing.

## Proof cost: the changed-line gate stopped paying for a column it never reads

The changed-line mutation-coverage gate collected per-test coverage `contexts`
that its own verdict never consults — it reads `executed_lines`/`missing_lines`
only. Measured from one coverage data file, with the export flag as the sole
difference:

```text
                with contexts          plain              ratio
  export        162.4 s / 8.22 GB      21.5 s / 12.26 MB  7.6x / 671x
  load          36.5 s / 20.44 GiB     0.13 s / 0.06 GiB  276x / 339x
                (peak RSS)
```

Verdict inputs were proven identical per file rather than by count: the same file
entries on both sides, and no file with a differing executed/missing line set.
Full measurement, with hashes and the exact commands:
`charness-artifacts/probe/2026-08-22-changed-line-coverage-context-blowup.json`.

Collection is now an explicit `--collect-test-contexts` flag, off by default. The
peak RSS was the sharper half of the cost: on a smaller host that load raises
`MemoryError`, and the gate has no branch for it, so an out-of-memory crash on a
proof surface would read as a tool failure rather than the refusal-to-judge it is.

When the gate cannot USE the coverage it finds, its structured payload now carries
`resume_command` and `resume_route`: the incremental lane first, and the
whole-corpus rebuild as the fallback. The lane's own measured cost is quoted in
`scripts/prepush_focused_changed_line_coverage.py`. Previously only the expensive
route was named, which is how a session came to rebuild the corpus repeatedly.

## The mutation harness runs against a Node repository

`mutate_and_restore` enforces its properties in terms of reported COUNTS, but how
to READ those counts was pytest-shaped and hardcoded, so no Node repo could use
it. Measured against a `node --test` fixture whose baseline is GREEN:

```
before:  exit 2, "baseline REFUSED: baseline produced no readable passing count"
after:   exit 0, "baseline: 2 passed", killed: 1
```

A plan selects its reader with a new key:

```json
{ "test_command": ["node", "--test", "--test-reporter=tap"],
  "reporter": "node-test",
  "mutants": [ ... ] }
```

**`--test-reporter=tap` is required, and this is the part most likely to bite.**
node picks its reporter by TTY, so a captured CI run may give you `tap` while an
interactive one gives you `spec`. The `spec` format omits the file-level failure
detail the harness needs to tell a broken module from a caught mutation, so it is
refused rather than half-read — with that flag named in the refusal.

That distinction is load-bearing: `node --test` has no error concept, so a test
FILE that fails to load is reported as a failing TEST. A module-breaking mutant
would otherwise have been reported as a KILL when no test caught anything.

`reporter` defaults to `pytest`, so every existing plan is unaffected.

## `--pursue-ready` tells a hollow section from a written one

A goal artifact could pass with whole required sections as bare headings, so
"pursue-ready" came to mean "has the right headings". A section is now hollow when
its body is empty **or** still byte-identical to what the scaffold wrote there —
because the scaffold seeds guidance prose everywhere, a plain non-empty check
would have called every fresh draft shaped.

Hollow sections are reported for every required section and refused only for the
shaping ones; `## Slice Log` before any slice runs is legitimately empty and is
reported without refusing. A section with genuinely nothing to say keeps its
heading and states `N/A — <reason>`, which the refusal names.

This reaches the exit code only under `--pursue-ready`, never the default
`check_goal` path, and is skipped for every non-shaping status — so no existing
artifact reddens on update.

## A goal can end without completing

`superseded` joins the status enum for a goal folded into a successor, overtaken,
or abandoned with its remainder handed on. Previously such a goal had to choose
between staying `active` forever and claiming a `complete` it never earned.

It costs one line, `Superseded by: <successor>`, whose path is verified to exist
when it looks like a path; `Superseded by: none — <reason>` is accepted, and
accepting it is the point. Refused at the write, including on creation.

**Before adopting it, know this.** It does NOT run the closeout-evidence
or Auto-Retro disposition floors that `complete` runs, so a run that surfaced
improvements can end with them unrecorded (#698). And a goal marked `superseded`
is an invalid status under the previous release, so adopting it forecloses a
clean downgrade.

## Evidence-durability scanning covers the artifact families that carry citations

`check_spec_evidence_durability` skipped the artifact families that carry most
evidence citations — goals, critiques, retros, probes, issues and release
reviews. Those were never scanned, and they held citations that had already
evaporated while the scanned families held none.

The scan now covers them. Enforcement is anchored on the artifact's
FILENAME date: artifacts predating the widening are counted and reported, never
rewritten, because editing a frozen retro so a checker goes green is evidence
edited to fit a gate. Artifacts dated from the widening forward are enforced, and
so is any artifact whose filename carries no readable date at all — an undated
filename must not buy a permanent exemption, which is a direction this repo has
had to correct on more than one floor.

**This gate is repo-internal.** It is classified `consumer_facing: false` in the
consumer validator catalog and is wired only from `scripts/run-quality.sh`, which
the `charness` CLI does not install or invoke. It does ship in the checked-in
plugin export alongside that runner, so a consumer who chooses to run the exported
`run-quality.sh` directly would exercise it against their own artifacts; nothing
in a normal install does.

## The cadence floor stopped refusing truthful artifacts

The gate-cadence floor matched the literal presence of `--skip-broad-pytest` /
`--verification-lock`, so a frame saying "broad pytest at EVERY slice boundary; do
not pass `--skip-broad-pytest`" read as deferring and `/goal` refused an artifact
carrying no contradiction. The floor now declines to render a verdict when every
flag mention on the line is negated, and does not block activation.

It does not read polarity — that would be the paraphrase matching the module
refuses. It reports that it cannot tell, and quotes the clause. No checked-in
cadence line declines, and no artifact migration is needed.

## Rollback: remediate, do not roll back

There is no version selector on `charness update`, and no downgrade procedure is
documented. That is deliberate advice here rather than a gap being papered over:

- the hollow refusal is per-artifact and fixable in place (write the section, or
  `N/A — <reason>`)
- the durability widening is repo-internal: no installed surface invokes it
- the reporter key and `superseded` are opt-in
- and per the section above, a downgrade after adopting `superseded` is lossy

If you must pin, pin the managed source checkout to `v6.2.2` and run
`charness update --repo-root <checkout> --no-pull`.

## Known limitations this release ships with

- **#699** — the release critique acceptor binds on version tokens, so a
  superseded HOLD critique for an abandoned candidate that reused the same version
  number can authorize a publish. Found while publishing this release; worked
  around here by passing `--critique-artifact` explicitly.
- **#697** — the mutation sampler and the changed-line producer share one coverage
  report path, and the freshness marker fingerprints content rather than the
  writer, so it cannot tell them apart. The read side is guarded, and that guard
  is a **third non-blocking skip** on the changed-line proof surface: in a session
  where the sampler ran first, the changed-line proof now stands down rather than
  rendering a verdict. The design is not fixed.
- **#698** — `superseded` bypasses the Auto-Retro disposition floor.
- **#694** stays open on its second blind shape: a deferral flag named only for a
  terminal step, with no earlier deferral, is still read as a deferral.
- **Documentation gap.** The `reporter` plan key, the hollow refusal, and
  `superseded` are under-documented on the shipped operator surfaces —
  `mutation-testing.md` does not mention the reporter key, `SKILL.md`'s list of
  what makes `--pursue-ready` fail is now incomplete, and `lifecycle-after.md`
  does not cover `superseded` even though the phase brief routes there. The
  runtime refusals name their own fixes, which is what keeps this a gap rather
  than a trap.
- **#671**, **#687**, **#688** unchanged.
