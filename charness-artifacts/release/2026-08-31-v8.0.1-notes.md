# Charness 8.0.1 — reuse established release quality at push

## Summary

Charness 8.0.1 lets release publication avoid a duplicate broad-quality run.
When the release helper has already established full release quality for the
exact clean Git and materialized-plugin state being pushed, the pre-push hook
reuses that result instead of rebuilding the same proof; otherwise it falls
back to the ordinary gate.

This is a release-workflow repair. It does not change the public skill or CLI
capability shape shipped in v8.0.0.

## What changed

- The release helper invokes `run-quality.sh` with `--receipt-json` and seals
  the resulting semantic receipt, which identifies whether release and
  full-queue quality actually passed, including explicit non-claims.
- The release helper seals that result to the exact clean `HEAD`, Git tree,
  repo-owned quality command, and materialized plugin bytes.
- The pre-push hook verifies pushed local-ref ancestry, consumes the matching
  receipt, and deletes it after that use.
- The irreversible close-keyword scan precedes receipt consideration on each
  pre-push invocation.
- A changed commit, dirty tree, changed materialized export, malformed receipt,
  or uncovered ref falls back to the ordinary pre-push quality path. A later
  artifact-only commit therefore receives its own relevant gate rather than
  borrowing proof for an earlier tree.

## Upgrade

1. Run `charness update`.
2. Confirm `charness version` reports `8.0.1`, then run `charness doctor`.
3. Restart the Codex or Claude session so the refreshed plugin cache is loaded.

## Rollback

For an installed consumer, reinstall or pin `v8.0.0` through the host's normal
plugin-install mechanism, then restart the host session. For a Charness source
checkout, revert or pin the checkout itself to `v8.0.0`; changing the installed
plugin alone does not revert repo-local hooks or release helpers. Rolling back
restores the duplicate release-push quality run but does not change v8.0.0's
public capability contract.

## Known residuals and non-claims

- The release quality command explicitly omits changed-line mutation
  coverage for this Goal. No mutation verdict or score is claimed.
- Receipt reuse targets the duplicate broad run for an unchanged release
  subject. It does not claim that the canonical release-quality run itself,
  plugin import checks, or subsequent pushes are fast.
- The standing-suite launch census from v8.0.0 remains structural evidence of
  reduced repetition, not an acceptable absolute spawn floor or a measured
  consumer-development speedup. This patch does not claim the residual Git or
  Python process population is small.
- Receipt integrity protects ordinary release operation from accidental stale
  reuse. It is not a security boundary against an operator who can rewrite the
  checkout or bypass Git hooks.
