# Charness v0.66.3

This patch release shortens two failure loops without weakening the final
release boundary.

## What changed

- Verification lock now checks the result of generated-surface sync before any
  verification command starts. If sync changes tracked state, closeout stops
  immediately, lists only the paths changed by sync, and tells the maintainer
  to commit the generated output and rerun the lock. Untracked scratch files do
  not trigger the stop.
- Concurrent identical usage-feedback writes are now serialized per record
  stream. Cooperating writers produce one append and one replay no-op instead
  of duplicate feedback IDs that invalidate the stream.
- Release-readiness, critique, and quality inventory records from the preceding
  lifecycle are carried forward without changing public command shape.

## Why it matters

Maintainers no longer pay for a broad verification run that was guaranteed to
be invalidated by freshly generated tracked files. Feedback capture also stays
idempotent when two agents record the same reviewed outcome at once.

## Compatibility and non-claims

- This is a patch: no public command, schema, skill name, or invocation contract
  is removed or renamed.
- The final clean-HEAD verification lock remains mandatory; the new preflight
  only exposes sync drift earlier.
- Feedback locking covers cooperating feedback writers. A whole-stream locking
  protocol for other event producers is not claimed.
- Existing tracked issues remain open; this release does not perform issue
  lifecycle changes.
- No binary release assets are expected; the GitHub source archives are the
  normal generated assets.

## Update

Run `charness update`, then confirm `charness --version` and `charness doctor`.
