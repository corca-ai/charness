# Charness v2.1.4

This patch makes the dead-code advisory quieter without weakening its deletion judgment.

- The two previously recurring dynamic-call findings are now classified as `registered_dynamic_entrypoint` only when repository AST evidence connects the producer to its actual consumer.
- Supported `runpy` evidence must resolve the exact caller-sibling file and symbol. Wrong absolute paths, nested paths, and matching strings alone remain review candidates.
- Supported hook-registry evidence must connect an uppercase `*Intent` entry through its bound consumer loop, module import, and same-receiver `getattr` dispatch. Unrelated loaders, receivers, and disconnected loops remain review candidates.
- The advisory's main module was split into cohesive source-role and dynamic-evidence helpers, restoring length headroom without changing the public command shape.

The release content delta is `v2.1.3..v2.1.4`. It includes two already-pushed v2.1.3 release-closeout records that do not change plugin behavior, followed by the two new implementation and fail-closed proof commits.

## Upgrade and rollback

Run `charness update`, then start a new Codex session or restart Claude Code so it loads the refreshed plugin surface. Use `charness version` and `charness doctor` to confirm the installed version and source/cache alignment. No migration is required.

To roll back, install the prior v2.1.3 release. The advisory remains non-blocking in both versions, so rollback does not change a release or deletion gate.

The live sweep reports 21 lower-confidence findings, including 2 evidence-backed dynamic entrypoints and 0 review candidates. This is not proof of arbitrary Python reachability or permission to delete unclassified code. No end-to-end wall-clock speedup is claimed; measured advisory runtime stayed near the 8.92-second baseline. No release-time real-host proof trigger matched this delta; fresh-checkout, public-readback, and installed-version evidence remain release closeout responsibilities.
