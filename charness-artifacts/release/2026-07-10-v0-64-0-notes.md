# Charness v0.64.0

This release makes usage feedback safer and more truthful, and speeds up common
operator and validation paths without changing existing install workflows.

## Highlights

- Adds a privacy-safe, linked usage-feedback event and operator writer so later
  evidence can be attached without storing prompts, transcripts, or identities.
- Keeps delivery counts and product-review dimensions truthful when explicit
  feedback events are present, including time-window and unique-threshold rules.
- Rejects malformed historical feedback streams without appending or emitting a
  traceback.

## Faster and More Reliable Paths

- Reuses a healthy bootstrap runtime after one isolated contract/module probe,
  while preserving the existing repair path for malformed, old, missing, or
  non-executable launchers.
- Runs independent Markdown advisory and blocking scans concurrently while
  preserving output, stderr, and exit-code behavior.
- Makes plain `charness version` and exact `charness --version` read-only probes;
  detailed `--verbose`, `--json`, and `--check` modes keep provenance behavior.

Measured on the maintainer Linux host: healthy bootstrap resolution improved
from 502ms to 102ms median; the Markdown gate from 4.73s to 4.01s; its dominated
preflight integration call from 5.02s to 3.96s. These are operator-path
measurements, not a claim about an application-serving or LLM runtime.

## Upgrade

Run:

```text
charness update
```

Then start a new Claude Code or Codex session if the update reports stale active
plugin paths.

## Limits and Non-claims

- No observer-owned feedback has been recorded yet; this release makes the loop
  available and correct, not proven product-improving in real use.
- No production LLM/provider runtime was added or benchmarked.
- No Cautilus evaluation was run; deterministic code/data/runtime gates owned
  this release.
- No GitHub issue closure is claimed by this release.
