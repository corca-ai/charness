# Charness v1.0.6

This patch release fixes the skill bootstrap failure reported from a consuming
repository and makes issue/release lifecycle evidence truthful without
mistaking objective completion for user satisfaction.

## What changed

- Fixed the unsafe shell form
  `SKILL_DIR=/path python3 "$SKILL_DIR/scripts/..."`, which expands
  `$SKILL_DIR` before applying the temporary assignment and can invoke
  `/scripts/...` when the prior value is unset.
- The shared bootstrap contract now exports `SKILL_DIR` before use and keeps the
  export plus dependent command in the same shell or tool invocation.
- The existing bootstrap validator now protects the exact failure pattern in
  both the canonical reference and individual public/support skill Bootstrap
  blocks that cite it.
- Verified issue close and release publish workflows can append linked,
  privacy-safe objective lifecycle signals when usage episodes are enabled.
  `closed_issue` and `released` are reported separately from `accepted` and
  `human_confirmed`; they are not evidence of human approval or general
  satisfaction.

## Verification boundary

- Focused bootstrap and lifecycle suites, plugin export synchronization, the
  locked broad repository closeout, and changed-line mutation coverage pass.
- Release publication still requires the normal public distinct-channel
  readback. After update, closeout will also run the documented bootstrap from
  an unrelated consuming-repo directory against the installed plugin cache.
- No historical lifecycle records are backfilled, and no per-issue lifecycle
  events are inferred for issues closed indirectly by a release.

## Update and rollback

Run `charness update`, then restart active Claude Code or Codex sessions before
judging the refreshed plugin cache. If you cannot update immediately, keep the
export and every `$SKILL_DIR`-dependent command in the same shell/tool
invocation. No migration is required. For rollback, select tag `v1.0.5` through
the same install method used for Charness, then restart the host session.
