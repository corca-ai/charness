# Charness v2.4.2

This patch makes the quality runner more reliable and keeps Defuddle guidance on
its upstream documentation.

## What changed

- Specdown quality checks now use the supported CLI invocation and write their
  transient report outside the repository, so a routine quality run does not
  dirty an executable-spec report.
- A Markdown file named `*.spec.md` alone no longer selects the Specdown quality
  preset. Add `.specdown` or `specdown.json` when a repository intends to use
  that executable-spec workflow.
- Defuddle installation and update guidance now points to the upstream project
  documentation. The supported command remains `npm install -g defuddle`.

## Update and recovery

Run `charness update`, then restart the active Codex or Claude Code session so
it loads the refreshed plugin. No data or configuration migration is required.

This patch does not add a version-pinned in-place rollback command. If an
update fails, keep its recovery output and use the normal reinstall/recovery
path for the previously working release rather than manually rewriting a
published tag or release state.
