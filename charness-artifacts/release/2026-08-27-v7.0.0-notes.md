# Charness 7.0.0 — faster, lower-friction development

## What changed

- `charness:achieve` is now the owner of active Goal Run navigation and
  progress. Goal pickup reads the provider's parent summary and the cursor
  child needed for the current slice; full child-graph reconciliation is an
  explicit sync operation.
- The standalone `charness:handoff` surface, `docs/handoff.md`, its adapter,
  and Charness-provided SessionStart/startup-context routing are removed. The
  normal discovery path is `AGENTS.md` → `docs/index.md` → the owner page.
- Independent work now fans out through the host's live spawn/subagent API when
  it is exposed; the parent owns intent, integration, and final verification.
  `charness task run` remains the isolated implementation lane when an explicit
  named worktree is useful or the host has no spawn channel. It creates that
  worktree from an explicit base, requires a clean parent, accepts an explicit
  scope, keeps runtime/cache output outside the worktree, runs the requested
  Codex command, and leaves a concise receipt. The older
  claim/submit/review/abort envelope remains available only when an external
  carrier or lifecycle really needs it.
- Provider resolution is explicit and happens once per operation. Python
  bytecode, pytest/coverage data, temporary output, and task runtime records
  are isolated from the source worktree instead of being hidden by
  `.gitignore`.
- The canonical `skills/public/` source and generated plugin export remain the
  package boundary. Export and release-layout checks remain; mirror editing is
  not an authoring workflow.
- Ordinary Goal completion uses deterministic Auto-Retro checks by default; a
  separate `Disposition review` is required only when a goal adapter explicitly
  selects `review-required`.
- The lesson ledger remains available as optional durable memory and selection
  state. `achieve` reads the bounded `recent-lessons.md` projection once when a
  goal starts or resumes (the `/goal` payload carries it; artifact-only starts
  use the same reader). Session-emission receipts and retro
  disposition-continuity records are no longer produced or required by the
  default or release contracts. The separate contract-register/graduation
  ceremony and its artifact are removed; consumers that need contract
  graduation must own that policy, while ordinary lesson memory uses only the
  ledger and its pure selection projections.
- Cautilus and its adapter, eval fixtures, proof planners, prompt-mutation
  tooling, generated artifacts, and Charness-owned lifecycle gates are removed
  from this release. Charness no longer installs, invokes, or validates
  Cautilus; a future integration would be a separate reintroduction.
- The stale checked-in #514/#515/#518 source-freeze bundle, which referenced
  retired closeout implementation, is removed. The generic source-capture and
  freeze validator remain available for a consumer that explicitly needs them;
  this historical bundle is not reused or re-stamped.
- Generic reviewer delivery receipts remain the proof of reviewer output
  delivery; lesson-session bundles, lane arguments, and lesson-bound reviewer
  finalization are no longer part of that reviewer contract.
- Release runs the full `--release` quality lane plus the adapter-declared CLI,
  package-surface, and fresh-checkout probes. Changed-line mutation is no longer
  auto-queued by Charness: the former branch-wide producer reran standing pytest
  after release pytest and blocked on a claim owned by no explicit consumer. The
  portable changed-line gate and scheduled mutation workflow remain available to
  consumers that explicitly opt in and provide their own scope.
- The lane was repaired to follow the current Achieve-owned, progressive-disclosure,
  and external-runtime contracts; stale handoff-era checks and artifacts were
  removed or updated instead of being hidden by a weaker release command.

## What you need to do

1. Refresh an existing installation with `charness update`.
2. Restart the Codex or Claude session after the refresh so the new plugin
   cache is loaded.
3. Remove any manually configured Charness SessionStart, Codex startup, or
   compact-context hook that still injects the retired handoff/routing flow.
   Do not recreate `docs/handoff.md`; read `AGENTS.md`, then `docs/index.md`,
   and invoke `charness:achieve` for an active goal.
4. For independent work, inspect the live host tools and use its spawn API
   first. Use `charness task run` when the lane needs a named isolated worktree
   or the host exposes no spawn channel, supplying `--repo-root`, `--path`,
   `--branch`, `--base`, `--scope`, and a prompt.
5. Keep the parent worktree clean before using `charness task run`; preserve
   any user changes in their own worktree or commit them intentionally before
   starting an isolated lane. If a consumer has a wrapper such as
   `run-codex-lane.sh`, keep only lifecycle behavior that the host spawn API or
   `charness task run` does not provide; this release does not modify consumer
   repositories automatically.

## Compatibility and boundaries

- This is a breaking release for callers that invoke `charness:handoff`, read
  `docs/handoff.md`, or depend on Charness-installed SessionStart/startup
  routing. Migrate those callers to the Achieve plus progressive-disclosure
  path above before removing their old configuration.
- This is also a breaking release for Charness callers that invoke or validate
  Cautilus surfaces. Remove those calls or keep them in a consumer-owned
  evaluator integration; no Cautilus command, adapter, fixture, or generated
  mirror is shipped here.
- The retro lesson ledger remains the durable memory surface; it is separate from
  session-emission receipts and retro disposition continuity, which are outside
  the default and release contracts. Lesson pickup is an Achieve entry action,
  not a global session hook, and it is advisory rather than a gate.
- Scheduler integration, hosted enforcement, conditional-trigger execution,
  and consumer-repository adoption are not claims of this release. In
  particular, the `ceal` wrapper is not deleted or declared fully replaced by
  this package release.
- This release does not claim changed-line mutation coverage for every modified
  Charness file. It claims the focused/core/release functional checks that are
  actually run; a consumer must explicitly own any changed-line or mutation
  proof it requires.
- To roll back, pin the installation to the previous published package
  (`6.5.0`) through the host's normal plugin-install mechanism. The retired
  handoff and hook behavior returns only with that older package and any
  separately retained host configuration.
