# Charness v0.63.0

This release adds an advisory prompt-mutation evaluation workflow for finding
which prompt sections are witnessed by scenarios, which sections are scenario
coverage debt, and which sections are candidates for cautious demotion.

## What Changed For Operators

- Added prompt-mutation tooling for section splitting, parentless snapshot
  generation, witness coverage, survival scoring, sentinel checks, and
  efficiency A/B capture support.
- Added capture-hygiene helpers:
  `prompt_mutation_clean_proof_preflight.py`,
  `check_prompt_mutation_blinding.py`, and
  `prepare_prompt_mutation_blind_workspace.py`.
- Documented the prompt-mutation policy: `UNTESTED` is scenario-coverage debt,
  `NO-OBSERVED-EFFECT` is a ranking signal, demote before delete, rerun the
  ship configuration, and batch changes behind a ratchet.
- Added friction reducers for maintainers, including goal closeout
  normalization, duplicate-ratchet triage drafting, and plugin-sync change
  summaries.

## Non-Claims

- No prompt prose is deleted or demoted by this release.
- The prompt-mutation pipeline is advisory. It does not add a commit or CI gate.
- `NO-OBSERVED-EFFECT` does not prove dead prompt prose; it only ranks a unit for
  review under the observed scenario battery.
- The live pilot was small-N and host/scenario-specific.
- The step-7 slim wording did not ship as a prompt change because the capture
  evidence was treated as tainted by blinding probes.
- Blinding helpers reduce late taint and report whether a clean blinding proof
  can be claimed; they do not guarantee hidden tool behavior.

## Upgrade

Run `charness update` to install the latest published Charness release. No
configuration migration is required. Restart active host sessions if the plugin
cache path changes during update.
