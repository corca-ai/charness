# Charness 3.2.0

## Operator outcome

This release adds an opt-in decision receipt for recurring closeout cost and
makes the quality-bootstrap customization warning safer for nested policy
values. The receipt is advisory: it does not move a gate, change the emitter
schema, or claim runtime relief.

## Highlights

- `retro --detail` reports the current readable schema-1 population, retention
  window, exact recurrence cohort, parent-record statuses, and finite paired
  elapsed/budget summaries. The default miner output is unchanged, and the
  detail mode is opt-in through the installed retro skill's resolved script
  path.
- The quality bootstrap repair suppresses only omitted
  `mutation_testing.commands.dry_run` and `.sample` empty-default refills. It
  preserves configured siblings and does not turn empty values into a generic
  suppression rule.
- The default miner retains its legacy handling of non-finite elapsed values;
  finite-only filtering is limited to the opt-in detail receipt.

## Claim ledger

- The local current-readable #503 cohort contains 16 entries: 12 completed and
  4 failed parent records, not 16 successful suite runs.
- This release measures 0 seconds of runtime relief. It provides a rerunnable
  decision receipt and a reopen trigger; it does not claim a faster closeout.
- #496's repair is deliberately narrow: only omitted
  `mutation_testing.commands.dry_run` and `.sample` empty-default refills are
  suppressed. It is not a general empty-value suppression, and configured
  sibling values remain meaningful.
- GitHub issues #496 and #503 remain open. No remote issue closure is claimed.

## Update and rollback

Update with `charness update`, then verify with `charness version` (expect
`3.2.0`) and `charness doctor`. To exercise the new receipt, resolve the retro
skill directory and run:

```sh
python3 "$SKILL_DIR/scripts/mine_closeout_telemetry.py" --repo-root . --detail
```

For rollback, use a source checkout at `v3.1.1`:

```sh
charness update --repo-root <v3.1.1-checkout> --no-pull --skip-cli-install
charness version --repo-root <v3.1.1-checkout>
charness doctor --repo-root <v3.1.1-checkout>
```

Remote CI, public-release visibility, and installed refresh will be recorded as
separate readbacks in the release evidence after their respective boundaries;
a local terminal green is not their substitute.
