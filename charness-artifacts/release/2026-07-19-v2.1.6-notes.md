# Charness v2.1.6

## Release scope

Release publication and linked-issue closure now have a stricter evidence order: a release is published and independently observed before any commit carrying GitHub close keywords can reach the branch. Resume recovery validates the exact carrier, evidence tree, tag, and remote identity instead of treating a terminal success as sufficient proof.

The release planner also emits a compact YAML-first evidence summary, shares one portable Git delta implementation across planning and verification, and avoids repeated inventory subprocess startup in the quality suite.

## Upgrade

Update through the normal Charness installation workflow. There is no data migration, configuration migration, or operator rollback step for this patch.

## Recovery

Most operators need no new action. A release maintainer resuming an interrupted publish uses `--resume --publish-current`. If interruption happened after an issue-closeout carrier or final evidence commit was created, repeat the exact original issue, classification, carrier-file, behavioral-evidence, repository, and critique arguments; the command now reports all missing safety inputs explicitly.

## Non-claims

Fixture evidence proves ordering, identity checks, and ambiguous-push recovery; it does not prove GitHub webhook timing. This release does not close a linked GitHub issue, so no live issue auto-close behavior is claimed.
