# Charness 6.0.0

This is a major release because a public flag surface was removed, several
validators now refuse inputs `5.2.0` accepted, and probe payloads changed shape.
A consuming repo that scripted against any of them will break on upgrade.

Read `## Breaking operator-contract changes` before running `charness update`.

## Breaking operator-contract changes

- **The `--json` COMPATIBILITY flags are removed. Functional `--json` is not.**
  What went is the no-op layer: hidden `argparse.SUPPRESS` aliases plus flags
  whose own help said "retained for parity" or "present for CLI-shape
  compatibility" on commands whose output was already JSON. One of the hidden
  aliases lived in `summary_output_lib.add_output_args`, so that removal reaches
  every `quality` script calling it at once; `inventory_adapter_gate_design.py`
  and `seed_dup_review.py` lose documented ones.
  **Measured on this tree, no repo-owned Python source declares its own
  `--json` option** — {{claim:json-declaring-scripts.count=0}}, derived from the
  block at the end of this note along with the surfaces that derivation could
  not scan. An earlier draft of these notes asserted the opposite over a
  measured `0`; that sentence is what the derived block below exists to stop.
  **Migration is `--json` -> `--detail`, and it is not a one-character edit.**
  The scripts that took `--json` do not emit a payload by default — with no
  output flag they print a human summary line, so dropping the flag replaces
  your payload with prose. This repo measured the same migration on its own
  helper: the flag, the parser, and the help text naming the removed mode are
  coupled edits, whose failure mode is a silent `JSONDecodeError` on YAML rather
  than a loud exit `2`. Pass `--detail` for the full payload or `--summary` for
  the compact one, and read it as YAML.
  **`seed_dup_review.py` is a removal, not a rename:** its structured output is
  gone with no `--detail` replacement. Parse the overlay it writes via `--output`
  instead.
  `charness <subcommand> --json` is also no longer stripped from argv and now
  exits `2`.

- **A scaffold refuses to write onto another subject's record.** `quality`,
  `debug`, `retro`, and the records-only families resolve `write_artifact_path`
  through `scripts/artifact_subject_identity.py`: a target whose subject key
  disagrees with the invocation's — or is unreadable, or was never declared —
  routes to a path that destroys nothing and reports
  `refused_write_artifact_path` with the reason. `quality` routes onto this
  review's OWN dated record, and refuses outright only when that record already
  exists; the records-only families route off an OCCUPIED path rather than off a
  disagreeing subject. **`debug` now takes `--subject`** to declare which
  investigation a run continues; a `debug` run that continues its own open
  record still succeeds unchanged. A wrapper that relied on the previous
  overwrite-in-place behavior must declare a subject or read the refusal.

- **A `## References` link in a handoff artifact must carry a descriptor on the
  link's own physical line.** `validate_handoff_artifact` refuses a list entry
  whose whole line is a bare markdown link, and a descriptor wrapped onto the
  following line is still refused. A `docs/handoff.md` that was legal in `5.2.0`
  fails on upgrade. The handoff scaffold's placeholder now emits a compliant
  stub.

- **An artifact passing through the handoff validator cannot prescribe a
  command a cost registry marks superseded.** `validate_handoff_artifact`
  refuses a body prescribing a registered dominated command and names the
  replacement — that validator is the seam, not every repo-owned document, and a new blocking
  quality gate covers the seam a document never reaches: registry-declared
  config literals and standing-gate surfaces, which is where a gate SPAWNS a
  dominated command with no document in the chain. **Both surfaces are inert
  until a consuming repo authors its own registry**, and the disclosure that
  they ship blocking is at
  `skills/public/quality/references/cost-dominance.md`, the point a consumer is
  told to author one. The registry is a denylist: an unregistered slow command
  passes, and that false-negative class is real rather than implied away.

- **The docs-graph gate judges named metrics against declared bars.**
  `check_docs_graph.py` judges every gated metric against a declared bar instead
  of a hardcoded comparison. `orphans` and `islands` keep an effective bar of
  `0`, so nothing about their threshold relaxed; `link_only_lines` joins the
  judged set against a ratcheted bar that may only decrease. A ratchet record
  whose bars RISE is DISCARDED rather than reported, and the run then falls to
  the strict default — so a consumer whose record rose sees a docs-graph failure
  with no payload key naming the record as the cause.
  **The exported gate's `link_only_lines` bar defaults to `0`**, so a consuming
  repo that inherited this repo's calibrated bar now inherits `0` and must
  express its own with `--link-only-lines-bar`. A metric added to the judged set
  without its block header, failure label, and remedy fails loudly at import
  rather than degrading to NOT-RUN.

- **The lesson ledger's score vocabulary is typed, and its schema moved from
  `4` in `5.2.0` to `6`.** The signed magnitude scalar is replaced by a typed outcome
  vocabulary in `scripts/lesson_score_outcome_lib.py`, each value routing to one
  disposition:
  `changed-an-action` graduates, `read-but-not-applied` and
  `pushed-a-wrong-action` rewrite in place, `not-consulted` strengthens binding.
  Every outcome requires an anchor; a `changed-an-action` anchor must name the
  counterfactual, and `not-consulted` requires the recording retro to already
  carry the class's recurrence tag. **Magnitude is retired from both
  vocabularies** — a legacy scalar contributes its sign, never its size.
  Committed legacy events keep their exact bytes and route to no disposition.
  Recompute rule for a ledger you migrate yourself: `score_total` is the sum of
  valences, `score_count` the event count, `outcome_counts` the per-outcome
  tally, and the validator refuses each of them if it disagrees with replay.
  **Scoring now cites the retro RECORDING the encounter**, not the lesson's
  origin retro; a writer that cited the origin is refused.

- **`session_id: "none"` is refused as a lesson-evaluation disposition** at the
  ledger write, in the disposition grammar, and in the reconciler, which
  re-derives the rule rather than trusting a parser it is reachable without. A
  void disposition can no longer raise `completed_evaluation_count`.

- **Every REQUIRED planner read must be priced.** `run_plan_envelope` gains
  `measure_read`/`measure_reads` and refuses an undisclosed `required_reads`
  entry at the shared chokepoint; `on_demand_reads` is not validated. This is BREAKING for any external planner built on the envelope:
  emitting `required_reads` without measuring them is now a refusal, and the
  hand-rolled resolvers collapsed into the shared one.

- **Release notes are a derived surface, and ungrounded quantities block a
  publish.** A repo using the `release` skill now gets
  `generate_release_notes.py` (derive the claim block from the tree, and
  re-derive it at publish), `lint_release_narrative.py` (a bare quantity — a
  digit run or a cardinal number word — outside a code span or a
  `{{claim:...}}` marker BLOCKS; the completeness words `only`, `all`, `every`,
  `none`, `still`, `repo-wide` are advisory), and a publish preflight wired on
  both the execute and resume lanes. It is armed by
  `require_derived_release_claims`, which defaults true, so DELETING the adapter
  key re-arms rather than disarms it. An existing release note with typed
  quantities will refuse a publish until it is grounded or reworded.

- **Repo-gate shell scripts refuse to run from the exported plugin copy.**
  `check-markdown.sh`, `check-shell.sh`, `check-links-internal.sh`,
  `check-secrets.sh`, `check-links-external.sh`, and `install-git-hooks.sh` exit
  `1` with a named reason when their package root is not the git root, instead
  of silently measuring a narrower tree. Set `CHARNESS_REPO_ROOT` to the source
  checkout to override the `check-*.sh` gates named here; `install-git-hooks.sh`
  deliberately has no such hatch and takes `--repo-root <git-toplevel>` instead.
  It is the one worth calling out: invoked bare from an exported copy it
  previously repointed the entire enclosing repository's `core.hooksPath` and
  disabled its real hooks.

- **Trigger probes report whether they RAN before what they found.**
  `retro/scripts/check_auto_trigger.py` and
  `prove/scripts/check_boundary_escalation.py` lead with
  `state: evaluated | not-configured | not-established`, emit `triggered` only
  when the probe actually ran, and exit `3` when the answer is undetermined. A
  caller that polled `triggered` alone was reading "could not tell" as "no";
  read `state` first, and treat exit `3` as an unanswered probe rather than a
  negative verdict.

- **The RELEASE-readiness probes stopped reporting success over an unevaluated
  run.** `check_fresh_checkout_probes.py` returned exit `0` with
  `status: configured` and `probe_results: []` when the declared probes had not
  been run — a `0` failure count from a run that executed nothing. It now
  reports `status: not_established` at **exit `3`** and omits `probe_results`
  entirely, and the release plan's gate packet passes `--run-probes` so the
  probes actually execute. A consumer whose declared probes are slow will feel
  that cost on every release plan, and a declared probe that fails now fails the
  plan. `check_real_host_proof.py` returned `required: false` over an EMPTY
  changed-path scope; it now omits the `required` key entirely in that state and
  exits `3`, so a caller cannot subscript a verdict that was never produced.
  Scripts reading either payload should read the status/scope key first and must
  tolerate the verdict key being absent.

- **The critique cross-surface probe refuses an unreadable adapter instead of
  reporting an opt-out.** A `.agents/critique-adapter.yaml` the loader rejected —
  including a slip like `boundary_cross_surface_globs: "docs/**"` where a list
  belongs, or list items written without `-` dashes — used to yield empty probe
  config, `not-configured`, and exit `0`. It now reports `not-established` at
  exit `3`. Only `[]` declares a deliberate empty probe.

- **`setup` no longer seeds an auto-retro opt-out the repo never chose.**
  `seed_retro_memory.py` used to write `auto_session_trigger_surfaces: []` and
  `auto_session_trigger_path_globs: []`, which the probe then read as a
  deliberate opt-out. Fresh adapters leave both keys unset so the probe reports
  `not-established` and names the remedy.

- **The retro lesson-evaluation floor is conditional on a declared evaluator.**
  A repo that declares no evaluator is no longer required to write a
  `not-evaluated / missing-start` disposition it had no way to avoid; the
  validator reports the floor as inert and names the opt-in command.

- **Adapter-declared retro sections that collide with a scaffold heading are
  dropped silently.** The fix for a duplicated `## Lesson Evaluation` drops ANY
  adapter-declared block whose H2 matches a scaffold-owned heading, body and
  all, with no warning. A repo whose retro adapter declares custom guidance
  under `## Waste`, `## Context`, or any other scaffold heading loses that
  guidance from the scaffold.

- **Gates that can turn a previously-green consumer red on unchanged files.**
  The quality-artifact date-coherence check, the widened
  `check_documented_command_flags` carrier scan, the docs-graph bar above, and
  the `## References` descriptor rule above all refuse inputs earlier versions
  accepted. The cost-dominance gate is NOT in this list: with no registry it
  returns unarmed and exits `0`, so only authoring a registry arms it. Several are listed under Added
  capability; for a repo that wires them, they are breaking.

No automatic migration is supplied. Run the affected commands after updating and
retain their output as the local migration record.

## Added capability

- **Defects a consuming repo actually hit are repaired.** A lesson session
  opened from an installed plugin used to fail with an instruction naming a
  `scripts/` path the consuming repo does not have, and the recovery from THAT
  failure named a `skills/public/retro/` path that exists in neither the consuming
  repo nor the export; the first message also warned that running the installed copy
  CAUSED the failure, so the only way forward was the action it warned against. Every
  command these refusals cite now resolves against the tree the reader has, and the
  foreign-copy warning fires only where that hypothesis can be true. Separately: a
  reference no longer points consumers at a link gate that refuses inside a consumer
  repo, `coverage_floor_policy.gate_script_pattern` can finally name a
  `.githooks/pre-commit` stop gate, and a repo that declares its lefthook and CI
  sub-keys absent no longer gets a `KeyError` or a false drift report.
- **Every repo-root shell gate refuses an exported copy by name.**
  `check-python-lint.sh`, `run-quality.sh` and `self-validate-install-update.sh`
  each carried a COMMENT saying they cannot run from the export and no code that
  said so to an operator; from the mirror they died naming absent directories
  rather than the reason those directories were absent, and `run-quality.sh` would
  have driven the whole standing lane against the plugin tree. The rule now has one
  home rather than a hand-copied block per gate, and a test asks it of the whole class.
- **The runtime-budget report counts the bars that cannot fail on this machine.**
  A budgeted label with no sample rendered one warning line that scrolled past
  inside a full standing-lane run and the gate never rendered the total, so "how many
  committed bars are unenforceable here" was unanswerable without reading the
  report by hand.

- **The bootstrap dependency contract now ships.** The export grew a top-level
  `packaging/` directory, so `bootstrap_runtime.py`'s `load_contract` resolves
  on a consumer machine for the first time instead of raising "missing bootstrap
  runtime contract". The documented `gather` entrypoint guards its third-party
  import and names what to install rather than dying on a bare
  `ModuleNotFoundError`, and a new detector refuses a documented entrypoint that
  imports an undeclared third-party package unguarded. Declaration is not
  availability: shipping a requirements file does not satisfy this detector.
- `scripts/what_reads_this.py` answers what reads a symbol, a path, or a config
  key, grouped by kind, and prints the surfaces it did NOT scan on every answer
  rather than only on an empty result.
- `scripts/init_lesson_ledger.py` creates a valid empty lesson ledger so a
  consuming repo can opt into the lesson lifecycle. It refuses to overwrite an
  existing ledger and refuses to wipe a committed one.
  `scripts/seed_lesson_transitions.py` makes a tagged lesson selectable, which
  is the step between "a ledger exists" and "a session is shown a lesson".
- `render_lesson_lifecycle_review` emits runnable archive, resurrect, and
  graduation-proposal commands — the production caller whose absence is why
  `state: archived` had never been written. Selection policy `v3` restores the
  archive-fallback slot that policy `v2` had pinned shut.
- **Write-capable subagent isolation is assertable.**
  `charness worktree create --path <path> --branch <branch> --prepare` asserts
  isolation as it creates, and `charness worktree doctor --require-isolation`
  refuses a shared checkout. Isolation is measured by comparing the checkout's
  `--git-dir` against the shared `--git-common-dir` — where the index actually
  is — not by comparing paths, and git discovery environment is scrubbed so a
  verdict is always about `--repo-root`.
- **A long child process has an observable lifecycle.** The standing pytest
  runner's child runs through `run_monitored_phase` in its own session, with
  SIGTERM converted so an enclosing guard reaps the process tree instead of
  orphaning it, and a run record that outlives the caller
  (`--print-last-run`).
- **Coverage instrumentation has one classifier, not a policy per builder.**
  `coverage_instrumentation_policy.classify_instrumentable_command` owns the
  decision and both builders render from it, so the standing runner is accepted
  by the changed-line gate rather than refused with "use a helper script for
  other runners". `check_changed_line_mutation_coverage.py` gains
  `--test-command`. Producer mode without producible coverage now blocks and
  records a `not_checked` proof instead of exiting green having measured
  nothing.
- **One executable guard per structural umbrella**, each with a recorded
  measurement of what it catches on this tree and a stated remainder:
  `scripts/check_closeout_classification_parity.py` judges an enumerated set of
  copies of the closeout classification vocabulary against the canonical tuple,
  all but one through the surface an operator reaches and that one as a
  module-attribute read; a further copy is held by a different gate, and the
  gate's own docstring states the split rather than claiming to hold every copy.
  `--assume-classification` turns the exact sites red without editing the tree; an emptied deterministic specdown floor
  must now name the `kind: judge` assertions that replaced it, each resolving in
  the sibling `outcome-assertions.json`.
- `check-markdown.sh` resolves markdownlint in tiers and its `npm exec` fallback
  carries `--no`, so it no longer reaches the npm registry.
- **The cost-dominance angle ships in the exported critique lineup** — "is there
  a cheaper path to the same evidence?" — alongside an exported consumer
  inventory built on the already-exported `standing_gate_discovery_lib`, so a
  consuming repo can ask whether its prescribed test command sits outside its
  own budgeted universe.
- Dated quality artifacts are checked for date coherence: a `Date:` header that
  disagrees with the date in its own filename is refused, which is the signature
  of a review overwriting the previous review in place.
- `check_documented_command_flags.py` resolves invocations in Python argv lists,
  adapter YAML command lists, surface-manifest command strings, and tests, not
  only in markdown, and reports typed skips so a pass cannot over-claim its
  coverage.
- The retro scaffold no longer emits a duplicate `## Lesson Evaluation` section
  when the repo's adapter declares the same heading, and the retro planner
  reports date-activated rules with their activation dates instead of letting an
  author discover them by tripping one.

## Known-weak surfaces shipping in this release

Stated so an upgrade is not a surprise.

- **Export completeness is only partly repaired.**
  [#634](https://github.com/corca-ai/charness/issues/634) STAYS OPEN and is
  commented with its honest score: an adversarial reviewer enumerated the
  defect class and this release closes a minority of it. The unguarded shell
  gates ARE repaired. The cwd-relative instruction sites are NOT, and neither is
  a detector for them: one was built and reverted, because it pushed a
  documentation placeholder into command fields that are EXECUTED rather
  than read, and refused correct prose telling a consumer to run their own
  script.
- **An unenforceable runtime budget is counted, not caught.**
  [#546](https://github.com/corca-ai/charness/issues/546) STAYS OPEN. Absence of
  a sample does not separate a fresh machine from a conditional gate that did not
  run from an abandoned bar, and a repair keyed on sample history was already
  built, measured defective and reverted. Reconciling budgeted labels against the
  labels a runner can actually queue is a repo-owned check this report does not
  perform, and its own advisory text says so rather than naming a gate a
  consumer's install does not contain.
- **The exported cost inventory is structurally narrower than the criterion it
  serves.** It asks the budget question only of already-registered commands,
  queue labels resolve only for wrapper-shaped runners, and the scanner
  recognises a fixed program list over a fixed set of surface kinds.
- **The exported docs-graph gate ships without the ratchet record or the test
  that ratchet it.** `--link-only-lines-bar` makes a consumer's own bar
  expressible; whether a repo-calibrated threshold should ship as a default is
  left open rather than decided.
- The `check_fresh_checkout_probes` exit-`3` repair does NOT bind on any
  production release path. Every production caller reads the payload in-process;
  exit `3` is reachable only from the CLI. What the release path gained is
  honest artifact text and probes that actually execute.
- `check_real_host_proof`'s `evaluation_scope` carries more values than the
  state contract it documents, and the config-error world still emits `required: false`
  at exit `1`. Exit `1` is loud, so it cannot be read as a verdict, but the
  key-absence guarantee holds only for the empty-scope state. Its one-line
  summary also prints `not-established` for the `empty` scope, so the text and
  payload channels spell that state differently.
- `check_fresh_checkout_probes` classifies a detached HEAD and a failed clone as
  `blocked`/exit `1` even though no probe ran. Fail-closed, so it can stop a
  release it should not; distinguishing those is deferred.
- The release plan's fresh-checkout gate packet is still labelled
  `cost_tier: cheap` although it clones the repo and runs every declared probe.
- The retro lesson-evaluation floor is conditional on a declared evaluator ONLY
  for retros under `charness-artifacts/retro/`. A repo with a different retro
  output directory keeps the old unconditional duty.
- `skills/public/setup/references/default-surfaces.md` still points consuming
  repos at an exported `check-links-internal.sh` that exits `1` when run from
  the export.
- The broad coverage gate matches the runner token anywhere while the
  classifier is start-anchored, so a wrapper-prefixed broad command is a loud
  refusal in producer mode.
- **The docs-graph ratchet is monotonic only over the rows PRESENT.** A consumer
  who REPLACES the record with a single high row is accepted, because a
  one-element list is trivially sorted. What stops that for this repo is a
  founding-row test, and tests are not exported.
- **The cost gate's exemptions are keyed to the FILE, not the line**, for
  standing-gate findings, so exempting one command in a file exempts the file's
  other findings of that kind. Its discovery reader is a line scanner with no
  heredoc or reachability awareness, so it can report a command that never
  runs.
- The narrative lint's blocking arm covers cardinal number words and digit runs.
  `one`, `both`, `half`, and `couple` are deliberately absent because their
  structural English use is not separable by regex, so a note asserting "one
  script declares it" passes the blocking arm.

## Update and recovery

Run `charness update`, then restart Codex or Claude Code as directed by the
updater. Verify the refreshed install with `charness doctor`.

There is no version-selecting updater rollback command. To return to `5.2.0`,
reinstall or pin the prior `v5.2.0` release using the host's supported plugin
mechanism, restart the host, and rerun `charness doctor`. If that host-specific
recovery is unavailable, use the repository issue path rather than mixing an old
install with new closeout artifacts.

## Evidence limits

- The removed `--json` surfaces were enumerated from the commit that deleted
  them and from a sweep of this tree, and the surviving count is derived below
  rather than typed. Whether any consuming repo scripted against them is not
  observable from here, which is why the migration is stated rather than assumed
  to be unnecessary.
- The derived block proves *notes agree with derivation* for the surfaces
  somebody registered. It does not prove *derivation agrees with truth*, and it
  cannot see a claim in this prose that no registered surface covers. Most
  sentences above are in that category.
- Public release visibility and installed-host readback are verified only after
  the release has been published, through their distinct channels.
