# Charness v1.0.1

Charness v1.0.1 fixes a one-way migration gap found during the installed-machine
readback of v1.0.0. Pre-v1 installations could retain a deleted
`*:find_skills_routing` ownership key in the host-hook state ledger even after
their settings had moved to the canonical session-routing hook.

## What Changed

- Session-routing install and uninstall now remove the retired state-ledger key
  for both Claude Code and Codex.
- Cleanup is deletion-only: it does not accept retired adapter keys, restore the
  removed `find-skills` workflow, or add a compatibility alias.
- Canonical session-routing ownership and unrelated foreign ledger entries are
  preserved.
- Regression tests cover both hosts across install and uninstall, including the
  state-only residue that escaped the v1.0.0 release gates.

## Migration

Run:

```bash
charness update
```

Then restart active Claude Code and Codex sessions and verify:

```bash
charness doctor
charness --version
charness session-capture status
```

No retired configuration names or APIs are restored by this patch. The v1.0.0
breaking-change migration remains in effect.

## Verification

- Focused host-hook reconciliation tests passed for both hosts and operations.
- Source and packaged-plugin hook implementations are identical.
- The installed final-consumer status returned `in_sync: true` with no drift or
  dangling hook references after the cleanup.
- Fresh-eye review confirmed the deletion boundary and preservation of canonical
  and foreign state.

## Rollback

Reinstall v1.0.0 to roll back the code. A retired ledger key already removed by
v1.0.1 is not recreated; restoring it is neither required nor supported.
