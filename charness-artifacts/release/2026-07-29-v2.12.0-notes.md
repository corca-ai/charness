# charness 2.12.0

Two escapes closed at the two places this harness renders a verdict: the release
publish boundary, and the quality runner's own summary line.

Both were found by measuring, not by review. A multi-lens audit of the previous
week's commits reported that five of the last twelve releases had published a
one-line body — and one of those was the release whose notes corrected an earlier
release's wrong migration instruction. Separately, this repo's changed-line gate
printed `PASS` beside its own warning that the run had proven nothing, and two
dead guards nearly shipped behind it.

## Added

- **`UNPROVEN` — a third gate status in `run-quality.sh`.** A gate that ran and
  established nothing now exits 3, renders `UNPROVEN`, is counted in neither the
  passed nor the failed column, and does not fail the run. The summary line reads
  `81 passed, 0 failed, 1 UNPROVEN (ran, established nothing)`.

  "Does not fail the run" is the mid-work path. Under the pre-push hook the same
  condition still returns 1 and stops the push — see Upgrading.

  It is **opt-in per label** (`UNESTABLISHED_CAPABLE_LABELS`), and that is the
  whole design rather than a detail. Exit 3 is not a runner's byte to redefine:
  measured on the development machine, `pytest` exits 3 on `INTERNAL_ERROR` — a
  crashed conftest or plugin, i.e. a suite that never ran — and `shellcheck` exits
  3 on a bad invocation. A global reinterpretation would have silently stopped
  gating on both. A gate joins the allowlist only after its own exit contract has
  been read.

  The shipped file arrives with `check-changed-line-mutation-coverage` **already
  enrolled**. If you vendor `scripts/run-quality.sh` from this release you get that
  gate's new rendering without doing anything; only a hand-merged diff that leaves
  the constant empty is inert.

- **Publish refuses to ship notes it was not given.** When notes are already
  drafted for the target tag in the release `output_dir` and publish is invoked
  without `--notes-file` — or with a *different* file — it now blocks and names
  every candidate.

  It is silent in three cases, not one: no draft for the tag, an unreadable or
  absent `output_dir` (a fail-open the arm cannot distinguish from the first), and
  a draft whose filename does not contain `notes` — `2026-07-29-v1.2.3-release.md`
  is invisible to it.

## Fixed

- **The published-body audit no longer calls an unauthored release `clean`.** It
  looked only for mutable source-tree pointers, so a body with no content had none
  and was certified. A body that is only the generated `**Full Changelog**` line is
  recorded `unauthored` now, with `gh release edit` named as the remedy. Advisory
  by construction — the release already exists by then — and host-agnostic: an
  earlier pass pinned the boilerplate shape to GitHub's own `compare`/`commits`
  URL, which sent every other host's empty body back to `clean`.

  Narrow on purpose: an auto-generated `## What's Changed` PR list is still
  `clean`, **including one with no items under it**. Calling that unauthored is a
  judgment the consuming repo owns, and the residual hole is left visible rather
  than closed by guess.
- **`VAR=1 ./scripts/run-x.sh` is a command, not an assignment.** The standing-gate
  discovery library matched the leading `VAR=` and dropped the whole line, so a
  runner invoked with an env prefix became invisible and the surface it references
  was never discovered at all.
- **The runtime recorder accepts every status the runner emits.** It rejected the
  new one at the door, dropping the sample and printing `failed to record phase
  runtimes` — a telemetry hole in exactly the gates the status exists for.
- **The aggregate telemetry no longer records `pass` for an all-`UNPROVEN` run.**
  The console said `UNPROVEN`; the durable artifact that later readers quote said
  `pass`.

## Changed

- The changed-line mutation lane has a runtime budget for the first time, sized
  from its RANGE cost rather than from a worst observed run. The producer's own
  measurement block records ~4min for a nine-commit session (31 pool files, 1009
  tests); the bar is 300000ms, i.e. 1.25x that, and ~24s is the common one-commit
  case. The repo's own `--suggest-budgets` proposed a bar
  1.4× an outlier produced by a six-commit unpushed range; taking it would have
  made a transient `base..HEAD` distance the permanent bar. The `run-quality-full`
  aggregate was re-based from 62000 to 420000 for the same reason — it had
  contradicted the lane since the lane went blocking, and the observed median of
  182923ms already exceeded it.

  That aggregate is now ~2.3x its observed median, which is looser than the ~1.4x
  this repo draws bars at, and `BUDGET_SLACK_FACTOR` is 3.0 — so the advisory built
  to flag a bar that cannot fail will not flag this one. Stated rather than left
  for the advisory to miss.

- **The push-time refusal moved from `--read-only` to the hook.** It is keyed on
  `CHARNESS_PRE_PUSH=1` now, which `.githooks/pre-push` sets. `--read-only` means
  "skip phases that mutate tracked artifacts" and is the published mid-work
  command; overloading it as "a push is imminent" made an ordinary mid-work run
  over one uncommitted mutation-pool file fail with "refusing at push time" and no
  push in flight. **If you invoke `--read-only` from your own push automation, set
  `CHARNESS_PRE_PUSH=1` or the refusal silently stops firing.**

## Known limits

Stated because a release note that only lists wins is the same over-claim these
changes exist to remove.

- **The five one-line release bodies are not backfilled.** The recurrence path is
  shut; the damage is not repaired. An earlier release's wrong migration
  instruction still stands uncorrected on the public releases. This was the
  maintainer's explicit decision, not an oversight.
- **A publish with no drafted notes on disk is still allowed.** Requiring notes to
  exist at all is a contract change for consuming repos. That case is *recorded*
  as `unauthored` in the durable artifact; it is not refused.
- **A CI range containing no eligible mutation-pool file is still a citable
  green.** `check_mutation_run_proof` marks a changed-line claim provable on the
  presence of a base SHA alone, without asking whether the range held anything to
  judge. Open, and named in the critique rather than left to be rediscovered.
- **The contamination signal under-approximates.** An explicit non-`HEAD`
  `--head-sha` over a dirty worktree, a git failure read as "nothing found", and
  dirty non-pool files that change what the focused coverage measures are all
  states where a run establishes nothing and does not say so. Pre-existing, but
  exit-code semantics are load-bearing now, which raises its cost.
- **A changed set that is EMPTY still prints `PASS`, not `UNPROVEN`.** Nothing was
  in scope, which is honestly nothing to prove — but it is the case an operator
  sees most often, and it is one surface below the `check_mutation_run_proof` gap
  above.
- **The hook/runner coupling is pinned by nothing.** An old vendored
  `.githooks/pre-push` with this release's runner means the push-time refusal never
  fires, silently, with a green console — the same shape this release exists to
  close, in the wiring of the fix. `.githooks/pre-push` is repo-local and is not
  exported in the plugin, so the push-time arm reaches a consuming repo only if
  that repo wires the variable itself.
- **The push-time refusal is unit-pinned at the wrapper, not exercised live.** No
  real push has run `--refuse-unestablished` end to end.

## Upgrading

**Two shapes now stop where they used to proceed.** Both recover with one existing
flag; neither is a rename, a removal, or a data migration, which is why this is a
minor and not a major. Saying "no action required" would be the hidden default
this repo's own version policy forbids.

- **A publish that drafts per-tag notes and takes `--generate-notes` now fails.**
  Pass `--notes-file <the draft>`, or rename/delete the draft AND COMMIT that —
  publish refuses a dirty worktree, so an uncommitted deletion trades one refusal
  for another.
- **A push whose mutation pool has uncommitted changes is refused at the hook.**
  This behavior is not new; what changed is that it keys on `CHARNESS_PRE_PUSH=1`
  instead of `--read-only`. Commit the pool files and re-run. If your own push
  automation calls `--read-only` directly, set `CHARNESS_PRE_PUSH=1` — otherwise
  you keep pushing, and you keep pushing *without* the check.

The `UNPROVEN` status itself needs no action, but see the enrollment note under
Added if you vendor `scripts/run-quality.sh`.
