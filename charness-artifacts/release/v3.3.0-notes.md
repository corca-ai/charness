# Charness 3.3.0

## Operator outcome

This release adds workflow-owned, offline proof utilities for maintainers and
operators who need to preserve a post-push evidence boundary. The additions
help detect stale implementation premises, validate captured slice identity,
plan a reproducible final proof bundle, and reconcile captured publish state.

These are repository workflow helpers, not new top-level `charness` commands.
No migration is required for existing callers.

## Highlights

- `scripts/check_premise_preflight.py` detects stale, duplicate, already-shipped,
  and partial-repair premises. A valid invocation records a durable decision,
  including a refusal; this write is intentional and should be treated as
  workflow state.
- `scripts/validate_slice_manifest.py` validates a captured target SHA, CI and
  issue observations, reader-root/parity identity, and source/plugin ownership
  for a declared slice.
- `scripts/final_bundle_preflight.py` produces a reviewable sync, behavior,
  verification, and closeout command plan and refuses missing or unbound proof
  inputs before broad execution.
- `scripts/publish_state_ledger.py` reconciles the immutable captured publish
  snapshot with source-owned goal and handoff claims without refreshing a
  provider or making an external write.

Supported examples from a source checkout:

```sh
python3 scripts/check_premise_preflight.py --help
python3 scripts/validate_slice_manifest.py --repo-root . \
  --manifest charness-artifacts/goals/2026-08-06-post-push-baseline.slice-manifest.json --json
python3 scripts/final_bundle_preflight.py --repo-root . \
  --manifest charness-artifacts/goals/2026-08-06-post-push-baseline.slice-manifest.json \
  --critique-path charness-artifacts/critique/release-3-3-0-prepublish.md \
  --behavior-channel 'behavior=python3 -m pytest -q tests/quality_gates/test_publish_state_ledger.py' --json
python3 scripts/publish_state_ledger.py --repo-root . --json
```

## Compatibility and proof boundary

- No existing top-level CLI invocation, install surface, or runtime budget is
  changed.
- The helpers report captured/offline evidence; they do not establish current
  provider freshness, installed-host behavior, or public release visibility.
- The controlled runtime A/B evidence remains advisory and does not justify a
  budget or scheduler change.
- Pre-release local evidence was 87 quality checks with 0 failures and 95
  focused neighboring tests. These figures are local candidate evidence, not a
  substitute for the post-publish CI and public readbacks recorded separately
  by the release artifact.

## Update and rollback

Update with:

```sh
charness update
charness version   # expect 3.3.0 after publication
charness doctor
```

For rollback, use a source checkout at `v3.2.0`:

```sh
charness update --repo-root <v3.2.0-checkout> --no-pull --skip-cli-install
charness version --repo-root <v3.2.0-checkout>
charness doctor --repo-root <v3.2.0-checkout>
```

Release-specific public visibility, remote CI, installed refresh, and baton
reconciliation are verified through their distinct post-publication channels;
the release helper's local green state is not their substitute.
