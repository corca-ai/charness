# Charness 5.1.0

Charness 5.1.0 makes its quality and issue workflows more honest for operators:
the installed plugin now preserves more evidence at the boundaries where a
passing local command could otherwise overstate what it proved.

## Highlights

- Standing-test economics now reports conservative subprocess-settlement
  signals in detail output. Literal deadlines and output capture are shown only
  when the static callsite proves them; dynamic lifecycle and process-tree facts
  remain explicitly unknown.
- Issue creation can return a typed, target-bound `verify-create` action, and
  closeout target disagreement is refused before a backend mutation.
- Quality and handoff planners disclose measured required-read size or a typed
  unavailable reason. SessionStart routing now finds configured handoff state
  from nested working directories.
- Public-skill validation reports a missing consumer policy as typed
  not-applicable state while retaining malformed or non-file policy errors.
- README proof evidence and baseline regeneration checks now refuse the
  previously unvalidated or ambiguous inputs they inspect.

## Upgrade

Run `charness update`, then restart Codex or Claude Code so the refreshed plugin
is loaded. If update fails, the plugin is unavailable after restart, or drift
persists, run `charness doctor` and follow its `next_action`; then rerun
`charness update` and restart the host. There is no supported version-pinned
rollback procedure for this compatible minor release.

## Release Boundary

The 22-issue opening cohort remains deliberately OPEN with its existing tracker
carriers. This release does not close those issues and does not by itself prove
hosted CI, provider behavior, or every consumer installation. The complete
per-issue disposition map is the committed
[execution ledger](https://github.com/corca-ai/charness/blob/v5.1.0/charness-artifacts/goals/2026-08-12-open-backlog-execution-ledger.md),
whose entries link to the corresponding GitHub carriers.
