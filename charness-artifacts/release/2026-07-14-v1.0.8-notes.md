# Charness v1.0.8

This patch aligns Charness's Codex MultiAgent V2 subagent defaults with the
current requested profile and makes that policy consistently visible in setup
output, adapters, and drift diagnostics.

## What changed

- When Codex exposes per-subagent controls, Charness now requests
  `gpt-5.6-terra` with `medium` reasoning effort for its coding, review, and
  dynamic-workflow subagents.
- In Codex MultiAgent V2, those caller-provided model and reasoning overrides
  use `fork_turns: "none"` by default. The full-history default
  `fork_turns: "all"` rejects those overrides; a consciously bounded
  parent-history count remains available when the assignment needs it.
- Generated and normalized `AGENTS.md` guidance retains the standing request
  to use dynamic workflows when the agent judges their benefit earns the cost.
  Setup also reports drift when a Charness-managed Codex profile differs from
  the default, without rewriting existing user instructions.
- Critique adapters now carry the context-fork field and document that a role
  can still override caller-selected model or effort unless its mapping
  preserves them.

## Verification boundary

These are requested spawn fields, not proof that a host or provider applied
the resolved model or reasoning effort. Charness records application only when
the host confirms it. The release does not add provider-side telemetry or
change an existing host's role mappings.

## Update, verify, and roll back

1. Run `charness update`.
2. Start a new Codex session (or restart Claude Code) so it loads the refreshed
   plugin cache and skill paths.
3. Run `charness --version` and `charness doctor` to confirm the updated local
   install surface is healthy.
4. If this default policy is unsuitable for your environment, reinstall
   Charness v1.0.7 through the same install path, then restart the host session.
   No data migration is required.
