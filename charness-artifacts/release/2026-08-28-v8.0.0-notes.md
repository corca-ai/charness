# Charness 8.0.0 — less friction, faster correct work

Charness now has one job: help a capable agent finish correct work faster while
reducing rework. This major release removes compatibility layers, duplicate
workflow ownership, and proof ceremony that had started to slow development.

## What changed

### One bounded task path

- `charness task run` now owns one complete isolated lane: clean-parent
  preflight, named worktree creation, external runtime/cache roots, Luna
  execution, terminal result delivery, and separate tracked, untracked, and
  ignored-residue verdicts.
- The model is fixed to `gpt-5.6-luna`. The orchestrator chooses one of
  `--effort medium`, `--effort xhigh`, or `--effort max`.
- `--scope` accepts repository-relative paths and quoted globs. `**` covers the
  Git candidate universe without mixing ignored virtual environments or cache
  symlinks into the candidate verdict.
- `charness task status` reads the external result store. It does not create a
  repo-local scheduler or infer parent state.

### Compatibility task lifecycle removed

The canonical commands are now:

```bash
charness task run --repo-root <repo> --lane <lane> --scope '<glob>' \
  --prompt '<bounded task>' --effort <medium|xhigh|max>
charness task status --repo-root <repo> [<task-id>]
```

The parent-level `charness task --repo-root <repo> ...` spelling,
model/`--codex`/`--codex-arg` overrides, and repo-local
claim/submit/review/abort task-envelope commands and state are intentionally
unsupported. There is no compatibility alias, shim, or automatic state
migration.

### Workflow ownership is smaller

- `achieve` owns active Goal Run planning, parent/cursor navigation, and lesson
  selection. Routine pickup reads the current child instead of the full graph.
- The standalone handoff skill/file, SessionStart and compact-context hooks,
  progress mirrors, lesson-session receipts, retro continuity ceremony, and
  Cautilus integration are removed.
- Release no longer emits automatic retro documents. The generated release
  retros and the signature/weighting code needed to suppress their boilerplate
  are deleted; the lesson projection now ranks only durable source observations.
- The lesson ledger remains optional durable memory; its selection projection
  is read by `achieve`, not injected through a global hook.
- Critique defaults to a pair of materially different reviewers in parallel.
  The parent integrates and counterweights their findings. Ordinary reversible
  implementation does not pay a fresh-eye or closeout-artifact tax.
- A review does not open automatic round-after-round critique. A narrow follow-up
  is owed only when repairing a real blocker materially changes the proof or
  verdict risk.
- The closeout floor-by-classification-by-carrier matrix is removed. Each floor
  keeps focused behavioral tests, while one classification-parity check protects
  the remaining shared vocabulary without replaying every carrier combination.

### Quality and release fail faster

- Ordinary implementation uses focused tests and the small core lane.
- Release pytest runs first and stops the release before later broad checks on
  failure.
- Export/layout validation runs at the release boundary after canonical source
  is stable. Checked-in plugin files remain generated output, not a second
  authoring surface.
- Changed-line mutation coverage runs once, last, in the release lane after all
  cheaper checks pass. It does not run during ordinary implementation. Broader
  mutation tooling remains explicit and opt-in.

### Documentation has one entry path

The normal discovery path is `AGENTS.md` → `docs/index.md` → the page that owns
the question. Compatibility pointer pages and retired task-envelope prose are
deleted rather than kept as aliases.

## What you need to do

1. Run `charness update` to install the latest release.
2. Confirm `charness version` reports `8.0.0`, then run `charness doctor`.
3. Restart the Codex or Claude session so the refreshed plugin cache is loaded.
4. Remove local wrappers or automation that use the old parent-level task
   spelling, task-envelope lifecycle commands, Charness SessionStart hooks,
   the handoff skill/file, or Charness-owned Cautilus surfaces.
5. Keep consumer wrappers for behavior that the host spawn API or
   `charness task run` does not provide. Charness does not edit consumer
   repositories automatically.

## Rollback

Reinstall or pin `v7.0.0` through the host's normal plugin-install mechanism,
then restart the host session. Old repo-local task-envelope state is not read by
v8; keep a separate copy if you intentionally roll back.

## Boundaries and non-claims

- Charness-owned task and quality commands isolate cache and temporary output.
  Arbitrary direct `python`, `pytest`, or `ruff` commands are not guaranteed to
  be cache-free; their ignored residue is reported separately from Git dirty
  state.
- This release does not delete consumer-repository wrappers, implement a hosted
  scheduler, or migrate old repo-local task-envelope state.
- Public GitHub installation across Claude/Codex hosts remains a testable
  hypothesis rather than a universal guarantee.
