# Charness 5.0.1

## Quality and closeout repairs

- Quality planning now reports a typed adapter-owned gap when a valid quality
  adapter declares its own command. It does not suggest a missing generic
  runner, and it does not claim to execute the adapter command.
- Direct and environment-prefixed Charness `./scripts/run-quality.sh` CI forms
  are now recognised for canonical-gate parity checks and can therefore produce
  parity findings. Repositories without that runner remain advisory unless they
  explicitly opt into refusal with `--require-canonical-gate-match`.
- The shipped issue-adapter `create` example no longer includes an invalid
  `reason` placeholder.
- Consolidated-closeout drafting now matches the actual preflight rules, and a
  HOTL disposition is bound to the issue being closed rather than an unrelated
  issue number quoted in its evidence.

## Update

No migration is required. Run `charness update`, restart Codex or Claude Code
as directed by the updater, then verify the refreshed install with
`charness doctor`.

## Evidence limits

- This release records local validation and package parity; it does not claim
  hosted CI, external consumer execution, or provider-backed issue-adapter
  behavior.
- The listed GitHub issues are not closed by this release alone. Each requires
  its own post-publication closeout and tracker readback.
