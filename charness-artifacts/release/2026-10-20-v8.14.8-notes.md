# Charness v8.14.8

## What changed

- `charness task run` steer resume keeps the Codex model and reasoning effort the lane was started with, instead of falling back to defaults on resume.
- A critique review run from a linked worktree now copies its finalized packet and attempt carriers into the primary worktree before scratch cleanup, so they outlive the linked worktree.
- `debug` no longer lets a resolved, unrelated prior debug record force every later run into a spec handoff. A resolved record the run does not continue is read as prior memory, even when its handoff is invalid. A forced-risk record that is unresolved or has an unknown resolution still forces the interrupt route, and a malformed risk declaration routes to repair, or keeps the interrupt when a forced risk class is still readable.
- The `task run` implementation-lane pre-edit stop is narrowed to premises that investigation has demonstrably contradicted. Unvalidated premises or large work are reasons to investigate or bound the claim, and multi-item work blocks only the contradicted items.

## Known issue

Under Node `v24.14.1`, the Node mutation-reporter tests in `tests/quality_gates/test_mutation_test_reporters.py` fail because the mutation baseline reader refuses output from the `spec` reporter, which a plain `node --test` produced there. A focused run of that file with that Node first on `PATH` failed, and the same file passed with an older Node major first on `PATH`; no log was retained. No file in this release touches the mutation reporters, so the failure is not a regression from it. Run the quality lane with an older Node major first on `PATH` until the reader is adapted.

## Update

Run `charness update`, then use `charness version` to read back the installed version. No migration is required.
