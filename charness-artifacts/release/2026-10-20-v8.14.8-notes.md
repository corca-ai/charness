# Charness v8.14.8

## What changed

- `charness task run` steer resume keeps the Codex model and reasoning effort the lane was started with, instead of falling back to defaults on resume.
- Critique review carriers linked from a worktree are preserved when the review result is promoted into the primary worktree.
- `debug` no longer lets a resolved, unrelated prior debug record force every later run into a spec handoff. A resolved record the run does not continue is read as prior memory; unresolved or unparseable records still force the interrupt route.
- The `task run` implementation-lane pre-edit stop is narrowed to premises that investigation has demonstrably contradicted. Unvalidated premises or large work are reasons to investigate or bound the claim, and multi-item work blocks only the contradicted items.

## Known issue

Under the newest Node line, the Node mutation-reporter tests in `tests/quality_gates/test_mutation_test_reporters.py` fail because the default `node --test` reporter there is `spec`, which the mutation baseline reader refuses. The failure predates this release and is unrelated to it. Run the quality lane with an older Node major first on `PATH` until the reader is adapted.

## Update

Run `charness update`, then use `charness version` to read back the installed version. No migration is required.
