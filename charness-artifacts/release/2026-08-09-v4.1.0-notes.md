# Charness 4.1.0

## Operator outcome

This minor release makes Charness more explicit about what its proof surfaces
actually observed. Quality declarations now distinguish declared, routed,
not-run, partial, and unreachable state; long quality runs expose progress and
retain actionable failure ownership; mutation and test helpers recover or
refuse instead of turning interruption, ignored files, or leaked processes into
misleading verdicts.

No top-level `charness` command migration is required.

## Highlights

- Quality planning renders declaration lifecycle rows, exact command packets,
  gaps, and execution state. Dotted deliberate-absence values remain absent,
  dead-code scope uses the same roots for Python and non-Python discovery, and
  ignored or escaping declared skill paths cannot earn `resolved`.
- Mutation sweeps journal pristine bytes before replacement, recover safely
  after termination, and refuse live-writer, changed-target, or leaked-child
  ambiguity. Changed-line test selection recognizes the repository's bounded
  dynamic loader forms instead of leaving the hosted coverage range unmapped.
- CLI drain tests own escaped grandchildren and test deadlines; synthetic
  test-economics fixtures own their pytest temp root; SLOC inventory excludes
  runtime `.charness` state, removes only its exact resolved output report, and
  converges across repeated runs.
- Setup inspection reports the static state of consumer Lefthook failure
  visibility without claiming a live pass. Complex shell constructs stop at
  manual reconciliation, while simple redirection gaps remain actionable.
- Regenerable-facts defaults no longer sweep arbitrary historical `docs/**`
  content as current state. Unconfigured docs are reported as not configured,
  while explicitly declared current-doc scopes remain enforceable.
- Adapter version refusal now reaches catalog, setup, handoff, bootstrap, and
  issue consumers. Provider-private rendered media is refused before an
  external issue write unless it has durable evidence.
- The always-loaded root instructions are smaller and route detailed contracts
  to their owners while preserving the full delegated-review authorization
  block. Documentation graph checks keep every current page reachable.

## Compatibility and deprecation

- The title/slug overlap heuristic is no longer part of quality, pre-push,
  staged-plan, or public-skill guidance. Existing direct
  `check_title_slug_drift.py` callers remain compatible in 4.x: advisory and
  strict exit behavior, legacy `checked`/`drift` JSON fields, and all four
  installed paths are retained with a deprecation notice. Its corrected default
  scope includes `charness-artifacts/goals`. Complete command removal is reserved
  for a future major release.
- Direct callers should remove this advisory checker from automation;
  rename-heavy work now uses the critique `Title-Slug Coherence Review`.
- Consumer-repo adapter unknown-key reconciliation remains explicitly
  unestablished when the installed reader corpus is unavailable. This release
  does not claim those keys were validated; issue #576 retains the design choice.
- Cautilus evaluation was not run for this release. Deterministic skill,
  packaging, dogfood, and fresh-checkout validation own the local evidence.

## Proof boundary

Focused local regressions and declared fresh-checkout probes passed on the
pre-version-bump tree. The 4.1.0 version surfaces are synchronized; the final
verification lock has not yet run. The recorded real-host trigger evaluation covers
`v4.0.0..f62e283f` and returned `required: false`; the final candidate range
still requires evaluation. These facts do not establish hosted CI, public

linked issue closure; those are read back in their own publication phases.

## Update and rollback

Update normally after publication:

```sh
charness update
charness version   # expect 4.1.0 after publication
charness doctor
```

To roll back the plugin/workflow surface, use a source checkout at `v4.0.0`:

```sh
charness update --repo-root <v4.0.0-checkout> --no-pull --skip-cli-install
charness version --repo-root <v4.0.0-checkout>
charness doctor --repo-root <v4.0.0-checkout>
```

Because this rollback uses `--skip-cli-install`, it does not downgrade an
already installed managed CLI. A full managed-CLI rollback remains outside this
release's local proof and requires the repository's supported installation
procedure.
