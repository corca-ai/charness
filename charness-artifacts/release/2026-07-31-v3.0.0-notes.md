# charness v3.0.0

47 commits since `v2.12.0`. This release adds no new skills and renames nothing.
It is a major bump because several proof surfaces that used to pass input they
had not established now refuse it, and one of those refusals changes an exit
code a CI job may already be branching on. **If you consume charness in another
repo, read the Migration section before upgrading.**

## Why major

The version policy reserves `major` for changed invocation expectations that
break existing automation and for forced migration steps. One item here meets
both: the portable changed-line coverage gate used to exit **0** when the
analyzed head was not the checked-out `HEAD` — a silent green over a scope it
had not established. It now exits **3**. Nothing else in the delta forces an
edit, but this one does, so the whole release carries the louder signal.

## Migration

- **`check_changed_line_coverage.py` on a `pull_request` event.**
  `actions/checkout` checks out the merge ref, so `HEAD` is the merge commit,
  not `github.event.pull_request.head.sha`. If you pin `--head-sha` to the PR
  head sha, this gate now returns exit 3 on every run. **Pass only
  `--base-sha` and leave the head defaulted.** Exit 3 means "ran, could not
  judge" and carries `ok: true`; it is not a coverage failure, but it is
  nonzero, and most CI will treat it as one.
- **`## Delegated Review` in a quality artifact.** An `executed` status must now
  substantiate itself: name the review channel that ran (reviewer, bounded
  subagent, critique angle, counterweight), the disposition it returned
  (findings, verdict, what it confirmed or refuted), or cite the path of the
  record it wrote. A section reading `- status: executed.` and nothing more is
  refused, as is an `executed` status that also states no reviewer ran. If your
  quality adapter's `language:` is not English, cite the review record's path —
  every other marker is an English word.
- **Closeout evidence binding.** Evidence now binds to the closeout's own
  context inside `check()` rather than only where a caller remembered to ask,
  so an unrelated artifact no longer satisfies an issue, goal, or release
  closeout. A closeout that used to pass on a stale neighbouring file will now
  refuse until the evidence names its context.
- **The release publish gate binds the standalone critique to the version being
  published.** A critique artifact for a different release no longer satisfies
  it.

## Also in this release

- The mutation-testing CI lane no longer aborts its coverage baseline on
  ambient CI-runner state; two tests were reading the runner's environment.
- The changed-line gate's env-shape false negative is fixed, and its
  could-not-look arms are covered rather than silently lenient.
- Fenced examples and empty globs no longer stand in for real matches in the
  prescribed-skill checks; a fence-masking repair that hid real sections was
  itself caught and repaired.
- `quality`, `issue`, `achieve`, `debug`, and `release` helper scripts picked up
  narrower verdicts, clearer refusal messages, and per-surface preflights.

## What this release does not prove

- **The delegated-review floor reads only the artifact — the same channel the
  author wrote.** It proves the section names an unnegated English review word
  or cites a path-shaped token whose existence is never checked. It does not
  prove that a reviewer ran, that a different agent context read the work, or
  that the findings recorded are the findings returned.
- That floor was measured against 71 checked-in sections in this repo and one
  constructed non-English section. **No consuming repo was exercised.**
- **Critique binding is token containment, not a shape check.** A four-byte file
  containing only the version string still satisfies the release publish gate;
  that residual is open and tracked.
- **CalVer and two-component versions degrade the binding.** A version like
  `2026.07.31` boundary-matches any artifact's `Date:` header, and `1.2` binds
  prose such as "section 1.2" — while the report still says
  `binding_checked: true`. A pre-release such as `2.12.0-rc.1` contains letters
  and falls back to substring containment. If you version that way, treat the
  release critique binding as near-presence-only.
- The exported `run-quality.sh` maps this gate's exit 3 to FAIL for labels it
  does not allowlist, so wiring the portable gate into that runner reproduces
  the could-not-judge-as-red conflation exit 3 exists to end.
- The quality review artifact shipped in this repo is dated 2026-07-25 and does
  not cover the surfaces this release changes.

## Upgrading

Run the repo-owned update command for charness to install the latest published
release, then re-run your quality gates and read any new refusal message before
changing a gate configuration to silence it.
