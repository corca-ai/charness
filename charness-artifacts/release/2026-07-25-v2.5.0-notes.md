## What changed

Three places where a machine treated its own single evidence channel as proof at
an irreversible boundary, plus a class of gate that could no longer fail.

**The mutation-testing workflow no longer closes GitHub issues.** Previously a
scheduled green closed the auto-filed mutation issue with
`state_reason: 'completed'`, selecting it with a `label + in:title` search that
never read the marker the workflow's own open step writes. Two escapes: `in:title`
is GitHub full-text, so a *human-filed* issue sharing those words could be closed
by machine; and the sample seed rotates per run, so the closing green generally
mutated a different file population than the run that filed the issue. It now
posts a recovery **candidate** comment carrying the run URL, sha, mode and the
green run's sample manifest, applies the label `mutation-recovered-candidate`, and
stops. The close is a human's call. Both the open and recovery paths now select on
the workflow's own marker and list issues by label instead of searching.

**The issue-closeout HOTL disposition floor stopped accepting its own negation.**
It matched the typed status vocabulary with an unanchored search, so `not
verified` and `could not be verified; no readback available` satisfied the floor
that gates issue closeout — it accepted exactly the undispositioned entries it
exists to refuse. The recognizer is now anchored to the value's leading token. The
same floor was never composed into `close-with-comment`, the one carrier that
mutates GitHub directly; it is now wired in.

**Runtime budgets can now report that they have gone slack.** A budget only ever
moved one way: a violation forced a raise, and nothing reported when the raise had
stopped being needed. `check-coverage` sat at 55000ms against a 7835ms worst run,
and `pytest` had drifted *above* the slower aarch64 profile's budget.
`check_runtime_budget` now emits a `SLACK` advisory naming budgets far under their
worst recent run.

Also: stale contract prose deleted — a rule that told agents to re-baseline the
duplicate ratchet in a way that silently accepts unreviewed families, a workflow
count that had been false since June, and a shipped reference pinning the wrong
`SKILL.md` line cap. `create-skill`'s `## Rules` block was a 46-line index
restating five references the body never triggered; each reference is now cited at
the workflow step where it applies.

## Upgrading

**Read this if you use the mutation-testing workflow.**

An upgrade does **not** update your installed `.github/workflows/mutation-tests.yml`,
and there is no re-render command. `propose_mutation_testing.py --execute` acts
only when the `mutation_testing` block is *missing*, and even then refuses to
overwrite an existing workflow file. To adopt the change, copy
`skills/public/quality/scripts/templates/mutation-tests.yml` over your installed
copy by hand. (A previous version of the reference told you to re-run `--execute`;
that instruction was wrong and is corrected in this release.)

Once adopted, a repo that relied on auto-close will accumulate open mutation
issues until a human closes them. `mutation-recovered-candidate` is a fixed label
name, not an adapter slot — relevant if you key automation on labels.

If you have ever rotated `mutation_testing.auto_issue.marker_token`, note that
both paths now select on the marker: issues filed under an old token become
invisible to the workflow, which will file a duplicate rather than update them.
Close the orphans by hand.

**Two changes can newly fail on upgrade, both intentional:**

- `mutation_testing.auto_issue.label` containing a comma is now an adapter
  validation **error**. The REST `labels` parameter reads commas as an AND-filter,
  so such a label can never be listed back — the workflow would silently file a
  duplicate every run and never annotate a recovery candidate.
- Issue-closeout carriers whose `HOTL` entry only *mentions* a typed status
  (rather than leading with one) are now refused, including at
  `close-with-comment`.

## Why minor

`version-policy.md` asks for the lightest honest bump and for the rationale when
the level is debatable. This one is. Not **major**: no major criterion is met —
the install surface (propose script, adapter block, `workflow_path`) is unchanged,
and because an installed workflow is never re-rendered, the template change
reaches zero existing installs; only fresh installs, which never had the old
behavior. Not **patch**: a new public label surface, a new candidate-comment
surface, and a new advisory output ship.

## What this release does not prove

- **No `actions/github-script` line in this release has ever executed.** No local
  gate runs it; the invariants are pinned as text across all three checked-in
  copies. It stays unproven until a mutation *failure* files a marked issue and a
  *later* scheduled green runs — the next cycle alone cannot prove it, because
  with no open marked issue the recovery step iterates an empty set.
- No consumer-repo install was exercised. The fresh-install rendering path from
  the plugin copy is untested.
- Release visibility is not behavior verification: a 200 on this tag proves
  publication only.
