# Charness v0.66.2

This patch release makes agent-facing maintenance commands clearer, keeps
delegation and host-portability claims truthful, and removes several sources of
avoidable verification and review churn.

## What changed

- Expanded useful `--help` guidance across release, retro, gather, handoff,
  issue, goal, implementation, web-fetch, duplicate, and quality planner tools.
- Corrected standing-delegation hierarchy and host-reference routing so portable
  instructions defer to repository-owned delegation contracts without claiming
  impossible instruction precedence.
- Repaired release-linked issue closeout so the release helper assembles and
  validates the complete issue-owned carrier, preserves artifact records apart
  from prepare packets, and can resume a partial publication without deleting
  or repointing its tag.
- Made quality scaffolding preserve the validator-owned H1 for custom titles.
- Kept explicit campaign changed-path and mutation-coverage proof on one
  immutable resolved SHA, preventing stale-marker reruns.
- Extracted closeout parser declarations into their internal owner, restoring
  entrypoint headroom without changing the CLI contract.
- Removed one AST-superseded regex and taught the advisory dead-code inventory
  to recognize dataclass output fields structurally instead of re-triaging them.

## Update

Run `charness update`, then verify with `charness --version` and `charness doctor`.
An already-running agent session may retain cached skill instructions until a
new session starts.

## Migration and rollback

No data migration is required. Operators using the optional release
`--close-issue` path must now also provide `--close-issue-classification` and
`--close-issue-carrier-file`; this repairs the former path, whose generated
carrier was rejected by the issue closeout consumer. If rollback is needed,
reinstall the previously published v0.66.1 plugin/install source; do not delete
or repoint the public v0.66.2 tag.

## Known risks and non-claims

- Existing-install refresh and fresh-checkout probes are release requirements;
  this release does not claim an isolated fresh-install exercise.
- Cautilus was not run; deterministic gates and bounded fresh-eye reviewers own
  the changed behavior because no explicit log-backed evaluator request existed.
- GitHub issue #433 remains open and is not closed by this release.
