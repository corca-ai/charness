# Release notes: v8.0.2-notes

## Summary

A patch release of correctness repairs to repo-owned gates and test
infrastructure. No public skill, command, adapter, or install surface changed, so
nothing here needs migration and existing callers are unaffected.

**A gate that could not run through its own invocation.** The staged-worktree
consistency gate is scheduled as `python3 scripts/<gate>.py --repo-root <root>`.
That argv puts `<repo>/scripts` on `sys.path` and not the repo root, so the gate
died at import with `ModuleNotFoundError: No module named 'scripts'`. Every test
reached it in-process, where both spellings resolve at once, so the suite
structurally could not observe it. It now bootstraps its own path, and a
real-process test crosses that boundary deliberately.

**One owner for gate bypass truthiness.** `NAME=0`, `false`, `no` and `off` are
what an operator writes to keep a gate running; bare truthiness reads every
non-empty spelling as "on" and switches the gate off instead. That inversion had
already shipped and been repaired more than once, in separate copies of the
same small predicate, because a repair to one restatement cannot reach the
others. The predicate now has a single owner, its spelling table is pinned once,
and the one copy that cannot import that owner — the standalone CLI, which must
work with no charness tree present — is bound to it by a test that drives both
implementations rather than by a comment asking a future editor to remember.

**A test-seed cache key that could name the wrong tree.** The key digested git
output while discarding return codes, so a failed read contributed the empty
string and every source state that failed the same way produced one constant
key: a shared namespace that unrelated checkouts would both write into and read
back, serving each other's seeds as a hit. Unreadable and absent are now
distinguished, untracked content is length-prefixed so a filename cannot absorb
it, and a source state that cannot be established refuses to name a key —
without taking test collection down with it.

**Test economics.** Substantial reductions in Git and subprocess work across the
standing suite, achieved by better structure rather than by weakening proof:
observing a fact once and classifying it many times, loading payload-only CLIs in
process, and content-addressing fixture seeds so they outlive an unrelated edit.

**The release lane had been failing, and the standing lane could not see it.**
The standing suite runs `-m 'not release_only'`, which skips the release queue
entirely, so a run of separate release-gate failures accumulated behind a green
that never measured them. They are repaired here. The largest was the
release-final changed-line gate, whose blocking set had grown a long tail of
changed lines with no executed test — mostly degradation arms: an unreadable
administration file, a status Git refused to produce, a working directory removed
underneath a running gate. Those are the arms where the difference between a
named refusal and a traceback decides whether the surrounding gate survives at
all, so each now carries a test that names the operator-visible consequence
rather than the line.

**A coverage mapper that answered "no test" about a tested file.** The
release-final lane resolves changed files to standing tests by textual reference,
and it could not see this repo's own by-path test loader: the module argument is a
test-local alias and the file argument is a `DIR / "name.py"` expression, so none
of its patterns matched. A changed release script was reported as mapping to
nothing while a whole test module drove it, which made the lane report PARTIAL —
it had analyzed all but one of its changed files and could not call that a pass.
The loader is now recognised, and the lane renders a verdict over its whole
changed set.
