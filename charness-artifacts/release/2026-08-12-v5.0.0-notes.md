# Charness 5.0.0

## Breaking operator-contract changes

This is a major release because two existing automation contracts now fail
closed instead of accepting incomplete input.

- `issue_tool.py close-with-comment` now requires a nonempty `AI-provenance:`
  line for every closeout classification. Add the line to the carrier body
  before invoking the command; its truth remains subject to the later closeout
  review.
- Handoff automation must no longer use `--pickup-target`. Run the handoff
  planner normally and repair each `unowned_entries` report before continuing.

No automatic migration is supplied. Run the affected command after updating and
retain its output as the local migration record.

## Added capability

- Local maintainer workflows can record lesson-ledger session and score evidence.
- Quality boundaries now cover timing-layer CI parity, immutable D47 measurement
  provenance, and content-identity ratcheting for boundary-bypass inventory.
- `handoff/judge-intent` has one authorized local Cautilus observation result.

## Update and recovery

Run `charness update`, then restart Codex or Claude Code as directed by the
updater. Verify the refreshed install with `charness doctor`.

There is no version-selecting updater rollback command. To return to 4.2.0,
reinstall or pin the prior `v4.2.0` release using the host's supported plugin
mechanism, restart the host, and rerun `charness doctor`. If that host-specific
recovery is unavailable, use the repository issue path rather than mixing an
old install with new closeout artifacts.

## Evidence limits

- The Cautilus result is one authorized local observation, not hosted CI,
  consumer behavior, or a general evaluator-success claim.
- Timing/CI evidence in this release verifies local static configuration; it
  does not claim a hosted workflow run.
- Public release visibility and installed-readback are verified only after the
  release has been published through their distinct channels.
