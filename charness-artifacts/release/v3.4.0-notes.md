# Charness 3.4.0

## Operator outcome

This minor release adds a maintained, opt-in closeout workflow for repository
operators. It helps run a bounded local closeout plan, freeze its critique and
evidence inputs, and retain a repository-relative receipt intended for
check-in. A companion validator checks
that a goal-bound retro citation and its exact recurrence markers reach the
next-session handoff.

These are repo-local direct scripts, not new top-level `charness` commands and
not a replacement for the normal installed-user update flow. Existing callers
have no migration or default-behavior change.

## Highlights

- `scripts/closeout_bundle.py` plans and, with explicit `--execute`, runs the
  bounded local sync, authoring preflight, packet/identity, and verification
  phases. The default completed receipt is
  `charness-artifacts/goals/<bundle-id>.json`; use `--receipt-path` to choose a
  different repository-relative path intended for check-in.
- `scripts/validate_retro_handoff_wiring.py` checks goal identity, the cited
  retro path in `docs/handoff.md`, and exact recurrence-class marker coverage.
  It deliberately does not judge prose meaning or disposition quality.
- Both scripts are mirrored in the checked-in plugin surface. Direct help
  checks pass locally, and both commands are declared in the fresh-checkout
  probe configuration; a fresh-checkout run remains a separate proof receipt.

## Compatibility and proof boundary

- No existing top-level CLI invocation or install surface is changed.
- The closeout result is local deterministic evidence only. It does not
  establish fresh-eye approval, provider freshness, installed-consumer
  behavior, remote CI, host-session proof, Cautilus, push, tag, publication,
  or release-readback proof.
- The validator proves mechanical wiring only; a human still judges whether a
  disposition is substantively correct.

## Update and rollback

Update normally:

```sh
charness update
charness version   # expect 3.4.0 after publication
charness doctor
```

This is an additive release, so operators may remain on 3.3.0 if they do not
need the new repo-local workflow. To roll back the plugin/workflow surface,
use a source checkout at `v3.3.0`:

```sh
charness update --repo-root <v3.3.0-checkout> --no-pull --skip-cli-install
charness version --repo-root <v3.3.0-checkout>
charness doctor --repo-root <v3.3.0-checkout>
```

Because this flow uses `--skip-cli-install`, it does not downgrade an already
installed managed CLI. A full managed-CLI rollback remains outside this
release's local proof and requires the repository's supported installation
procedure.

Release visibility, remote CI, installed refresh, and baton reconciliation are
verified through distinct post-publication channels; the release helper's
local green state is not their substitute.
