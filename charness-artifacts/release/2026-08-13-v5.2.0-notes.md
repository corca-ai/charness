# Charness 5.2.0

Charness 5.2.0 helps maintainers keep local quality evidence bounded, trust
focused changed-line results against the same population as broad proof, and
preserve lesson and contract decisions as reviewed append-only history—without
turning scores, reports, or an update into authorization.

## Highlights

- Failed standing-test basetemps now retain a bounded, runner-owned inspection
  window. Mutation-report cleanup is an explicit inventory, digest confirmation,
  and unchanged-candidate operation; managed or ambiguous evidence is preserved.
- Focused changed-line coverage uses the broad producer's marker policy, so a
  release-only test cannot silently turn a broad-missing line into a local clean
  verdict.
- Lesson ledgers can record reviewed archive and resurrection events, and the
  selection preview reserves its archive slot for a real archived lesson.
- Contract registers can record multi-session graduation proposals, citations,
  and reviewed graduation or retirement transitions while retaining displaced
  unit history. Evidence reports and scores remain non-authorizing.
- Handoff and retro workflows expose the local lesson-evaluation seam and typed
  continuity states without claiming that a command receipt proves presentation
  or usefulness.

## Upgrade

Run `charness update`, then restart Codex or Claude Code so the refreshed plugin
is loaded. If update fails, the plugin is unavailable after restart, or drift
persists, run `charness doctor` and follow its `next_action`; then rerun
`charness update` and restart the host.

There is no supported version-pinned rollback procedure for this compatible
minor release. Reinstalling an older plugin also does not undo repository-local
ledger migrations or append-only lifecycle events.

## Repository State and Migration

`charness update` refreshes Charness's managed checkout and installed or
host-visible surfaces. It does not migrate or otherwise mutate a consumer
repository's lesson ledger or contract register, and it does not apply an
archive, resurrection, graduation, or retirement.

For repositories that use these local state files, the lesson-ledger v3→v4 and
contract-register v1→v2 migration commands preview by default. Inspect the
receipt and repeat with `--execute` to write. Commit or otherwise preserve the
state files before executing a migration.

Lifecycle-event and graduation-proposal recorders append immediately after full
candidate validation; they are not preview commands. A proposal does not change
contract membership. The separate contract-transition command previews by
default and requires `--execute` plus a reviewed Markdown decision to apply.
See the version-pinned
[development guide](https://github.com/corca-ai/charness/blob/v5.2.0/docs/development.md#local-lesson-ledger-authoring)
for the exact commands and refusal boundaries.

No score threshold or evidence report authorizes a transition. This release
applies no live lesson lifecycle or contract-membership transition.

## Proof Limits

The release delta has local fresh-checkout command probes and cumulative
changed-line coverage over its mapped production files. Those checks do not
prove an installed host, every consumer repository, or hosted provider behavior.
The configured real-host trigger did not match this release delta; that is a
scope result, not installed-host proof.
