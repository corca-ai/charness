# Charness v1.0.9

This patch makes the root `charness` CLI's operational output a single YAML
document, so people and automation have one structured response contract.

## Breaking change

- Root operational commands now write YAML to stdout. Automation that parsed
  root `charness` JSON must switch to a YAML parser.
- The legacy exact `--json` argument remains accepted for transition safety,
  but it is ignored and does not select JSON output. It is no longer advertised
  in root command help.

## Output boundary

- `--help` remains human-oriented text on stdout.
- Progress messages and unstructured fatal errors remain on stderr; successful
  operational responses remain one YAML document on stdout.
- Private helper scripts retain their explicit JSON subprocess protocols; this
  release changes the root `charness` command only.

## Update, verify, and roll back

1. Run `charness update` and start a new Codex or Claude session so it loads
   the refreshed plugin cache and skill paths.
2. Update automation to parse YAML, then run `charness version` or
   `charness doctor` to verify the installed surface.
3. If a consumer must temporarily retain the previous root JSON response
   contract, reinstall Charness v1.0.8 through the same install path and
   restart the host session. No persistent-state migration is required.
