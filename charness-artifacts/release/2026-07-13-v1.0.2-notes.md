# Charness v1.0.2

Charness v1.0.2 tightens local issue-command validation and reduces duplicated
quality-test cost while preserving the delivery-boundary checks that protect
updates and runtime evidence.

## What Changed

- Invalid `issue resolve --target` usage now returns the existing local error
  before GitHub backend resolution or authentication preflight.
- Aggregate quality-runtime tests avoid repeated recorder process startup while
  retaining direct recorder contract coverage.
- Codex cache tests keep real update wiring, official app-server refresh, and
  actual cache-rotation/session-staleness proof in one smoke; stable cache
  transformations are checked at the pure helper layer.

## Compatibility

This is a patch release. Valid issue creation and resolution flows, public
command shape, adapters, and install/update behavior are unchanged.

## Update

Run:

```bash
charness update
```

Then restart active Claude Code and Codex sessions if the update reports cache
rotation, and verify:

```bash
charness doctor
charness --version
```

## Verification

- Focused issue tests prove the invalid local request performs no backend,
  preflight, or invocation work while preserving its return code and payload.
- Focused runtime and Codex cache tests improved under the same commands without
  removing their separately owned real-boundary smokes.
- Repo quality, secret, supply-chain, packaging, and plugin-mirror checks passed
  before the final clean release lock.

No Cautilus evaluation was run under the repo's ask-before-run policy. This
release does not close or claim resolution of issues #433 or #436, and it does
not claim a full-suite speedup from the focused measurements.

## Rollback

Reinstall v1.0.1 if rollback is needed. Do not delete or repoint a published
tag; record any publication problem explicitly and issue a corrective release.
