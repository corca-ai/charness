# Charness v1.0.0

Charness v1 removes the duplicate workflow router and leaves one clear split:
installed skill metadata plus model judgment choose ordinary workflows, while a
deterministic catalog reports hidden capability availability without pretending
to recommend a route.

## Breaking Changes

- The public `find-skills` skill and its free-text recommendation engine are
  removed. `/charness:find-skills` is no longer a supported invocation.
- The SessionStart routing hook now uses only the canonical `session_routing`
  adapter key and the `session_start_routing.py` hook script.
- The capability inventory now uses only `capability-catalog-adapter.yaml` and
  `charness-artifacts/capability-catalog/latest.{md,json}`.
- Legacy `find_skills_routing` input and `find-skills-adapter.yaml` discovery are
  rejected rather than silently translated.

## Migration

Before or immediately after updating:

1. Rename `find_skills_routing` to `session_routing` in any usage-episodes or
   host-hook adapter configuration.
2. Rename any `find-skills-adapter.yaml` file to
   `capability-catalog-adapter.yaml`.
3. Run `charness update`. The update reconciler removes Charness-owned retired
   SessionStart hook entries and installs the canonical hook when enabled; it
   does not keep accepting the retired configuration names.
4. Restart Claude Code and Codex sessions so their injected plugin paths and
   SessionStart context come from v1.0.0.
5. Run `charness doctor`, `charness --version`, and
   `charness session-capture status` to confirm installed version and hook
   state.

For hidden support or integration availability, use:

```bash
charness catalog list --repo-root . --json
```

Use `charness catalog refresh --repo-root .` only when intentionally refreshing
the durable catalog pointer. Neither command performs semantic task routing.

## What Changed

- Added deterministic `charness catalog list`, `refresh`, and
  `resolve-skill-path` commands.
- Simplified setup-generated `AGENTS.md` routing guidance to direct workflow
  selection with a narrow catalog fallback for hidden availability.
- Renamed the active host-hook module, script, APIs, state/status output, tests,
  and checked-in plugin export to session-routing terminology.
- Removed obsolete recommendation tests, evaluator scenarios, schema aliases,
  adapter fallbacks, current-pointer compatibility entries, and active docs that
  taught the retired router.
- Kept old hook markers and script names only in one-way cleanup code and tests
  that delete Charness-owned installed state.

## Update And Rollback

Update with `charness update`, restart active host sessions, then verify with
`charness doctor` and `charness --version`.

To roll back, reinstall v0.66.4. If configuration was migrated, also restore
the v0.66.4 adapter key/file names before reconciling hooks with that version;
v1's one-way cleanup may have removed old Charness-owned SessionStart entries.
