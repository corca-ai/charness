# charness 2.11.0

The runtime-budget gate stops asking you to transcribe numbers it already has: it
now emits the whole `runtime_budget_profiles` block for the profile it just
refused. And the affinity probe 2.10.0 shipped with a known crash no longer has
one.

No verdict changes on upgrade. The new flag is opt-in, and the advisory whose
number changed never affected an exit code.

## Amends the 2.10.0 notes

Two things the 2.10.0 notes told you are now obsolete. If those are the newest
notes you have read, both are wrong as of this release:

- **"Unreproduced, not yet fixed"** under 2.10.0's known limits described a crash
  when `sched_getaffinity` raises `OSError`. It is fixed here — see Fixed below.
  Do not pin 2.9.0 or work around it.
- **"Add the new id (run the gate once to see which)"** was the 2.10.0 migration
  instruction for a `profile_config_errors` exit. The error message now hands you
  the exact command instead, with `--runtime-profile` already filled in. The
  people most likely to need it are the ones still mid-migration from 2.10.0's
  profile-id change.

## Added

- **`--suggest-budgets` on `check_runtime_budget.py`.** A profile with recorded
  samples and no `budgets` block is the one combination that hard-fails the gate,
  and writing that block by hand is where bars get transcribed *below*
  already-observed runs — it put eight such bars in this repo's own adapter. The
  flag prints a paste-ready block: every value 1.4x that label's worst observed
  run, rounded up to 500ms.

  Each line carries `n=`, the sample count behind it, and labels with `n<3` are
  listed separately as thin evidence. A bar sized from one run and a bar sized
  from twenty read identically once committed, and the slack advisory only fires
  at 3x, so nothing downstream will ever tell them apart. The header names the
  sample *source*, not just the profile, because a declared `command_timing_log`
  with no `profile` field matches every profile — so a block headed for one
  machine can be measured on another.

  It exits non-zero when the profile has no samples at all: an invented bar is
  worse than a missing one. It cannot be combined with
  `--json`/`--summary`/`--detail` (usage error, exit 2) — the output is commented
  YAML, and honoring those flags would either drop the comments carrying the
  evidence depth or hand YAML to a caller that parses JSON.

- **`skills/public/quality/scripts/runtime_budget_sizing_lib.py`** — how a bar is
  *sized*, split out of `runtime_budget_lib.py`, which now imports it. Copy the
  quality scripts directory as a unit; a partial copy leaves `runtime_budget_lib`
  unimportable.

- **The "profile not configured in `runtime_budget_profiles`" error now carries
  the command that fixes it**, with `--runtime-profile` filled in for the profile
  it rejected. Without the interpolated profile, pasting the command while
  investigating *another* machine's profile re-derives from the machine you are
  sitting at and files bars from the wrong hardware under the right heading.

## Fixed

- **The 2.10.0 known limit is closed.** `sched_getaffinity` is now wrapped in
  `except (AttributeError, OSError)`. A host whose kernel *refuses* the query — a
  seccomp/LSM policy — crashed every gate that derives a runtime profile in
  2.10.0, where the `os.cpu_count()` call it replaced could not fail at all.
- **The slack advisory and `--suggest-budgets` no longer propose different
  numbers.** `consider <N>ms` (and `suggested_budget_ms` in `--json`) now comes
  from the same function the new flag uses. In 2.10.0 the two disagreed for an
  identical sample — 10969 vs 11000 — on the one path an operator is told to act
  on. Values move up by at most 499ms and never down, so a bar retuned from this
  advisory is never *tighter* than 2.10.0 proposed.
- **The no-samples message no longer misdirects you** when you name a profile
  other than the current machine's.

## Why minor rather than patch

The affinity and advisory repairs alone would be patch. A new exported operator
flag plus a new exported module is additive operator surface, which the version
policy puts at minor — the same call 2.9.0 and 2.10.0 made for the same shape.

One debatable point, stated rather than hidden: **`SLACK_SUGGESTION_HEADROOM`
moved out of `runtime_budget_lib` into the new sizing module.** If you import that
constant by name, update the import. These are path-loaded skill helpers rather
than a published API and no in-repo consumer imports it, which is why this is not
major — but it is a public name that disappeared from an exported module.

Also changed and not major: the `profile_config_errors` stderr line gained a
suffix. The stable prefix `is not configured in runtime_budget_profiles` is
intact, so a grep survives; an exact-line matcher does not.

## Not in this release

Listed only so their absence is not read as an omission — none of these reach an
installed user: this repo's own `.agents/quality-adapter.yaml` bars (repo-local;
the exported adapter template still renders `runtime_budget_profiles: {}`), the
runtime-budget gate tests, and the handoff refresh.

## Known limits

- `--suggest-budgets` output is proven derivable, paste-parseable, and annotated
  with its evidence depth. It is **not** proven to be good bars — whether
  1.4x-of-worst is right for your repo is your judgment, which is why the mode is
  advisory and never edits your adapter.
- **When affinity is *refused* rather than absent, the profile falls back to the
  full CPU count silently.** A container that both limits CPUs and blocks the
  syscall files slow samples into the unrestricted profile again — the
  cross-contamination 2.10.0's change was written to stop. Deliberate: fail-open
  is the right call for profile detection, and the case needs a policy that blocks
  a read-only query.
- Sizing falls back to a declared `command_timing_log` when `runtime-signals.json`
  has nothing for the profile. Check the header's source line before committing.
- The new sizing module has not been through a mutation run.
