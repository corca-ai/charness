Goal Run establishment no longer needs contract archaeology (#821)

Closes #821

Classification: bug

JTBD: An operator establishing an issue-native Goal Run with `achieve` and
`issue` must work from the skill surface, not by reverse-engineering
contracts from a previous run's artifacts. Five deterministic frictions
burned roughly forty minutes, two provider refusals, and one immutable
mistake recording on the reporting activation.

Boundary: In scope are the five reported contracts — the binding freeze
command, the bootstrap body block, the attempt-id reuse rule, the
progress cursor shape, and the planning-section writer. Out of scope is
the fail-closed hardening of corrupt-receipt create recovery (valid
follow-up, needs its own provider-behavior design) and any change to
provider recovery semantics.

Resolution Brief: `goal_binding.py freeze` hashes the draft once,
canonicalizes planner-ordered manifest dependencies at build, and lands
the binding at the deterministic sibling; the bootstrap block's exact
eight fields and the `verified-target-roundtrip` constant are documented;
attempt ids are documented single-use with a reuse hint in the refusal;
the parent cursor's six required fields and two tolerated legacy digests
are documented; and non-Goal planning sections are documented as
direct edits the writer preserves.

Implementation: `goal_binding.py` freeze dispatcher plus dependency
canonicalization, new `goal_binding_freeze.py` (pre-read containment
check, no provider call, deterministic sibling only),
`issue_tracker_observation.py` reuse hint, three skill-doc updates
(`SKILL.md`, `issue-backend.md`, `lifecycle-during.md`,
`goal-artifact.md`), and `test_goal_binding_freeze_cli.py` (18 passing).
Shipped in charness 8.9.1 (patch: repair, no invocation break). Release
critique answered three reviewer blockers with repairs and deferred one
pre-existing recovery hardening as follow-up.

Behavior: Goal Run establishment contracts verified on this tree —
`goal_binding.py freeze --help` names the freeze subcommand, freeze
writes the deterministic sibling binding, bootstrap/attempt-id/cursor
contracts read from the skill references, and the focused suite plus the
release lane (89 passed, 0 failed) are green.

Root Cause: Establishment contracts lived in code and prior-run
artifacts instead of the skill surface: no freeze entrypoint existed,
the bootstrap block shape was recoverable only from an earlier run's
body file, attempt-id single-use was unstated, the cursor shape lived
only in the pickup contract, and the writer's title-and-Goal-only scope
left every other section's path ambiguous.

Debug Artifact: The diagnosis trail is the reporting issue body, which
quotes all five refusals verbatim, plus the critique packet binding the
repaired delta
(`charness-artifacts/critique/2026-09-19-050038-packet.json`) and the
two worker results dispositioned in
`charness-artifacts/critique/v891-release-critique.md`.

Siblings: Sibling search decision — the same establishment frictions
appear in no other open issue; the nearest neighbor is #820, which is
8.9.0 release context rather than a shared failing contract. Proof: an
open-issue search over goal-run establishment terms surfaces this issue
alone.

Prevention: Stored binding bytes stay strict while build inputs
canonicalize; draft containment is checked before any read; the
unimplementable binding-path override was deleted rather than
documented; each clarified contract lives in its owning module with
standing tests beside it.
