# Charness v2.2.1

This patch makes focused proof complete before commit and makes failed release
preparation safely resumable without persisting raw exception logs.

## What changed

- The mutation-coverage selector now includes eligible untracked files, follows
  imported test helpers, and retains tests that exercise loader entrypoints. This
  trades a few seconds of selection time for avoiding a late full proof rerun.
- Detailed selector diagnostics now use `--detail` YAML. The residual internal
  `--json` flag is removed; the default remains a compact copyable command.
- Failed pre-publication releases persist typed recovery state under the Git
  common directory at `charness-release-failures/*.yaml` without dirtying the
  worktree. Records use 0700/0600 permissions, atomic replacement, and retain the
  newest 20 files.
- Durable recovery records intentionally omit raw exception text. Preserve the
  terminal failure payload when detailed remediation context is needed; if record
  persistence itself fails, bounded actionable detail remains in the terminal.

Existing rollback and `--resume --publish-current` safeguards remain the recovery
path. No release-time real-host trigger matched this patch; clean-checkout probes,
the broad suite, focused coverage, exact changed-line consumption, and bounded
fresh-eye review provide the pre-publication evidence.

## Update

Run `charness update`, then restart the host session so it loads v2.2.1.
