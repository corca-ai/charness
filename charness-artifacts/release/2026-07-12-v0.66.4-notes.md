# Charness v0.66.4

This patch makes verification cheaper to run and harder to misuse.

## What Changed

- The observed SLOC inventory writer now runs during sync, so a read-only
  verification phase does not create its own tracked drift or false-start a
  later gate.
- Mutation-coverage production now emits the resolved base SHA, coverage JSON
  path, and one copyable strict-reuse consumer command. The executable path is
  resolved from the Charness checkout/install; `--repo-root` still identifies
  the repository being verified.
- Unfiltered full, read-only, and release quality runs record a current
  aggregate runtime sample without allowing telemetry failure to replace the
  quality result.
- Quality-runner tests were split by behavior seam without increasing test
  count or changing the public command surface.
- Release-time host proof now follows the explicit external-tool control-plane
  surface, avoiding an unrelated nose checklist for ordinary plugin scripts
  while retaining doctor/install/update path coverage.

## Mutation-Coverage Handoff

After the producer succeeds, run its `mutation_coverage_consumer_command`
exactly. Success means the existing coverage file is reused for the same
committed base and no blocking changed lines remain. If the consumer reports a
stale source, base mismatch, or missing path, rerun the producer for the current
committed bundle; do not reconstruct the arguments from memory.

## Compatibility and Scope

No migration, new public CLI, prompt/skill behavior change, or new blocking
quality floor is introduced. This release moves the one observed SLOC writer;
it does not claim an exhaustive audit of every future write-shaped verifier.
The existing release-carrier preflight behavior was already shipped separately;
tracker lifecycle is not part of this patch.

## Update and Rollback

Run `charness update`, follow any host restart instruction it prints, then use
`charness doctor` and `charness --version` to confirm the installed release.
If rollback is necessary, reinstall `v0.66.3`; no state migration is required.
