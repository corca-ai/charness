# Charness v8.4.4

## Summary

- Clarify when implementation can reuse applicable evidence, with verification
  scope routed to its owning contract and independent release proof preserved.
- Let review previews continue into live execution without reserving the live
  attempt; keep preview bytes intact and duplicate live execution refused.
- Preserve release advisory meaning: evidence limits and recommendations are no
  longer collectively described as confirmed inaccuracies.
- Use the length checker's own target universe for cheap staged checks, so
  evidence-only Python copies do not trigger an empty-universe failure.

## Consumer evidence and limits

Installed-package alias spec-to-impl and existing-script CLI journeys pass their
frozen acceptance checks without operator rescue. Repeated-work results are
mixed: CLI executable repetition improves, while alias handoff repetition
increases. These bounded observations are not a general speed guarantee.
The comparison records the shared timeout deviation and exact package sources.

## Update

Run `charness update`, then `charness version`. No command migration is required.
Update follows the managed branch, which may also contain post-release commits.
