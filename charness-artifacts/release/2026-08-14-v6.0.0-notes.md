# Charness 6.0.0

## Breaking operator-contract changes

This is a major release because a public flag surface was removed and two probe
payloads changed shape. A consuming repo that scripted against either will break
on upgrade.

- **`--json` is gone from public skill helpers.** Two documented flags
  (`inventory_adapter_gate_design.py`, `seed_dup_review.py`) and eleven hidden
  compatibility aliases were removed. One of the hidden ones lived in
  `summary_output_lib.add_output_args`, so the removal reaches 27 `quality`
  scripts at once. Default output has been YAML since the 5.x line and is
  unchanged; ask for the full payload with `--detail`. Migration is usually one
  character of parser change or none at all: JSON is valid YAML, so a YAML
  parser reads both the old and new output. `charness <subcommand> --json` is
  also no longer stripped from argv and now exits 2.
- **Trigger probes report whether they RAN before what they found.**
  `retro/scripts/check_auto_trigger.py` and
  `prove/scripts/check_boundary_escalation.py` now lead with
  `state: evaluated | not-configured | not-established`, emit `triggered` only
  when the probe actually ran, and exit 3 when the answer is undetermined. A
  caller that polled `triggered` alone was reading "could not tell" as "no";
  read `state` first, and treat exit 3 as an unanswered probe rather than a
  negative verdict.
- **Repo-gate shell scripts refuse to run from the exported plugin copy.**
  `check-markdown.sh`, `check-shell.sh`, `check-links-internal.sh`,
  `check-secrets.sh`, `check-links-external.sh`, and `install-git-hooks.sh` now
  exit 1 with a named reason when their package root is not the git root,
  instead of silently measuring a narrower tree. Set `CHARNESS_REPO_ROOT` to the
  source checkout to override. `install-git-hooks.sh` is the one worth calling
  out: invoked bare from an exported copy it previously repointed the entire
  enclosing repository's `core.hooksPath` and disabled its real hooks.
- **`setup` no longer seeds an auto-retro opt-out the repo never chose.**
  `seed_retro_memory.py` used to write `auto_session_trigger_surfaces: []` and
  `auto_session_trigger_path_globs: []`, which the probe then read as a
  deliberate opt-out. Fresh adapters leave both keys unset so the probe reports
  `not-established` and names the remedy.
- **The retro lesson-evaluation floor is conditional on a declared evaluator.**
  A repo that declares no evaluator is no longer required to write a
  `not-evaluated / missing-start` disposition it had no way to avoid; the
  validator reports the floor as inert and names the opt-in command.
- **The two RELEASE-readiness probes stopped reporting success over an
  unevaluated run.** `check_fresh_checkout_probes.py` returned exit 0 with
  `status: configured` and `probe_results: []` when the declared probes had not
  been run — "zero failing probes" from a run that executed none. It now reports
  `status: not_established` at **exit 3** and omits `probe_results` entirely, and
  the release plan's gate packet passes `--run-probes` so the probes actually
  execute. A consumer whose declared probes are slow will feel that cost on every
  release plan, and a declared probe that fails now fails the plan.
  `check_real_host_proof.py` returned `required: false` over an EMPTY changed-path
  scope; it now omits the `required` key entirely in that state and exits 3, so a
  caller cannot subscript a verdict that was never produced. Scripts reading
  either payload should read the status/scope key first and must tolerate the
  verdict key being absent.
- **The critique cross-surface probe refuses an unreadable adapter instead of
  reporting an opt-out.** A `.agents/critique-adapter.yaml` the loader rejected —
  including a one-character slip like `boundary_cross_surface_globs: "docs/**"`
  where a list belongs, or list items written without `-` dashes — used to yield
  empty probe config, `not-configured`, and exit 0. It now reports
  `not-established` at exit 3. Only `[]` declares a deliberate empty probe.

No automatic migration is supplied. Run the affected commands after updating and
retain their output as the local migration record.

## Added capability

- `scripts/init_lesson_ledger.py` creates a valid empty lesson ledger so a
  consuming repo can opt into the lesson lifecycle at all. It refuses to
  overwrite an existing ledger and refuses to wipe a committed one.
- Dated quality artifacts are now checked for date coherence: a `Date:` header
  that disagrees with the date in its own filename is refused, which is the
  signature of a review overwriting the previous review in place.
- `check_documented_command_flags.py` now resolves invocations in Python argv
  lists, adapter YAML command lists, surface-manifest command strings, and
  tests, not only in markdown, and reports typed skips so a pass cannot
  over-claim its coverage.
- The retro scaffold no longer emits a duplicate `## Lesson Evaluation` section
  when the repo's adapter declares the same heading, and the retro planner now
  reports date-activated rules with their activation dates instead of letting an
  author discover them by tripping one.

## Update and recovery

Run `charness update`, then restart Codex or Claude Code as directed by the
updater. Verify the refreshed install with `charness doctor`.

There is no version-selecting updater rollback command. To return to 5.2.0,
reinstall or pin the prior `v5.2.0` release using the host's supported plugin
mechanism, restart the host, and rerun `charness doctor`. If that host-specific
recovery is unavailable, use the repository issue path rather than mixing an old
install with new closeout artifacts.

## Evidence limits

- The removed `--json` surfaces were enumerated from the commit that deleted
  them and from a repo-wide sweep of this tree. Whether any consuming repo
  scripted against them is not observable from here, which is why the migration
  is stated rather than assumed to be unnecessary.
- Public release visibility and installed-host readback are verified only after
  the release has been published, through their distinct channels.
