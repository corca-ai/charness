# charness 2.9.0

A quality gate that had stopped gating now gates again — and the escape hatch it
documents is reachable from the place it blocks.

## Stricter gates (read this before upgrading)

`check-seed-fixture-budget` **can now fail your push.** Previously a `du` scan
that failed was reported as advisory and exited 0, which meant a box whose scan
was permanently broken passed the gate forever without ever measuring a byte.

What changed, precisely:

- A scan failure that is not a capability gap now exits **1**
  (`blocking_pytest_temp_scan_failed`).
- A **capability gap stays advisory**: `du` absent, `du` not executable, or a
  `du` too old to accept `-B` (BusyBox, some BSD builds). Those are things the
  box cannot do, not measurements that broke, and no retry would change the
  answer. Portable hosts are not newly blocked by this.
- A `du` walk that merely lost a file to a concurrent teardown is **not** a
  failure. `du` keeps walking and still prints the root total; that output, not
  the exit status, is what the gate grades. Such a scan is accepted and reported
  as `partial`.
- A walk that died before printing the root total is retried, bounded, with the
  timeout capped **across** attempts rather than per attempt.

**Escape hatch.** Pass `--advisory-on-scan-failure` when invoking the gate
directly, or set `CHARNESS_SEED_FIXTURE_ADVISORY=1` when it runs inside
`run-quality.sh` (which fixes the argv). Both report the failure without
blocking. This exists so the answer to a scan failure is never
`git push --no-verify`, which disables every gate to get past one.

## Fixed

- **The plugin-exported copy of `check_seed_fixture_budget.py` was dead.** It
  hard-coded a `skills/public/` path that does not exist in the flattened export
  layout and died with a bare `FileNotFoundError`. It now resolves both layouts,
  like every sibling script already did.
- The runner comment justifying this gate's placement still described it as
  fail-open, which would have misled the next person to move it.
- The gate's `attention-state-visibility` declaration listed one advisory state
  when there are now three, plus a blocking one.

## Added

- `skills/public/quality/scripts/pytest_temp_scan_lib.py`: the `du`-backed pytest
  temp scan, its retry policy, and its failure taxonomy, split out of
  `standing_test_economics_lib` and re-exported from it.
- `--advisory-on-scan-failure` on `check_seed_fixture_budget.py`.

## Why minor rather than patch

The behavior repair alone would be a patch. The new public flag and the new
module in the public quality surface are additive operator surface, which the
version policy puts at minor. This also matches how 2.8.0 shipped the same class
of change — blocking gates getting stricter.

## Known limits

- A `partial` scan under-counts, so a budget breach could in principle hide
  behind one. It is reported, not gated; the margin on the observed footprint is
  four orders of magnitude.
- The BusyBox/BSD `du` usage-error detection is matched against strings those
  builds are documented to emit. No real Alpine or macOS run backs it. If the
  detection misses, that host gets a blocked push, recoverable with the escape
  hatch above.
- `du_timeout` blocks and is not treated as a capability gap. With
  `PYTEST_DEBUG_TEMPROOT` unset the scan falls back to the shared
  `/tmp/pytest-of-<user>`, so only direct invocation against a tree the repo does
  not own is exposed; `run-quality.sh` keys the temp root per repo.
