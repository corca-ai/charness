# charness 4.2.0

## Read this first: three floors can now refuse work that previously passed

All three are floors doing what their published contract already claimed; the
implementations were narrower than the contracts. Each escape is one line, in a
section that already exists, and each refusal message names it.

1. **The release coordination floor now recognises your release surface.** It
   previously matched only four of charness's own script names, so in every other
   repo it was silently inert — a goal that bumped a version closed with no
   release evidence and no line saying the check had not applied. It now matches
   ecosystem-standard version manifests and publish commands (`pyproject.toml`,
   `package.json`, `Cargo.toml`, `pom.xml`, `setup.py`, `npm publish`,
   `cargo publish`, `twine upload`, `gh release`, `git tag`, and more).
   **If your goal touches one of those and does not need a release step**, add to
   `## Coordination Cues`:
   `Release: n/a — <reason, 30+ chars>`.
   **If your release surface is bespoke**, declare it in your achieve adapter:
   `release_surface_tokens: ["./ops/ship-it.sh"]` — see
   `achieve/references/adapter-contract.md`.

2. **The issue closeout observer reads negation by clause, not by a character
   window.** `Fresh-eye satisfaction: parent-delegated review never ran` is now
   correctly refused; previously only a negation within 24 characters *before* the
   token was seen, so a sentence saying no delegation happened could read as one
   that did. Clean results are unaffected: `no` and `none` count only when they
   precede the token, so `parent-delegated bounded review found no blockers`
   still passes. **Escape** if a review genuinely could not run:
   `Fresh-eye satisfaction: blocked <host-signal>`.

3. **The consolidation-ledger floor gained `unif*` and lost a length cap.**
   `Four implementations, three unified.` is now refused exactly as
   `three consolidated.` already was, and a count separated from its verb by more
   than 80 characters is no longer invisible. **Escape**: state the two numbers
   separately — `population: 4 implementations; removed: 2`.

## New: re-verify your backlog instead of re-reading it

`achieve` gains a Before-phase helper that answers "is this issue still true?" in
one command, and then **stops** — it never closes an issue and never recommends
closing one.

```bash
python3 "$SKILL_DIR/scripts/recount_premise_state.py" --repo-root . \
  --premise-file <your judgements>.json --with-bodies --exclude <the goal you are shaping>
```

Per open issue it renders `premise-holds`, `premise-refuted-clean`,
`premise-refuted-with-live-residue`, or `unverifiable-by-machine`.

Three things worth knowing before you trust it:

- **The premise judgement is yours.** With no `--premise-file`, every issue reads
  `unverifiable-by-machine`. The tool will not invent a judgement you did not make.
- **A refuted premise is not a close signal.** `premise-refuted-with-live-residue`
  is a REFUSAL to recommend. The instance this was built from was genuinely
  refuted and still must not close, because a further ask was live.
- **Residue is STRUCTURAL, and `clean` is not a claim that nobody declined.** It
  reads exactly two signals: an explicit `Premise-residue: #N — reason` marker a
  record author writes, and unchecked `- [ ]` items in the issue body. It does
  **not** infer a decline from wording, so when a record declines, write the
  marker. A channel that did not run (unread body, absent or gitignored record
  root) refuses rather than reporting clean.

## New: `consolidated`, a close that claims nothing about the defect

A sixth issue closeout classification, for moving an issue to an umbrella rather
than fixing it. It is **not** floor-exempt — it swaps the resolution floor for its
own, because meeting the resolution floor with a consolidation means writing
sentences that are not true.

It requires `Consolidated into: #N` (exactly one destination, not a
self-reference), refuses any repair claim (`Implementation:`, `Prevention:`,
`Resolution brief:`, `Behavior #N:`, `HOTL #N:`, `Critique #N:`, or a
`Fixes`/`Resolves` keyword), and must close via
`issue_tool.py close-with-comment --reason "not planned"` — a keyword close would
render publicly as `completed`, asserting the repair it refuses. Four facts are
read back from the tracker first: the destination exists, is OPEN, its body names
the issue moving into it, and it is not itself a consolidation.

See `issue/references/closeout-discipline.md`.

**Not yet exercised end to end.** No umbrella has been filed and no member closed
through this path against a live tracker. The refusals are tested; the happy path
against real GitHub is not. Its blast radius is contained — every new path is
gated on the classification, so a repo that never selects it cannot regress.

## Also

- `quality`'s attention-state registry covers the new backlog-re-verification
  surfaces, so their skip states are declared rather than reading as clean passes.
- Four suites now declare which modules they are the standing coverage for, so the
  changed-line mutation gate can map them.

## Open risks and non-claims

- The consolidation chain check is near-inert against real chains: a consolidated
  destination is CLOSED, so the OPEN check catches what the chain check claims to.
- The backlog re-verification scanner hardcodes `charness-artifacts/` and two
  `docs/` paths. It fails CLOSED for a different layout (an absent root becomes a
  refusal, never a clean verdict), but its message says "check --repo-root", which
  misdiagnoses that case.
- The observer's negation vocabulary is English-only, stated in the module.
- No consumer repo was inspected for this release.
