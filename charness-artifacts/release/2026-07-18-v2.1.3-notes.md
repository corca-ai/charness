# Charness v2.1.3

This patch makes release preparation safer and improves maintainer diagnostics.

- If local release preparation fails before its release commit, Charness restores tracked changes to the clean starting commit and quarantines newly created non-ignored files instead of deleting them. Retry the normal release command after inspecting any reported quarantine path.
- A release commit that exists but lacks its local tag can be resumed only with `--resume --publish-current`; it revalidates that exact commit and refuses ambiguous remote or public tag state.
- Focused mutation-test suggestions now recognize split path references and local loader ancestry. They remain a focused hint: broad pytest and the changed-line consumer remain authoritative.
- Dead-code advisory results now suppress only proven framework and source-scanned conventions. Dynamic exports remain review candidates; advisory output is not an automatic deletion decision.

The release content delta is `v2.1.2..v2.1.3`. It includes the three post-tag v2.1.2 verification and handoff records that were already pushed to `main`; runtime changed-line proof for this release's new implementation work used the exact `3c2516b9..b618c784` range.

## Upgrade and rollback

Run `charness update`, then start a new Codex or Claude session if it needs the refreshed plugin surface. No migration is required.

For failed local release preparation, use the reported rollback or quarantine evidence and retry. Do not manually rewrite a post-commit release state; use the documented resume path.

No end-to-end wall-clock speedup is claimed. No release-time real-host proof trigger matched this delta; fresh-checkout, public-readback, and installed-version evidence remain release closeout responsibilities.
