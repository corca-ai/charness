## What changed

Charness 1.0.4 is a patch release for two operator-safety defects:

- `charness catalog refresh` now rejects missing or non-directory `--repo-root`
  values before writing. Invalid roots return a clean exit code and diagnostic
  instead of creating a typo directory or leaking a traceback.
- Claude plugin observation and mutation now honor an explicit `--home-root`
  consistently across doctor, init, update, reset, and uninstall. A custom-home
  workflow no longer reads from, writes to, or removes plugin state in an
  unrelated process home.

## Verification

- Added backend, direct CLI, public handler, and actual-process catalog tests.
- Added two-home public CLI tests for Claude doctor, init, and reset, covering
  observation plus both mutation directions without adding standing copy-heavy
  test cost.
- Full release gates, fresh-checkout probes, public release visibility, and
  installed-version readback are release-workflow proof items; these notes do
  not claim them before that workflow completes.

## Update

Run `charness update`, then restart active Codex and Claude Code sessions so
they resolve the refreshed plugin cache and skill paths.

This is a patch update with no migration step. If v1.0.4 regresses, restore the
v1.0.3 release, restart active Codex and Claude Code sessions, and rerun
`charness doctor --json` plus cache/version checks.

Deterministic fake-CLI tests prove the custom-home subprocess seam; this release
does not claim a real Claude custom-home runtime exercise. No issue lifecycle
changes are included in this release.
