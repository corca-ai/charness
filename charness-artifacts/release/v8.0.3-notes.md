# Release notes: v8.0.3-notes

## Summary

A patch release that closes the follow-ups the previous Goal Run left open. No
public skill, `charness` subcommand, or install surface gained or lost a
member: `git diff --name-status v8.0.2..HEAD -- 'skills/public/*/SKILL.md'
packaging charness` adds and deletes nothing, and the derived block below
lists the current inventories. Nothing here needs migration. The operator
named this version in advance (recorded under Interview Decisions in
`charness-artifacts/goals/2026-09-03-lesson-review-and-775-followups.md`);
the lightest honest bump is patch.

**A lane cannot report done past an unproven line.** `charness task run` now
runs the release changed-line gate in the lane's own worktree at completion,
against the lane's own base, and writes the verdict into the receipt as
`changed_line_gate` with the same `blocking_detail` the pre-push hook prints.
A refusal demotes the result to `validated-partial-result` and names the line
in `next_step`. Repeated push refusals for one commit were this class.

**A finished lane keeps only its record.** A `completed` commit-only lane
releases its worktree and runtime at completion and the receipt names the
branch that carries the candidate. The runtime tree under `charness/runtime/`
now has a retention rule for the rest: finished lanes, nested keys, idle
rebuilt-on-demand caches, and keys whose repo is gone, swept on every standing
pytest run with every removal and skip logged. A child bootstrapped from a
key's exported cache home lands beside that key, never inside it.

**A test cannot ride a short deadline.** A sibling of the wall-clock form
check refuses a test whose verdict depends on a short `*_TIMEOUT_SECONDS`
knob together with an assertion on the child's output, or a short
`communicate`/`run`/`wait` deadline whose handler asserts; the limits are
constants in the check. Its
record names each kept site with a written reason and only shrinks; its
docstring names the shapes it cannot see.

**Skill scripts say which copy answered.** Inside the authoring repo the Goal
Run pickup and the release planner report `script_origin`. The pickup refuses
a drifted installed copy before any provider read instead of reading an older
contract; the release planner reports and does not refuse, because it is
read-only, and the publish helper's entrypoint guard refuses before a release
mutation. The rule lives in the shared bootstrap-resolution reference.

**Release critique repairs, in this tree.** The runtime sweep's salvage of
uncommitted edits reads NUL-separated paths and reads its archive back before a
worktree is removed; the update instruction says what `charness update` does
(fast-forward the managed checkout's branch); the README names the host
restart between install and first use; the Goal lifecycle page is marked
current.
