## Lifecycle / execution

### achieve

**의도:** achieve operates a long-running autonomous objective as an auditable goal lifecycle: it interviews prose intent (e.g. `$achieve <outcome>` or a `/goal @file` request) into one reviewable goal artifact under charness-artifacts/goals/, keeps slice progress and verification visible during the run, and proves the goal at the end with honest non-claims. It coordinates the existing workflow skills (ideation/spec/impl/quality/issue/critique/retro) around that single goal artifact rather than being a separate task-execution or run-loop engine.

**본문 지원:** Bootstrap resolves `$SKILL_DIR`, reads live repo/handoff context, then scaffolds-or-locates and validates the goal artifact via `upsert_goal.py` and `check_goal_artifact.py` so every invocation starts from a real on-disk artifact. The Workflow spine runs one goal as three hard phases — Before (interview prose into a shaped `--pursue-ready` draft: outcome, non-goals, boundaries, verification plan, timebox, `Discuss before activation:` for consequential defaults), During (slice and record into `## Active Operating Frame` and `## Slice Log` with escalating named proof levels and slice-level critique), and After (describe-first closeout preflight, final quality gate, honest non-claims, bound Auto-Retro dispositions, flip to `complete`). Output Shape fixes the artifact location plus its audit sections, the `/goal` activation line, and the split completion report (self- vs user-verification, residual risk, non-claims, operator decision queue). Guardrails keep achieve a goal operator not a task runner — `/goal` is pursue-only, no fabricated host metrics, and coordination routing is deferred to `find-skills` rather than an inline phase→skill map.

**레퍼런스 (조건별):**

- *engage-always (매 런 코어):*

  - `goal-artifact.md` — The goal artifact structural contract: fixed location, `## Active Operating Frame`, audit sections, helper scripts, metrics-honesty and producer contract.  ·  **조건:** every run — the structural contract every run must follow to save and validate a reviewable artifact (referenced alongside lifecycle.md; tagged DEPTH)
  - `coordination.md` — Per-skill roles inside a goal (ideation/spec/impl/debug/quality/issue/critique/retro), the `handoff` boundary, and the find-skills routing cues seeded during active runs.  ·  **조건:** every run — coordination routing is a core workflow step and find-skills routing cues must be seeded on active runs

### spec

**의도:** spec turns a concept or ideation artifact into a living implementation contract: it refines existing design docs into the current build contract, decides what must be fixed now versus probed during implementation, defines testable success criteria tied to acceptance checks, and keeps that contract synchronized as `impl` discovers new facts.

**본문 지원:** Bootstrap grounds the contract in repo truth first — it reads current concept docs plus implementation/acceptance reality (git status, README/AGENTS/handoff, ideation/impl/create-skill neighbors, and the risk-interrupt planner) before inventing structure. Contract Shaping picks the lightest honest contract shape and routes the taxonomy checkpoint, executable-vs-lint boundary, and design lenses; the 8-step Workflow is the spine — ingest the artifact, classify remaining uncertainty into Fixed/Probe/Deferred, reduce only the ambiguity that blocks this slice, define the execution contract, tie every important success criterion to at least one acceptance check with durable proof, keep the contract alive during impl, run bounded critique, and end with the next execution state. Output Shape fixes the canonical spec sections (Problem, Capability Contract, Current Slice, Fixed/Probe/Deferred, Non-Goals, Success Criteria, Acceptance Checks, Critique, Canonical Artifact, First Implementation Slice) plus the Closeout Vocabulary verification-type tokens, and Guardrails forbid reopening ideation, skipping the bounded critique, leaving rejected paths chat-only, or writing a fake spec over an unstable concept.

  - `success-criteria.md` — Governing rubric for good success criteria (observable, testable, bounded, tied to user/operator value) with examples.  ·  **조건:** Every run — Workflow step 5 treats success criteria as 'the heart of the spec'; gist inlined (classTag INLINE), the doc is the governing rubric not a forced open.

  - `design-lenses.md` — Beck (smallest honest slice, fast feedback) and Ousterhout (deeper seam, duplicated low-level detail signals a wrong boundary) moves for slice sizing and contract boundaries.  ·  **조건:** Every run that decides slice size / contract boundary — RCF floor: this content appears nowhere in the SKILL.md Contract Shaping body, so a representative run is forced to open it (required command fragment).

### impl

**의도:** impl is the skill for moving work out of a contract and into real code, config, tests, or operator-facing artifacts. It consumes the current implementation contract when one exists (or bootstraps a small honest current-slice contract inline when it does not), implements the smallest meaningful slice, verifies it with the strongest honest proof available, and keeps the contract synchronized when implementation reveals new facts.

**본문 지원:** Bootstrap resolves $SKILL_DIR, reads the current contract (spec/handoff/diff) or reconstructs the smallest honest one, resolves+inits the impl adapter, and runs a verification survey and worktree readiness probe as onboarding — finding the best self-verification path before any code is written. The seven-step Workflow is the spine that carries the intent: ingest the current slice and restate it in implementation terms, keep the contract honest (Fixed Decisions fixed, Probe Questions as learning goals, Deferred Decisions visible), implement the smallest meaningful unit, verify with the strongest honest path (executed proof over inspection, evaluator/Cautilus only for explicit behavior proof), sync truth surfaces and re-read the contract, run the critique stop gate, and end with an execution-status closeout. Output Shape plus the Closeout Vocabulary section pin the emittable-verbatim tokens (the Lint Gate status enum and the five completion-report categories) so a validator can substring-match them, while Guardrails delegate each positive rule back to the Workflow ladders and forbid ever calling a same-agent pass a critique.

- *engage-always (매 런 코어):*

  - `design-lenses.md` — Beck/Ousterhout design moves: keep feedback slices small and single-question, and hide complexity behind a deeper seam / simpler ownership boundary.  ·  **조건:** Every run chooses a slice (step 3); the smallest-honest-slice gist is inlined, so the specific Beck/Ousterhout moves are engage-always context opened deeper only when interface/seam shape is the real risk.

### debug

**의도:** debug is for investigating a bug, error, or unexpected behavior through a disciplined root-cause workflow that forbids any fix before a falsifiable hypothesis exists. It preserves a durable debug artifact so future sessions inherit the root cause, detection gap, sibling scan, and prevention rather than re-solving the same incident.

**본문 지원:** Bootstrap resolves the adapter and runs plan_debug_run.py plus scaffold_debug_artifact.py so the run opens from a planner-named artifact status, prior incidents, required/on-demand reads, seam-risk posture, and a scaffold JSON that carries the safe write target, required heading/section order, a line budget, and the validator command to run before stopping. The Workflow is a six-step RCA spine (define the problem, define correct behavior, build the smallest honest reproduction, enumerate diverse causes, test a falsifiable hypothesis, resolve and preserve the learning) where each substrate reference is routed exactly once at the step that needs it, and closeout demands detection-gap, sibling-search, seam-risk, interrupt-decision resolution, and the required critique. Output Shape fixes the durable latest.md section order from Problem through Prevention (validated as strict current schema, with historical dated records treated as legacy memory), and Guardrails enforce disciplined-RCA hygiene — exact error preserved, multiple candidate causes, minimal repro, web-search-first, artifact kept past the fix — plus structured carry-forward of external-seam and host-disproves-local risk.

### quality

**의도:** Quality is for understanding and improving a repo's overall quality bar rather than fixing one narrow bug: detect the existing gates, run the available ones as evidence packets, read that evidence through concept / behavior / security / operability lenses, inspect skill drift and runtime risk, and then propose (or implement) concrete next quality moves — delete, merge, split ownership, extract a helper, narrow an interface, or add a floor — instead of only cataloging what is missing. Gates are evidence, never the judgment.

**본문 지원:** Bootstrap resolves `$SKILL_DIR` and runs a planner chain (`resolve_adapter` -> `bootstrap_adapter` -> `resolve_quality_artifact` -> `plan_quality_run.py --json`, optionally `--target-skill`) that emits `required_reads`, cost/trust-tagged `gate_packets`, an inline `brief` carrying demoted-primer discipline, and (for skill runs) a `structural_review_packet`. The Workflow restates scope, reads every required primer before broad gates, runs report-first gate packets by their `trust_model`/`cost_tier`/`parallel_group`, answers the structural packet, opens `on_demand_reads` only when a concrete trigger fires, then classifies findings by enforcement tier and posture. Output Shape is the scaffolded-then-validated quality artifact (`scaffold_quality_artifact.py` -> fill `template` -> single-pass `validate_quality_artifact.py`) with required Healthy/Weak/Missing/Deferred sections plus Recommended Next Quality Moves. Guardrails/Invariants keep passing gates as evidence-not-success, implement low-risk repo-local deterministic moves the same turn, forbid final summaries that hide Weak/Missing/Advisory/Delegated-Review findings, route any cautilus call through the planner-consult + wrapper, refuse moving local proof to CI without a full rerun channel, and run a bounded fresh-eye review before broad recommendations.

### handoff

**의도:** handoff prepares the next session so a following operator can continue without re-deriving session state: it produces a short, current, operationally useful baton pass that names the exact next pickup path. It is a continuation pointer, not a diary, and it treats a mention-only pickup as an instruction to actually run the workflow named in the handoff's Workflow Trigger.

**본문 지원:** Bootstrap plans the run first via the deterministic planner scripts/plan_handoff_run.py (resolve `$SKILL_DIR`, `--intent auto`), which resolves the adapter-owned artifact path (default [docs/handoff.md](../../docs/handoff.md)), summarizes the artifact, detects chunked-routing triggers, and lists intent-keyed `required_reads` plus cheap `gate_packets`; it also enforces the 30-60 line target (70-line hard stop) and flags stacked dated `## This Session` sections as a diary smell. The Workflow spine then runs conditional chunked routing over the live backlog, decides pickup vs refresh, identifies the canonical adapter-resolved artifact, and rewrites the doc around continuation (trigger, continuation capability, state that changes the next action, ordered next actions, open decisions, tight references) rather than history. Output Shape fixes the section skeleton (`Workflow Trigger`, `Continuation Capability`, `Current State`, `Next Session`, `Discuss`, `References`), and Guardrails enforce the load-bearing rules: a session-open pickup invokes the named trigger instead of only re-reading, no unverified state as fact, single-source detail to its owning artifact, and honor the size gate as a failure guard rather than a target. A bounded `critique` pass runs when the handoff changed materially before the clean baton pass.

## Tracking

### issue

**의도:** Issue files a GitHub issue from current context, or resolves GitHub issues end-to-end, through an adapter-resolved backend (`gh` by default, or a host-mediated capability like `acme github`). Creation reports the observed problem before proposing a solution; resolution treats GitHub as source of truth, classifies the fix-unit, runs a causal review for bug-class issues before designing the fix, and runs a resolution critique so the same class of issue does not recur.

**본문 지원:** The opening fixes GitHub as the source of truth for issue identity/state/comments and forbids hardcoding `gh` when the planner reports a different `selected_backend`; Bootstrap then makes every run start with `issue_tool.py plan`, reading its `required_reads`, opening `on_demand_reads` only on trigger match, trusting `gate_packets` for deterministic failures, and refusing to act when `backend_ready` is false. The Intents section supplies two ordered spines: `issue new` (plan -> problem-first body -> existing-label/milestone gating via `resolve-milestone` -> create with `--body-file` -> report only from the verified `{repo, number, url}` ledger, warning when `body_verified` is not true), and `issue resolve` (plan -> newest-open selection -> read with `comments_read: true` -> capture one-line JTBD and classify as bug/feature/deferred-work/question/decision-needed -> classification-specific review or pause -> smallest complete fix -> resolution critique + auto-close carrier -> `verify-closeout --expect-state CLOSED` -> behavior verdict from a channel distinct from CLOSED/carrier). Guardrails harden this: target repo is durable state, no design from stale/partial/comment-less reads, no relabeling to dodge the classification pause (default to `bug`/`feature` when unsure), and the irreversible-boundary rule that `carrier_verified` and `CLOSED` are necessary but not sufficient.
