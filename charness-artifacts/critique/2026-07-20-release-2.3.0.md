# Critique Review
Date: 2026-07-20

## Decision Under Review

Release v2.2.1 → v2.3.0 (minor). Scope: three commits since v2.2.1, all in the
quality skill and its adapter contract:

- `82a1faad` — adapter-owned test discovery: new adapter field
  `test_file_discovery` (command / patterns / patterns_mode); the
  standing-test-economics inventory consumes it, falling back to built-in globs
  now including `.mjs`. Fixes the `.mjs` test-surface undercount (issue #447).
- `bf6dd5b7` — new advisory quality inventory `inventory_hardcoded_discovery.py`
  + `discovery_filter_scan_lib.py`: a polyglot discovery-list tripwire.
- `8a407105` — adapter-owned lint-ignore discovery: new adapter field
  `lint_ignore_discovery.directives`; py/js/ts stays the built-in default.

One bounded high-leverage fresh-eye release reviewer ran the publish-safety /
backward-compat / bump-correctness lens; rail-1 reviewer-boundary fingerprint
verified clean around the pass.

## Failure Angles

- Backward compatibility: are both new adapter fields truly inert when omitted?
- Bump correctness: minor vs patch vs major.
- Publish safety: half-wired validators, generated-surface/registration drift.

## Counterweight Pass

- Publish verdict: **safe-to-publish**. Both `_apply_*` helpers are registered in
  `validate_quality_adapter_data`, both defaults seeded in
  `infer_quality_defaults`, docs + example in parity, plugin mirror carries the
  same new scripts and `.mjs` globs. The only Act-Before-Ship item — bumping the
  `plugin.json` manifests from 2.2.1 — is the publish helper's own job, not a code
  defect.
- Bump verdict: **minor (2.3.0)**. Two new additive, inert-when-omitted adapter
  capabilities outrank the `.mjs` default correction (which alone would be patch).
  No renamed surface, no changed invocation, no forced migration → not major.
- Backward-compat: **both fields inert when omitted, verified.** A v2.2.x
  consumer adapter with neither field behaves bit-identically for the lint scan;
  for test discovery the only delta is a repo with `.mjs` tests seeing a higher
  `test_file_count`. That inventory is advisory/inference-layer (prints
  counts/findings, is not a gate or ratchet baseline), so no consumer CI newly
  fails — the founding undercount is corrected, not a breaking surprise.
- Over-worry (no action): `shell=True` on `test_file_discovery.command` is the
  documented trusted-repo-owned boundary (same as `gate_commands`); malformed
  lint directives drop silently in the lib but the adapter validator is the
  authoritative loud gate.
- Resolved deferral: confirmed `.cjs`/`.mjs` in the lint `TEXT_SUFFIXES` set were
  pre-existing at v2.2.1 (`git show 5235228e`); this release changed only the
  discovery-boundary marker comment above it, not the suffix set — no measurement
  widening to note.

## Publish Verdict

and judged at the publication boundary, not by this pre-publish critique.
