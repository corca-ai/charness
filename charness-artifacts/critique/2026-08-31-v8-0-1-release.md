## Findings

### Resolved before ship — read-only had widened the non-claim

The first north-star reviewer returned HOLD because `--read-only` let release
quality skip ordinary `check-coverage` when the changed paths were outside its
shortcut list. That contradicted the existing contract that mutation was the only
omitted release verdict. The runner now makes release mode queue `check-coverage`
independently of read-only mode, while ordinary read-only pre-push retains the
changed-path optimization. The focused coverage-selection suite passed seven tests,
and both repaired-surface reviewers returned SHIP.

### Receipt reuse remains fail-closed

The receipt sealer requires a passing quality surface, successful effective exit,
an empty unproven set, release and full-queue semantics, and measured scope. It
binds the clean HEAD/tree and materialized export. Pre-push runs the close-keyword
guard first, validates pushed-ref ancestry, consumes a valid receipt once, and
falls back to the ordinary gate on malformed, dirty, stale, export-drift, or
uncovered-ref state. A post-quality artifact commit changes HEAD and therefore
cannot borrow the earlier proof.

### Operator narrative is bounded to the actual optimization

The notes say receipt output is helper opt-in, promise reuse only for an unchanged
subject, and distinguish installed-plugin rollback from reverting a Charness source
checkout. They retain mutation, consumer-speed, absolute-spawn, and hostile-operator
non-claims. Patch is the lightest honest bump because public capability shape does
not change.

## Failure Angles

- An exit-zero but semantically unestablished quality result could otherwise be
  sealed as pass; the sealer inspects the semantic fields rather than process status.
- A quality-side artifact commit could move R to C after the run; exact HEAD/tree
  validation makes C fall back instead of inheriting R's proof.
- An ignored materialized export could drift outside Git; its filesystem digest is
  sealed and rechecked.
- A speed repair could silently omit a sibling gate; the first reviewer found this
  exact class in ordinary coverage, and the release-specific regression now owns it.
- A release note could imply unconditional savings; the summary and residuals now
  state the exact unchanged-subject condition and fallback.

## Counterweight Pass

- Act Before Ship: none remains after restoring `check-coverage` to read-only
  release mode and repairing the operator notes.
- Bundle Anyway: keep the focused regression, delegation record, materialized export
  sync, patch rationale, and exact non-claims in the release commit.
- Over-Worry: malicious checkout rewriting and `--no-verify` are not a new receipt
  security boundary; restoring the retired broad real-host detector would recreate
  unrelated friction.
- Valid but Defer: concurrent receipt consumers are not atomically serialized,
  export mode metadata is not sealed, later R-to-C pushes intentionally fall back,
  and the canonical quality run itself is not claimed fast.
