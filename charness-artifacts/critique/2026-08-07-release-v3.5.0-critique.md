## Findings carried into the release notes

(a) Adapter `version` is reconciled, not echoed. Only `version: 1` is accepted;
    any other integer, a boolean, or a non-integer is now an error at all 18
    sites. 16 resolver sites previously accepted any integer and wrote it back as
    authoritative.
(b) `validate_adapters.py` now requires a `version` key on every adapter,
    including `.agents/cautilus-adapter.yaml` and `.agents/critique-adapter.yaml`,
    which previously returned before reaching the floor.
(c) `render_yaml_mapping` moved to `scripts/adapter_yaml_render_lib.py` with no
    re-export.
(d) Setup inspection finding-type rename (a machine-readable output contract).
(e) Upgrade note: consumers set up before this release get a new
    `review_required` finding until they regenerate their AGENTS.md
    `## Subagent Delegation` section.

## Why minor rather than major

Reachability of (a) was measured, not assumed: every adapter-producing surface in
this tree emits `version: 1` — the shared builder `scripts/adapter_init_lib.py`,
every `adapter.example.yaml`, every scaffold template, and every doc snippet. The
reviewer found zero shipped surface emitting anything else or omitting the key,
so no configuration the harness ever produced stops working. The refusals bite
only hand-authored values charness never generated. `scripts/` is not a published
Python package, so (c) does not force major either.

## Residual risk, stated

A consumer who hand-edited `version:` to a value charness never emitted is
refused where they previously passed. That is the intended repair — such a
declaration was being echoed back as authoritative by 16 of 17 readers — but it
is a real break and it leads the release notes.

## Non-claims

No consumer repo was inspected. No mirror byte-diff was performed by the reviewer
(the `validate_packaging_committed` gate covers it and passes). Remote CI is
observed separately and is not claimed here.
