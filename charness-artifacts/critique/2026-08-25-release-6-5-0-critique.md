typed producer-to-final-consumer provenance checks and the associated reviewer,

payload shapes while missing, malformed, stale, or unbound evidence now stays

## Findings And Counterweight Triage

1. The first fresh-eye blocker was real: the resume publication tail could
   create a release after claims review without rechecking generated surfaces.
   `ensure_release_surface(..., stage="post-claims-review, pre-push")` now runs
   before artifact commit, tag/branch push, or `create_release`, and its result
   is carried as `payload["version_drift_check"]` into the final artifact.
2. The second round found existing success fixtures with no generated surface;
   the fixture now runs its sync producer before creating the resumable commit.
   It also found wrapper prose claiming the old known gap; source and plugin
   comments now describe the actual owning boundary.
3. The round-2 repairs were accepted-unreviewed under the cap, but they are
   backed by 83 release-focused tests, including positive payload binding,
   missing-surface refusal before publication, idempotent branch/tag repair,
   and generated-surface integration fixtures.
4. Broad `origin/main` changed-line evidence remains a valid-but-defer
   concern because its cumulative historical range contains pre-existing
   uncovered lines and unmapped mutation-pool files. The release claim uses
   only the committed current-slice proof below.
5. Real-host proof is over-worry for this target: the configured trigger
   evaluation covered 31 changed paths and returned evaluated/no-match. It is
   recorded as no host obligation, not as live-host success.

## Semantic Reviewer Question

- Invariant: every publication leg binds one target version to every required
  generated surface and refuses drift after the claims boundary.
- Owning boundary: `publish_release_resume_publish.py` owns the final resume
  decision; `current_release.py` and `publish_release_preflight.py` own the
  surface predicate; `publish_release_artifact.py` owns the durable claim.
- Recorded instance: a prepared claims stop whose plugin or marketplace file
  is deleted or corrupted before resume.
- Axis-varying counterexample: keep the prepared commit, claims verdict, tag,
  and publication state unchanged while changing only one required generated
  surface. A proxy based only on the prepared record would still publish; the
  repaired boundary re-reads the surface and refuses.

## Boundary Ownership

- Producer: release helper, version-surface checker, sync/export producer,
  focused tests, fresh-checkout probes, and post-publish adapter commands each
  produce their own evidence.
- Consumer: the release record, claims-review gate, tag/public release, and
  operator update path consume those typed results.
- Owning surface: the resume publication tail owns the irreversible
