# Release 2.11.3
Date: 2026-07-27

## Decision Under Review

Publishing `2.11.3` as a **patch** over `2.11.2`. The release carries the
issue-close carrier fixes (B1/B2/B3 from the evidence-surface bug hunt) plus the
four earlier local commits. All three changes make closeout gates STRICTER, so
the bump level is a genuine judgment call, not a default.

## Failure Angles

- **The bump understates a breaking change.** A downstream repo on `2.11.2` with
  green CI can go red on `2.11.3` with no change of its own, and the remedy is a
  human editing prose in a commit body or a goal artifact. `version-policy.md`
  lists "forced migration steps for existing users" under **major**.
- **The release surface claims a closure the code disclaims.** B2 is
  `FIXED (narrowed)` and explicitly cannot refuse a fluent excuse. A headline
  reading "a skipped check is not a passed check" reads as closure.
- **The fix's own author-facing surfaces still lie about it.** The release exists
  to make proof surfaces truthful; a shape renderer that states the new floor at
  the wrong value is the same defect one layer out.
- **The publish carrier's own checks are in the open backlog.** D1/D4/D5/D6/D8
  are reproduced-and-open on the exact gate that will publish this.

## Counterweight Pass

- Real blockers, both fixed before publish: `describe_goal_closeout_shape.py`
  rendered the detail floor at 40 when the gate enforces 20 (a stale line left
  behind when the floor was lowered — it would have taught authors to pad to
  twice the required length, the exact fabrication the lowering avoided), and
  `describe_closeout_draft_shape.py` omitted the floor entirely. Both now read
  the live constant instead of restating it, so they cannot drift again.
- Real blocker, fixed: the commit-msg hook is the only carrier that can block
  `git commit` and it discarded the specific, actionable failure detail the
  library had already built. Fixed on that carrier and on the achieve sibling.
- Not a blocker, and stated in the notes instead: the publish carrier's
  distinct-channel and installed-readback claims are known-unproven at this
  version (D4/D6/D8). They were equally unearned when `2.11.2` shipped; this
  release does not make them worse, and D1/D5 are next in the fix order.
- Over-worry: that `patch` hides a breaking change. The tightenings move behavior
  *toward* the already-documented contract in all three cases — the placeholder
  set already declared `n/a`, the enum-plus-length skip contract is unchanged,
  and nobody was ever told that the word `Answer:` earns a floor exemption. A
  false PASS on an irreversible boundary is a defect; refusing the input that
  produced it is the fix, not a contract change. `minor` would be the worst
  choice: it signals neither breakage nor new capability.
