# Release Critique — 3.0.1 → 3.1.0

Date: 2026-08-07

## Decision Under Review

Publish a `minor` bump to **3.1.0** over 142 commits (`f22d7539..HEAD`, since
2026-07-31): 23 new scripts, a new `--fields-file` operator surface on
`upsert_goal.py`, a new blocking standalone-import gate, and ten public `SKILL.md`
files touched. No public skill deleted or renamed; no package id change.

The operator chose `minor` after being shown the evidence, including two changes that
refuse calls which previously succeeded. The operator also explicitly DECLINED a full
142-commit breaking-change scan, so the critique was scoped accordingly and the
non-claim is recorded below rather than implied.

## Failure Angles

- `minor` is dishonest because a refusal breaks a correct existing caller.
- A breaking change elsewhere in the 142-commit span that the rationale never saw.
- The new BLOCKING gate strands a consuming repo on a reason it cannot act on.
- Shipping a knowingly-broken module (#497) in the delivered package.
- Version drift or an unsynced mirror at publish time.

## Counterweight Pass

Three of the five angles came back clean and were CLEARED with evidence rather than
waved off — the consuming-repo strand risk in particular, which was the angle I
expected to block. One produced a real blocker. One produced a release-notes
obligation rather than a block.

The blocker is the same class this run has now hit seven times, which is why it was
worth a full round on a version bump: a guard placed at the boundary that was easy to
test rather than the one that breaks the invariant.

## Evidence Requests Answered

The reviewer flagged three items it could not resolve without a baseline, each of
which could have flipped the bump. All three were run and all three resolve in the
release's favour:

- **`append_slice_log.py`'s unknown-key/duplicate-key refusals** — not a break: that
  helper's `--fields-file` is itself NEW in this span (`c09c7f4a`), so there is no
  previously-succeeding caller to break.
- **`achieve_adapter_policy.py`'s direct-commit template rule** — `git log` shows the
  file unchanged in `f22d7539..HEAD`, so the rule is not new and cannot hard-break a
  consuming repo's older adapter in this release.
- **#497's provenance** — `git log -S` puts it at `3cb6c576` (2026-06-25),
  confirmed an ancestor of the 3.0.1 tag commit. Pre-existing.

## Verdict

**SHIP-WITH-FIXES**, and after F1 and F2 landed, **`minor` is honest**.

The reviewer's own condition: narrow `_resolve_slug` and `minor` stands; leave it and
the policy's `major` bucket applies. It was narrowed, and the false-positive control
now pins the distinction (`PROJ_184`, `My Goal`, and a status flip all pass; `""`,
`"!!!"` and `"   "` refuse).
