## Decision Under Review

Whether the current v8.0.0 tree is safe to tag, publish, and install as the
next consumer-facing Charness plugin release.

## Findings

### F1 — HOLD: generic update can mutate Goal Run parent identity

`skills/public/issue/scripts/issue_tracker.py:108-114` compares only
`GOAL_RUN_IMMUTABLE_FIELDS`, which omits `parent_identity`. The generic
`issue_tool.py update` route calls `update_issue_body` without the stronger
bound validator (`skills/public/issue/scripts/issue_tracker_cli.py:194-202`).
The direct negative control accepted a desired body whose parent number changed
from 724 to 725. Therefore the advertised invariant that immutable Goal Run
metadata cannot be altered is false outside the bound update path. A consumer
or operator can amend human Markdown through the intended bound operation, but
the generic Charness capability still offers an identity-changing bypass.

Required action: make the generic guard reject every immutable Goal Run identity
field, including `parent_identity` (and its removal), and add a regression that
proves no provider mutation occurs. Re-run the focused issue boundary tests.

### F2 — HOLD: generated plugin export does not match canonical source

`python3 scripts/validate_packaging.py --repo-root . --validate-export` refused
with a large missing export set, including `plugins/charness/scripts/changed_line_run_trust.py`,
`plugins/charness/scripts/reviewed_input_identity.py`, the new release helpers,
and root plugin manifests. The source tree has uncommitted changes while
`plugins/charness/**` is still the prior generated mirror. Tagging this state
would publish a plugin whose installed behavior does not contain the reviewed
source fixes.

Required action: run the repository-owned manifest/export sync once after source
integration, validate the export and import smoke on the resulting tree, then
rebuild the release evidence against that exact tree before tagging.

## Failure Angles

- Goal Run safety: bound parent amendments correctly permit human Markdown
  changes while preserving one metadata block and binding/readback; the generic
  ingress hole above defeats the same safety property.
- Reviewed-input proof: the focused selection passed 141 tests, including
  commit/range, deletion preimages, symlink/current-pointer, submodule, and
  refusal controls. This is meaningful semantic coverage, not a static-only
  replacement for process tests.
- Release resume: the focused release boundary selection passed and retained
  direct-child evidence, distinct observer state, and ambiguous-push recovery.
- Mutation recovery: the parent-liveness guard is narrowly scoped to the child
  wrapper and has a real process-boundary regression; mutation score remains
  unmeasured.
- Process reduction: the final external census records 10,735 launches for
  8,612 passing tests: 7,600 Git and 1,910 Python-family processes, versus
  18,010 / 13,300 / 2,997. This is structural test-suite evidence, not a
  consumer speed claim.

## Counterweight Pass

- Act Before Ship: F1 and F2. Both are directly reproduced or refused by the
  current tree and affect the claimed release boundary or installed behavior.
- Bundle Anyway: after F1/F2, refresh the release artifact's generated claim
  block and run the cheap packaging/import validators in the same release pass.
- Over-Worry: lack of elapsed-time proof for the instrumented census does not
  block publication because the release explicitly makes no consumer speed
  claim and the launch-count claim is bounded as structural evidence.
- Valid but Defer: hosted mutation execution remains open/unmeasured (issue
  #763); external worker installed-versus-source identity remains open (issue
  #715). Preserve both as non-claims rather than weakening the release gate.
