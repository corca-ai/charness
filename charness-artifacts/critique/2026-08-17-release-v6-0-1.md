## Boundary Ownership

- Producer: `plan_retro_run.py`, which emits a validator path derived from the retro
  adapter's `output_dir`
- Consumer: `validate_retro_artifact.py`, which keys its candidate filter and owned
  prefix on the hardcoded literal `charness-artifacts/retro/`
- Owning surface: repo-python and skill-packages
- Verdict: escalated-to-issue-spec

Neither side is wrong alone — the producer honours the adapter, and the consumer
predates any adapter awareness. The defect is that this release taught the producer to
hand the consumer a path the consumer cannot own, so a consumer with a custom
`output_dir` got a schema gate that exited 0 having opened nothing.

Ownership sits with the CONSUMER: the debug sibling resolved the identical split by
giving its validator an adapter-derived prefix, and retro owes the same move. That is
deferred out of this release rather than done badly in it, because the retro validator
loads no adapter at all and adding one changes verdict logic on a proof surface. The
producer-side scoping is reversed in the meantime, so the split is not live. Escalated
as next-session work rather than closed here.

## Findings

The angles produced fourteen concerns. Two survived as ship-blocking, and one
central alarm was refuted by measurement.

**Refuted before triage.** Two angles independently reported that four exported
debug docs assert a filename-keyed rule the validator no longer implements, and
concluded a consumer's dated record would newly fail on upgrade. The docs claim
is true and was fixed. The consequence is not: measured on a fixture with a
legacy-shaped record behind a symlinked pointer, the v6.0.0 validator and the
current one both exit 1 — identical. The pointer's name always applied the
strict rules to the target's BYTES, so that content was already strictly
validated. No consumer's corpus run changes verdict.

**Blocker 1 — retro shipped scoping without the refusal that makes it safe.**
`plan_retro_run.py` was taught this session to emit
`--paths <adapter-derived path>`, but `validate_retro_artifact.py` keys both its
candidate filter and its owned prefix on the literal `charness-artifacts/retro/`.
For a consumer whose adapter declares a different `output_dir` the two disagree.
Reproduced: the command prints `Validated 0 retro artifact(s).` and exits 0 — a
schema gate reporting green having opened nothing, which is verbatim the class
the debug half of this work exists to close.

**Blocker 2 — the bump level, and the missing rationale.** The parent proposed
`minor` on the ground that a new detector makes a consumer's gate catch more.
Gawande refuted it: that is the literal definition of the policy's Patch bullet
"validation or packaging repairs", none of the four registered release claim
surfaces moved in this delta, and the detector's own author calls it a repair.
The counterweight agreed. `version-policy.md` separately requires the rationale
be stated whenever the level is debatable, and nothing in the tree stated it.

**Crash reachable from a verdict surface.** `unresolvable_named_paths` shells
out to git with `check=False`, which suppresses a failing git but not an absent
one. Reproduced: `FileNotFoundError` escapes. Dead code until a validator
declared an `owned_prefix`; the first one that did made an uncaught traceback
reachable.

## Counterweight Triage

### Act Before Ship

- **Retro's hardcoded prefix.** Fixed by REVERSING the retro scoping added this
  session, not by giving retro the adapter resolver. The debug sibling could be
  scoped safely because its validator already loads an adapter; retro's loads
  none, so introducing one is a verdict-surface change owing its own proof and
  review rounds — not a release-eve edit. The unscoped corpus command always
  judges something, which is the honest fallback. The retro test now asserts the
  ABSENCE of `--paths`, so re-adding it without the resolver fails there.
- **Bump level.** `patch` (6.0.1). The rationale is recorded in this artifact and
  in the bound claims-review artifact under `charness-artifacts/release-review/`.
  It is NOT in `charness-artifacts/release/latest.md`: that record's template
  emits no bump-rationale field (`publish_release_artifact.py` neither takes nor
  writes one), so re-running the helper cannot add it. The claims round caught
  this sentence claiming otherwise and the correction is its doing.

### Bundle Anyway

- Four exported debug docs corrected to state the role-keyed rule.
- Three copies of a false reassurance ("the markdown gate still runs it at
  commit time") replaced; `check-markdown.sh` exits 1 when no engine resolves,
  so the sentence sent the operator past a gate that would refuse them.
- `authoring-preflight.md`'s un-caveated "cannot drift" claim now names
  `unforecast_classes` and what an empty list does and does not mean.
- The named-path refusal no longer reads as a pure typo accusation; the most
  likely way to reach it is running a scoped gate before writing the artifact.
- `run_when` added to the debug shape packet for the same reason.
- `npm ci` documented as a prerequisite in `docs/development.md`.
- The OSError guard on the git call, kept because a verdict surface must not
  traceback — not because the git-less container is a real consumer.

### Over-Worry

- **The git-less slim container.** No named user, and the tree refutes it:
  `_git_paths` is still unguarded, so the default no-`--paths` run of every one
  of these validators already dies on such an image. The container was never
  supported and this release does not change that. Guard the call site; do not
  open a make-the-toolchain-git-optional workstream.
- **The byte-copy pointer still double-counting in the seam-risk index.** The
  code concedes the cost is an inflated tally on a reporting surface, not a
  verdict. Real, cheap to defer.
- **The derived notes block being byte-identical to v6.0.0's.** That is the
  generator working: no registered claim surface moved. It is corroborating
  evidence FOR the patch bump, not a defect.
- **Softening `CHARNESS_REQUIRE_MARKDOWNLINT` back to opt-in.** Rejected. That
  restores exactly the vacuous-green default the strictness was written to kill.
  The documentation gap is real; the default is right.

### Valid but Defer

- `charness-artifacts/quality/latest.md` is stale — it asserts as open two issues
  this delta closes, and claims a lane is red that now passes 102 tests. A dated
  measurement snapshot is supposed to be a snapshot; hand-editing one to agree
  with today is worse than leaving it. Regenerate at the next quality run.

## Deliberately Not Doing

- **Not giving `validate_retro_artifact.py` an adapter-derived prefix in this
  release.** It is the correct end state and it is deferred on purpose: that
  validator loads no adapter today, and adding one changes verdict logic on a
  proof surface, which owes two bounded review rounds this release cannot buy.
  The scoping that would have depended on it is reversed instead, so nothing
  ships half-safe.
- **Not making the toolchain git-optional.** See Over-Worry.
- **Not hand-editing the stale quality record.** See Valid but Defer.
