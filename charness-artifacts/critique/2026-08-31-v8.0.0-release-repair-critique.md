## Findings

### F1 — HOLD until the exact candidate is committed and the changed-line gate is rerun

The complete release quality run reached 82 passed checks and one intentional
refusal. `release-changed-line-coverage` reported that 93 changed mutation-pool
files were absent from `base..HEAD` because the candidate is uncommitted, so it
could not establish a verdict. This is the expected pre-commit safety behavior,
not evidence that mutation failed, but a tag must not be cut while this proof is
unestablished. Commit the exact candidate, rerun the release gate against that
commit, and treat any new refusal as a release blocker.

### F2 — The two historical blockers are structurally closed

The Goal Run generic update now includes `parent_identity` in immutable metadata
and the parent amendment path requires a repository-contained canonical receipt
binding parent, Goal Binding, current/desired body hashes, and explicit approval
evidence. There is no loose boolean authorization facade in the exercised path.
The focused issue tests passed, including no-provider-mutation negative controls.

The packaging validator reads the filesystem materialized export rather than
Git-enumerating an intentionally ignored tree. The contract is consistently
renamed to `materialized_plugin_root` / `materialized_source_path`; packaging,
adapter, and install-surface validation passed (1 manifest, 15 resolvers, 12
adapter YAML files).

### F3 — Resume and execution seams are owned at the right layer

The custom release `record_path` is used to derive candidate artifacts through
the complete prepared-to-resume-to-carrier path; focused release resume and
publish tests passed. Task-run Git identity is read as one repository snapshot,
while task-run scope/evidence/support and reviewed-input identity receive the
snapshot explicitly. In-process script behavior is covered alongside CLI
delivery behavior rather than pretending they are interchangeable. The direct
task-run/parity selection passed 105 tests; the issue/release/packaging
selection passed 131 tests.

### F4 — Unsafe global caches were correctly rejected

The mutation Git-call investigation records 252 calls crossing separate Python
processes and rejects a module-global filesystem-token cache: its lifetime was
too narrow to deliver the predicted reduction and its token omitted Git
semantic inputs. Operation-scoped snapshots and immutable object-ID batching
remain; the 252-call residual is explicitly not claimed fixed.

### F5 — Structural process reduction is evidence, not a speed claim

The final external census records 10,597 launches for 8,623 passing tests:
7,524 Git and 1,834 Python-family launches, down from 18,010 / 13,300 / 2,997.
That is 41.2% fewer total, 43.4% fewer Git, and 38.8% fewer Python-family
launches, with density falling from 2.10 to 1.23 per test. The census was
instrumented and therefore does not establish elapsed-time or consumer-repo
speed. The release notes correctly make that non-claim; this critique does not
call 10,597 “fast.”

## Failure Angles

- A release can pass ordinary tests while publishing a stale materialized
  export; the direct filesystem validator and adapter checks address this.
- A parent amendment can preserve Markdown while changing the Goal identity if
  the generic ingress and bound ingress do not share immutable-field ownership;
  the focused negative controls exercise both seams.
- A resume classifier can lose a consumer-declared root record when it assumes
  one fixed artifact directory; record-path-derived candidate tests address
  this.
- In-process tests can accidentally replace process-boundary proof, and a
  global mutable-state cache can produce a false speed estimate; the task-run
  parity tests and cache rejection record keep those claims separate.
- The release gate itself can report a false green against a dirty candidate;
  this tree instead produced the honest `unestablished` refusal, which is why
  commit-before-tag remains mandatory.

## Counterweight Pass

- Act Before Ship: commit the exact candidate and rerun
  `./scripts/run-quality.sh --release --read-only`; do not tag on the current
  unestablished changed-line result. After that, run the publish helper's own
  fresh-checkout and public readback boundaries.
- Bundle Anyway: preserve the exact 10,597 census and the 280-second
  release-quality runtime advisory in release evidence, and ensure the final
  release record names mutation as unestablished/non-claimed rather than
  converting it to a score.
- Over-Worry: requiring a consumer speedup number, a mutation score, or a
  complete Rust migration would expand this release beyond its stated JTBD;
  the notes already bound those as non-claims and retain the explicit Python
  owners where their consumer-artifact boundary is not proven.
- Valid but Defer: the 252-call mutation residual, runtime-budget advisories,
  and installed-worker source-identity gap (#715) deserve follow-up work, but
  they do not justify restoring the rejected global cache or blocking a release
  once the committed changed-line proof is established. Hosted mutation remains
  unestablished under #763 and is not closed by this release.
