## Release Scope

v8.14.6 is a patch release: it restores the documented task-run receipt
contract ("Receipts record observed phases plus blockers") for muse lanes,
where it was false, and adds no command, flag, skill, or install surface.
Receipt additions are strictly additive (`execution.stream_diagnostics`,
`muse.events.log`); one existing display field (`failure.message` on
muse executor-error) now carries the named cause instead of a bare exit
code, with no exact-match consumer in repo. The self-review move is a
verbatim relocation with re-pointed execution references. Closes #886.

## Surface-Lock Inventory

Generated artifacts: the `plugins/` mirror and marketplace manifests are
regenerated by sync; the sync reports no drift for this slice
(1213 unchanged).

Consumer-visible behavior: muse lane receipts now carry observed phases,
first-scoped-diff evidence, terminal-report delivery, and
`stream_diagnostics` (retry count, last stream error kind, terminal
reason, explicit `unavailable-upstream` gap marker). Codex lanes are
behavior-identical (same retention shape, extracted dispatcher).
`failure.message` on a named muse failure carries the cause.

Documentation surfaces: none touched; `docs/agent-task-runs.md` already
describes the restored behavior and deliberately does not recopy receipt
fields (`--help` is the typed surface).

## Operator Action Required

None for the upgrade itself. Operators running muse lanes on a muse
binary without `muse exec --json` support must upgrade that binary: the
lane now passes `--json` unconditionally (same precedent as the Codex
lane's unconditional `--json`), and an old binary fails its lane loudly
at argument parse instead of running blind.

## Upgrade Path

Standard patch upgrade from any 8.x install via `charness update`; no
migration, no config change. Rollback to 8.14.5 is safe (additive
receipt detail only; no state or contract change).

## Failure Angles

- A mixed-signal binary (status events without retry facets plus
  stderr-only retries) would receipt zero retries: the count is now the
  best observation across both signals, never their sum (§C1, repaired
  and tested).
- The issue's exact timeout shape (partial deltas, no terminal event)
  had no boundary proof: a timeout fake-muse lane now proves phases,
  partial delivery, guard snapshot, and diagnostics together (§C2,
  repaired and tested).
- Early retries would age out of a 1 MiB diagnostics tail on long lanes:
  diagnostics now scan the full events log with marker prefiltering
  (linear, no full parse) (§C3, repaired and tested past 1 MiB).
- Importing the split self-review module first would crash on the
  execution cycle: the execution import is now function-lazy like its
  siblings, with a fresh-interpreter order proof (§C7, repaired and
  tested).
- A non-terminal envelope under `run.terminal.*` would be misread as the
  report: terminal extraction now requires `kind == "run_terminal"`
  (§C6, repaired and tested).
- A pre-`--json` muse binary fails its lane at argument parse: loud,
  operator-owned, same precedent as the Codex lane's unconditional
  `--json`; no silent blind run is possible (§R1).
- `failure.message` on a named muse failure now carries the cause
  instead of the bare exit code: no exact-match consumer exists
  in repo; the message repair is the issue's condition 3 (§R2).
- Quota-transcript false positives via the new events log: same text
  the stdout scan already read, same pre-existing codex pattern (§R3).
- The release could understate its surface as patch: every addition is
  additive receipt detail restoring a documented contract; no new
  capability, command, or migration (§R4).
- Release-record precision: notes must say the cause is preserved when
  the binary provides it and the gap is named otherwise — never that
  every retry now explains itself (§R7).
