## Change

Cut `3.0.1` (patch) at `64ebf14d`, previous `v3.0.0` at `6d6a9bde`. The delta

input, plus their plugin mirrors, tests, two docs, and the run's artifacts.

## Capability at Stake

Three of the four repaired surfaces ship inside `plugins/charness/`. A consuming
repo that upgrades gets stricter SKILL.md density rules, a stricter HITL chunk
check, and a stricter cautilus bundle check — so a previously-green consumer run
can go red with no change on their side. The release's own thesis is that a gate
must not lie about its input; the risk is shipping a gate that lies about its own
verdict instead.

## Counterweight Triage

**Act Before Ship** — 1, 2, and the notes obligation. Fixed before the tag:
`_changed_blocked_message` now branches on which cause set `blocked` and prints
`EXEMPT_SECTION_REMEDIATION` (with the doc pointer) for an exempt-section block;
`check_chunk_contract.py` raises `ChunkInputError` and emits
`{"status": "error"}` with exit 2 for an unreadable path. Both pinned by new
tests. The notes carry a "stricter gates" migration section and an explicit
"why patch".

**Bundle Anyway** — 4, 5, 6, 7, 10, 11, 15. All folded in the same session: the
docstring, the `--all` help string, the false handoff sentence, the
`portable-authoring.md` caveat, the dogfood record, the rename as a migration
line, and the quality-artifact staleness as a non-claim.

**Over-Worry** — 9, 12, 13, 14 and one more. The fence re-derivation is a latent
refactor wish with no corpus instance; `"?" in text` already arms detection on
any chunk with a question mark, so `let me know` adds near-zero false-positive
surface; `(saw None)` and the absolute path are cosmetic on messages that already
name the issue and the path.

Also over-worry, and worth recording because it looked serious: the concern that
the new classification-ordering rule could fail the shipped `issue` skill's own
correct behavior. `audit_brief.py` has no caller in that flow, so it cannot.

**Valid but Defer** — 3 (grandfathering the exempt-prose audit is a policy
decision about ratchet semantics, not a patch-level repair, and fixing 1 removed
the part that made the block unactionable), 8 (prose churn, better done with the
sibling-copy reconciliation), 14's second remedy (deciding how much gate internals
to expose).

## Deliberately Not Doing

- **Not grandfathering the exempt-prose audit in this release.** It is the
  honest-looking fix, but it changes what the ratchet means, and the counterweight
  is right that a patch is the wrong place to decide that. The migration section
  names the consequence instead.
- **Not porting the bounded exemption into `skill_ergonomics_lib.py`.** The
  portability boundary stands; the divergence is now disclosed in the consumer-
  facing reference rather than only in a repo-internal doc.
- **Not bumping to minor.** The public shape — commands, flags, skill names — is
  unchanged, which is the repo's own patch criterion. The debatable part is
  stated in the notes rather than defaulted silently.
