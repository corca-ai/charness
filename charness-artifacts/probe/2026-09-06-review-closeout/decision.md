# Reduce review-to-closeout reexecution

The authorized slice is local implementation, not reopening Goal 805 or releasing a version. Success is fewer avoidable reviewer launches and corrections in the same closeout scenario while retaining meaningful error detection. No new Goal, provider write, push, release or installation is authorized.

## Causal disposition

The [baseline](./baseline.json) executed the real semantic runner with a deterministic fake backend and exact two-issue observations. It spent one worker invocation, then both public closeout consumers refused only the descriptive scope prefix. This is a local executable fixture, not semantic approval or a savings measurement.

The [authority reviewer](./cause-authority.json) blocked prefix removal. The [cost reviewer](./cause-cost.json) preferred testing it, while preserving semantic coverage. The parent ran the former's counterexample: a fully joined, exact-target `causal-review` fixture with passing observations stating `Root cause confirmed; no repair exists`. Current issue observer returned `carrier-unverified`; a memory-only prefix-removal hypothesis returned `delegated`. Therefore the deletion loses a real wrong-phase refusal and is not adopted. No production or historical review bytes were changed by that experiment.

## Working implementation contract

1. Keep every existing final-consumer purpose, membership, behavioral, classification, freshness and delivery check. No automatic cross-purpose or changed-byte approval reuse.
2. Put the intended resolution-review invocation under the existing issue CLI, so the caller supplies repository, issue numbers, reviewed paths and focus instead of separately assembling purpose and opaque target strings. One `review-resolution` invocation derives `issue-resolution` scope and qualified targets, then uses the existing generic semantic runner unchanged. The command means resolution review, never causal diagnosis. Add resolution/recurrence purpose to the actual reviewer prompt; do not merely alter a returned report. Keep generic review available for other purposes.
3. Keep this command small: explicit repository, repeatable positive distinct issue numbers and reviewed paths, required lens, optional attempt identity/Goal lineage/dry-run. No packet-import, provider fetch, new state registry, model scheduler, install lifecycle or separate prep/execute artifact. Existing runner owns packet creation, adapter selection, dry-run, receipts, progress and output. Input validation and `--help` must not launch workers or touch providers. Existing plugin export owns distribution; no separate installation.
4. Reuse the existing durability decision in that same issue-owned launch path, over exactly the supplied reviewed paths before asking the generic runner to freeze them. Selected-doc checking belongs to the existing evidence-durability owner, not a reimplementation in the issue wrapper. Preserve artifact family roots, late-date/Goal-binding grandfathering, reproduction markers, generated exports and batched ignore checks. Never invoke its whole-repository main as a per-review tax.
5. Do not add durability gating to the changed-surface section producer: its changed set can differ from explicit reviewed inputs, causing unrelated dirty evidence to block a narrow review. The issue launch path already has the exact declared paths. This prevents the Goal 805 failure through the new supported issue-resolution path; generic reviews remain unchanged. Preflight is readiness, not approval or immunity to later file changes.

## Acceptance and comparison

- Same deterministic backend, targets and semantic evidence: baseline generic wrong-purpose invocation is refused after its first worker; the corrected baseline needs a second worker. The issue-owned invocation must produce a directly accepted carrier with one worker. Preserve actual old and new final-consumer output and total call counts.
- Run both public closeout commands, and retain commit/pre-push consumer coverage from the existing composed bundle test. No actual provider mutation is necessary.
- Wrong-phase diagnostic result remains refused. Missing/nonpassing target observations, wrong/duplicate targets, scope-join mutation, stale reviewed input and damaged delivery remain refused.
- A changed enforced Markdown artifact citing ignored runtime evidence must make packet preparation fail with zero fake worker calls; repair it to durable proof and one review can run. Valid reproduction-source, generated-export and grandfathered cases must keep their existing disposition.
- Measure local scenario elapsed time as descriptive fixture evidence, with reviewer calls as the stable verdict. Do not assert a timing threshold or infer live model latency, token charges, user wait or long-delegation gains from fake execution. Human corrections in the harness are simulated transitions, not observed real user interventions.

## Deliberately not doing

No new universal gate, wrapper binary, purpose schema, content-equivalence oracle, receipt editing, historical review relabeling, CI/release rerun or benefit-generalizing model pilot. Exact-byte changes still invalidate bound approvals; preventing cheap citation repair after review is preferable to silently declaring it semantically equal. A no-benefit result rejects the candidate rather than turning completed work into a success claim.
