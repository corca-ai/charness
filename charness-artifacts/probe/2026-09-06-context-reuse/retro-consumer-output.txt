## Waste

- We generalized from one nominal input before defining the formatter's input
  boundaries, so an operator check had to expose the omitted whitespace case
  (recurrence-class: boundary-case-before-happy-path).
- The correction was cheap and local, but the missing test delayed confidence
  until after the change was treated as complete.

## Critical Decisions

- The initial test chose `"Alice"` as sufficient evidence and skipped an input
  partition or boundary matrix; this constrained confidence in the behavior.
- After the operator check, we added `" Alice "` as a focused case. That fixes
  the observed omission but does not, by itself, define tabs, newlines, empty
  input, or all-whitespace behavior.

## North Star Alignment

- Held: the change stayed reversible and local, and the later focused test gives
  concrete evidence for the reported whitespace behavior.
- Mis-applied: the standard's requirement to establish boundary behavior before
  generalizing from one passing test was inverted by starting with only the
  canonical example.
- Failure signature: a missing edge case was found by a later operator check;
  the README reports that this pattern has recurred twice.

## Expert Counterfactuals

- Engelbart's system-improving lens changes the next action at the method/tool
  boundary: make the input-partition matrix part of the formatter test method,
  not an operator's late discovery. Before implementation or acceptance,
  enumerate canonical, surrounding-space, tab/newline, empty, and
  all-whitespace inputs; decide the contract for each, then require focused
  tests for the changed boundaries.
