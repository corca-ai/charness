# Final-Bundle Preflight Contract

Status: draft
Date: 2026-08-06

## Decision Under Review

Add a source-checkout-only final-bundle preflight that reads the frozen Slice 1
manifest, derives the current committed/worktree slice range, inventories
artifacts and matched surfaces, and emits a reviewable command plan without
executing commands or writing repository state.

The preflight is a planner and refusal surface. It does not become the owner of
GitHub issue state, GitHub Actions state, packaging policy, critique shape, or
behavior semantics. Those owners remain the existing manifest validator,
surface manifest, critique validator, and the explicitly named behavior
channel.

## Contract

The command is:

```text
python3 scripts/final_bundle_preflight.py
  --repo-root <repo>
  --manifest <slice-manifest.json>
  --critique-path <review.md>              # repeatable durable review artifact
  --behavior-channel <id>=<command>        # repeatable
  [--paths <repo-relative-path> ...]
  [--json]
```

It always performs a dry run. It never invokes a command supplied by the
manifest, surface inventory, critique packet, or behavior channel; it only
prints the commands that a later locked closeout may execute.

When `--paths` is omitted, changed paths are the union of the committed
`premise.local_head_sha..HEAD` range, staged and unstaged tracked changes,
non-ignored untracked files, and deletions. The path list is sorted and
deduplicated. The explicit-path form is diagnostic-only: it reports
`status: diagnostic`, never emits the locked closeout command, and cannot be
used to claim a complete final bundle.

The result is `ready` only when all of these hold:

1. The Slice 1 manifest is structurally valid, and its target, carrier, CI
   readback, and remote readback identities agree. A manifest failure is a
   refusal, including carrier/CI SHA mismatch.
2. Every changed path is covered by `.agents/surfaces.json`, and the selected
   surface inventory preserves the selector's exact commands. Zero sync
   commands is valid for a surface that declares none; the aggregate must have
   at least one verify command. Unmatched paths are a real bundle gap, not an
   implicit opt-out.
3. The existing packaging owner renders a disposable plugin tree from the
   current source tree, and the checked-in plugin tree matches it for the
   selected export. A mismatch is a `needs_sync` refusal with the canonical
   sync command as remediation; transformed assets are never compared by a new
   path-mapping registry. The inventory records the owner and comparison
   result, while the planned packaging verifier remains authoritative after
   sync.
4. Every critique input is an existing durable Markdown review artifact whose
   `Reviewed Input Identity` binds to an existing JSON prepare packet. The
   packet path, packet SHA-256, identity SHA-256, current reviewed inputs, and
   deterministic packet Markdown rendering must agree. This catches an
   unbound, stale, or half-persisted packet before the broad gate. Packet
   content correctness stays with `validate_critique_artifacts.py` in the
   generated command set.
5. At least one behavior channel is named. Each channel has a stable identifier
   and a non-empty copyable command. The preflight records the channel as a
   planned behavior proof; it does not claim that the command ran or that its
   semantics are correct.

The generated command set is ordered:

1. manifest validation;
2. surface sync commands;
3. critique validation;
4. named behavior commands;
5. surface verify commands;
6. verification-locked slice closeout over the same manifest-local base.

Commands are descriptive strings only. No push, release, issue write, provider
call, Cautilus evaluation, or runtime-budget decision is generated by this
slice.

## Output Shape

JSON output has `kind: charness.final-bundle-preflight`, `schema_version: 1`,
`status`, `captured_baseline_identity`, `candidate_snapshot`, `changed_paths`, `artifact_inventory`,
`surface_inventory`, `mirror_inventory`, `critique_inventory`,
`behavior_channels`, `planned_commands`, `blockers`, and `non_claims`.

Artifact inventory is path-based and classifies goal/spec/critique/quality/
fixture/other evidence paths. Surface inventory preserves the selector's
surface IDs, matched source/derived paths, sync commands, and verify commands.
Mirror inventory is explicit about `owner`, `status`, and any reason. Critique
and behavior inventories preserve the input identity without turning it into a
semantic verdict. Each planned command has `phase`, `command`, and
`reason_surface_ids` where a surface owns it.

Each blocker is an object with a stable `code`, `subject`, `message`, and
`remediation`; independent blockers are aggregated in deterministic order.
Exit codes are `0` only for a complete non-diagnostic `ready` plan and `1` for
any refusal, diagnostic path selection, or invalid input. The JSON and text
renderings end with the same status and blocker codes.

## Deliberately Not Doing

- Do not mutate the frozen Slice 1 manifest to add a second command scheduler or
  execution state.
- Do not infer a behavior proof from a passing surface validator, a critique
  packet's existence, a push exit code, or a remote CI result.
- Do not execute shell text, parse shell syntax, call GitHub, write a ledger,
  refresh a provider readback, or publish anything.
- Do not replace packaging or surface ownership with a second generated-file
  registry. The existing packaging renderer is the owner; transformed output
  identity belongs to its canonical sync/verify commands.

## Acceptance Checks

- A valid fixture emits `ready` with the manifest identity, artifact/surface /
  mirror inventories, explicit behavior channel, and ordered command set.
- An unmatched path refuses with a named bundle-gap blocker.
- A missing or divergent generated plugin export refuses as `needs_sync` with
  the canonical sync remediation.
- A malformed or unbound durable critique artifact refuses before command
  generation.
- Missing behavior channels refuses rather than silently claiming local proof.
- Carrier/CI SHA mismatch is refused by the manifest-owned identity validator.
- The CLI is dry-run: hostile command text is preserved as data and never
  executed; source and checked-in plugin copies remain byte-identical.

## Non-Claims

The preflight proves only that the selected final-bundle inputs are structurally
present and that a command plan was generated. It does not prove that the
commands pass, that the behavior channel reaches the intended semantic path,
that the provider or installed consumer works, or that any remote state is
fresh beyond the captured manifest record.
